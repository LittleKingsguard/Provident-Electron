# L0 research — fact-finding before a design commitment

Procedure for the delegated `role_l0_research` seat (canonical D-23). Ceiling: 40 lines.

## 1. When it runs

A note, a feature request, a paradigm or a package whose answer depends on something outside this
project (canonical D-23); `D-304` is the intake window that first applies it here. Ordinary work
inside an accepted unit is the loop's (brief §4).

## 2. What it may conclude

What is true, cited through the register's two sources (D-47): a URL, a path, or a command whose
output is quoted. It never commits a design, a dependency or a rule (canonical D-23); a question
that needs user intent climbs to the user as the envelope's `question` (envelope.md §3).

## 3. The over-fit firewall

A named package or technology is an **option** recorded with the acceptance predicate it
satisfies, so a substitute is judged against the predicate and never the name (canonical D-23).
Recording the name alone is how one recommendation becomes a locked dependency list.

## 4. Output

`strata/records/<topic>-research.md`, at most 40 lines and replaced per pass, never appended
(brief §1). One row per finding: claim, source, confidence, and what it would change if false.

## 5. Return

The envelope of `strata/envelope.md`: `PASS` with the record's path as its citation, or `FAIL`
with the question it could not answer — which L0 then takes to the user (envelope.md §2, D-1).
