# app-layout — unit record

**The unit that surfaced these findings.** `provident-ssr` defects are **upstream-owned and never patched here** (`D-5`, `D-52`); each finding carries symptom, reproduction, suspected root cause and proposed fix shape, and stays live until the package discharges it — a discharged finding keeps its row and says what discharged it, as `store-tabs-record-unit.md`'s `ST-F1` does (`D-5`).

## AL-F1 — A NAME-CONSUMED PROVIDER IS DROPPED FROM RENDER WITH ITS WHOLE SUBTREE, so positional inheritance cannot be used for a provider that is also an element · **PARTLY DISCHARGED at `provident-ssr@0.5.2`; the seam's name-keyed def root stays open and upstream-owned** (`D-5`)

**What is correct, and what a fix keeps.** `fitReference` resolves a consumer's binding **by tree position** — own → descendants → nearest ancestor, `dist/core/resolve.js:180-227` — and `applyDerived` **appends** the resolved classes (`dist/core/derived.js:332`), so a consumer inherits from whichever ancestor it stands under, which is the one property that cannot go stale (`D-264`).

**Symptom.** A zone node providing styling for its children (`component: { reference: 'zone-format', value: ['zone-sidebar-format'] }`) **disappears from the compiled tree when its panes consume it**, and its panes are **orphaned**: not re-parented, not rendered (`D-253`).

**Reproduction, measured on the installed package in a real renderer (2026-11-12).** Each pane authors `component: { reference: 'zone-format', target: 'css.classes' }`. `rootNode.compile(nodes)` answers **`actionable = [app, pane-menus]`** — `#top` absent, `app.childOrder = ['node-2']`, `node-2` never created — **while the pane's own `css.classes` read `['pane', 'in-top']`: the value is right and the element is gone** (`D-253`).

**Suspected root cause.** `dist/core/node.js:1223`: `if (hasAnyTarget && isResolutionParticipant(node) && !isSeamProvider(node)) continue;` — with its own docblock at `dist/core/node.js:1154` stating the intent, that a PURE provider consumed by name is dropped. **The predicate is total**: it drops every name-consumed provider, and that docblock's sentence is false of a zone, which is a value holder **and** an element (`D-5`).

**Second finding — the seam escape keeps the zone and loses the position.** `target: 'type'` renders the zone and puts the definition's classes on the pane's own element, but the definition is read **by name** (`dist/core/registry.js:132-135`): with two zones authoring one `reference`, the pane standing in `top` emitted `['in-left']` — the last-registered prototype — while its compiled `bindings` said `in-top` (`D-264`).

**Proposed fix shape.** Narrow the drop predicate to ask whether the provider is an **element**: drop a name-consumed provider only when it has **no family parent**. If that is too broad for shipped shapes, an explicit opt-in — `component: { …, provide: 'element' }` — under which the provider renders and its value is still consumed by name (`D-5`). **Rejected on cost and named so it can be:** making `materializeSeam` read nearest-ancestor and mint one def-root per provider fixes both findings and changes how every seam in the package resolves (`D-5`).

**Discharge state — 2026-11-13, on the installed `provident-ssr@0.5.2`.** **The element half is discharged and the version is named**: the compile emit gate narrowed from *any name-consumed provider* to *a runtime-minted VALUE RECORD* — `node.valueRecord`, written by `mintRowNode` alone (`ops.js`), so an authored node reads `undefined` and no document can forge it. Re-measured on this record's own reproduction: `actionable = [app, top, pane-menus]`, `#top` present with its pane inside it, the pane reading `['pane', 'zone-sidebar-format']` (`D-5`). **The seam half did not move**: with `top` authored first, the emitted element still carries the last-registered `['in-left']` while the bindings say `in-top`, which upstream records as `R-VPD-1`, NOT fixed (`D-5`). **And `css.classes` is still the only css seam** — `target: 'css.style.<key>'` is a blocked css-family target — so a pane inherits class names and no declaration, which is why the fill, the figure and the scroll stay the paint's (`D-264`).

**What this unit did with the discharge (`D-264`'s next step).** **The pane's zone format is now inherited by position and nothing writes it**: each of the four zones authors `component: { reference: 'zone-format', value: ['pane-in-<zone>'] }`, the app root authors the stage's value, and each pane authors the one-line consumer — so a fourth pane authored with that one consumer inherits the sidebar form with no CSS edit (`D-264`). **Deleted, each with what it removes**: the pane's painted `props.zone` attribute (`paintStyle` now takes no attribute list), `declaredZoneNameOf`, `publishedZoneOf`'s preview guard (re-pointed at the style text) and the sheet's `[zone=…]` keys (`D-264`). **Kept, because a class carries no declaration**: the record's adjustable figure (`D-243`) and the layout's fill/scroll relation (`PANE_FILL`/`LAYOUT_ZONE_AXES`), both written per delivery; and **kept because the inheritance does not cover it**: `D-262`'s declared-place fallback for the order, and the drops' authored `props.zone`, which is the act's destination operand and not a formatting key (`D-262`). **Measured after, on a fresh profile with real drags**: a `['panes','pane-menus','zone']` write to `left` repaints `pane-in-left` and the write back restores a **byte-identical rendered HTML**; mid-drag the pane wears the target zone's class while the record stands untouched by the gesture (`D-264`).

**If a later package version resolves the seam's def root by position, that half is re-read here the same way and this finding closes** (`D-5`).
