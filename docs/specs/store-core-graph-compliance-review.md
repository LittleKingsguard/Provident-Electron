## 3. THE FOUR FAMILY VERDICTS

**All three non-purity verdicts are REQUESTS-TO-ADOPT or FINDINGS, not breaches of an adopted repo rule** — see §1. They are stated at their honest strength.

### (1) MODULARIZATION — **NON-COMPLIANT against the family; UN-ADOPTED in this repo; the substance is a REAL gap.**

**The facts.** No artifact, no hash, no scratch root, no wave state (`§2` rows 4/6). **And the family is not adopted here** (`§1`). **But the module HAS a freezable surface** — enumerable interface functions (2 value exports, 27 type declarations), declared error shapes (the closed refusal union + the one `GraphLoadError`), locatable start/end points — **so PARK is unavailable, exactly as `§4.4`'s structural test requires** (`no freezable surface` does not obtain). **The exit set is therefore exactly two: a wave re-entry, or a recorded scope ruling that the wave does not apply.**

**Why the gap is substantive rather than bookkeeping.** The freeze exists to make the surface, the licence and the re-freeze **comparable**. That is `I3`'s shape with no frozen surface to be stale against.

### (2) INTEGRATION — **NON-COMPLIANT against the family; UN-ADOPTED in this repo; ONE HARD BREACH and ONE UNAVAILABILITY.**

- **The licence's UNION is declared but not asserted as a set.** `§5.1` names the two module paths and the conditional wiring row 6; nothing asserts `edit-set ⊆ surface ∪ host wiring points` **by set equality**, and `§3.4 R-10` asserts only the pre-existing frozen surfaces. **Remedy:** one row naming the union's two components with a positive control that an edit outside it FAILS.
