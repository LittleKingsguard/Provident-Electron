**What this section is.** The ledger text is **contract-exact** about the lifecycle and the binding negatives; it is **silent** about several clauses a TestWriter must have before it can author a **falsifiable** row. **This filing DECIDES each of those clauses and records the decision here**, each with its reason and its landing site. **No decision here weakens a binding negative**, and **`§7a` lists the items that could NOT be decided from the sources** — those are ARCHITECT questions, and they are the ones `§7a.1` does **not** rule.

**Ruling note 1 — the module path is `src/shared/gesture-session.ts`, and the test file is `tests/gesture-session.test.ts`.** **No source names either path.** The sibling convention decides it (`src/shared/mount-invariant-guard.ts`, `owned-list-host.ts`, `slot-host.ts`, `layout-projection.ts`, `zones.ts`, `census.ts`), and the unit's own name (`U-GSESSION`, *gesture session*) decides the stem. **Nothing else in this file presumes the path.** *(The same note names the test file, because `§5.1`'s diff scope must be a real, checkable allow-list.)*

**Ruling note 2 — THERE IS NO AMBIENT ELEMENT SOURCE AND NO SELECTOR CHANNEL: the CONTROL ELEMENT IS PASSED BY THE CONSUMER.** The ledger's *"each gesture-start listener attached to ITS OWN CONTROL ELEMENT"* is expressed here as an **element argument of `install(element, options)`** — the **exact object reference** the consumer already holds. **The session NEVER derives, looks up or re-queries an element** (`R-2` forbids `closest`/`querySelector`/`getElementById`/`querySelectorAll` **as tokens in any form**), **and it holds no registry of controls other than the ones it installed into** (that registry exists precisely so `dispose()` can perform the baseline restore the ledger names). **The element is compared by IDENTITY (`===`, `Object.is`-equivalent for objects), never by name, class, attribute or position.** Landing: `§2.1`, `§2.4` item 2, `M-1`, `R-2`, `R-5`, **`I-9`**.

**Ruling note 3 — "THE LISTENER BASELINE" IS THE SESSION'S OWN LEDGER, AND `dispose()` RESTORES IT EXACTLY.** *"`dispose()` restoring the listener baseline"* cannot mean *"the element has zero listeners afterwards"*: **the session cannot observe, enumerate or remove listeners another party installed, and a claim that it can would be a false claim about an unverifiable subject.** **RULED:** the session maintains an **exact ledger** of the listeners **it** attached, and `dispose()` **detaches every one of them**, so that **after `dispose()` the session's own contribution to the page is EMPTY** — every `on(element, type, handler)` call it made is matched by exactly one `off(element, type, handler)` call with the same three values. **`dispose()` reports what it did** (`DisposeReport.removed`) **and reports honestly whether the detach was complete** (`DisposeReport.complete`) — because an injected source's `off` may itself fail, and **that failure must not be reported as a baseline restore**. Landing: `§2.1` (`dispose`), `§2.3` item 7, `M-13`, `I-5`, `F-7`, **`P-GS-IM-6`**.

**Ruling note 4 — THE SESSION DOES NOT READ POINTER IDENTITY, AND `pointerup` IS UNCONDITIONALLY TERMINAL.** The ledger requires *"the session ends on up/cancel"* and nothing about multi-pointer disambiguation. **RULED:** the session treats **every** `pointerup` **and every `pointercancel`** as a terminal event for the active gesture, **without reading any field of the event object** (`pointerId`, `button`, `buttons`, `isPrimary` — the event is **opaque and is never inspected**, which is also what keeps `P-GS-TP-2`'s boundary trivially satisfiable and makes the magnitude clause of `§2.3` item 5 airtight). **A second pointer's `pointerdown`** on the same control while a gesture is active is **not** a terminal and does **not** start a second gesture: it is handled by the **first-only rule** (`§2.3` item 3), so a gesture has **exactly one active gesture per session** and **no pointer bookkeeping exists**. **`U-GUTTER`/`U-RELOCATE` own any pointer-identity policy they want, and they may not ask the session for it.** Landing: `§2.4` items 3/4, `M-9`, **`F-9c`**, `§5.5.1 P-GS-TP-2`. **This is the one clause of this filing that COULD be a contract change later; it is recorded as ARCHITECT QUESTION 3 (`§7a`) because the sources are silent and a real multi-pointer consumer could want otherwise.**

**Ruling note 5 — THE CONSUMER NEVER CALLS `commit()`: THE SESSION CALLS IT EXACTLY ONCE, AT A TERMINAL.** The ledger's *"exactly ONE COMMIT per gesture"* and *"cancel ⇒ ZERO commits"* are only **countable** if the session owns the call. **RULED:** `commit` is an **injected callback** that the session invokes **exactly once**, and only from the **`end`** and **`reset`** terminals (**`cancel` invokes it zero times**). **This is what makes `U-GUTTER`'s and `U-RELOCATE`'s commit rows derivable FROM THE SESSION rather than re-implemented per controller** (`§2.6` items 1–3), and it is the mechanism of the single-gesture-authority remedy. **A consumer that wants different writes builds the value in `onMove`/`onEnd` and lets the session commit it.** Landing: `§2.1` (`SessionOptions.commit`), `§2.3` item 5, `§2.6`, `M-10`/`M-11`/`M-12`, `I-2`/`I-3`/**`I-3b`**/`I-3c`, **`P-GS-SM-3`**. **Recorded as ARCHITECT QUESTION 2 (`§7a`) because the alternative shape (a controller-called `session.commit()`) is expressible with the same ledger words.**

**Ruling note 6 — `reset` IS A SESSION TERMINAL, and *"the supplied default"* stays the CALLER'S VALUE.** The session exposes **three** terminals (`end`, `reset`, `cancel`) because `U-GUTTER`'s row — *"reset ⇒ exactly ONE commit of the **supplied** default"* — **cannot be expressed as a sequence of the other two without violating the one-commit-per-gesture rule** (a `cancel` + a fresh `begin` + `end` is **two gestures**, and a bare `end` with a default value is indistinguishable from a user-chosen end). **The session is still policy-free about it:** it accepts **any** caller-supplied value, holds **no** default, and **never computes one** — *"the supplied default"* is the consumer's value and the session merely commits it **exactly once** with the outcome `'reset'` so the consumer's `commit` callback can tell the two terminals apart. Landing: `§2.1` (`reset`), `§2.3` item 5, `M-12`, `I-3b`, `F-4`, `§2.6` item 3. **Recorded as ARCHITECT QUESTION 1 (`§7a`) for the same reason as note 5.**

**Ruling note 7 — THE LEDGER'S `E3`-BEFORE-`E6` ORDER IS AN ANOMALY, AND THIS FILING FOLLOWS THE ARCHITECT'S ORDERING INSTEAD.** `docs/next-steps.md`'s `## OPEN` table numbers `E3` (`U-GUTTER`) **before** `E6` (`U-GSESSION`), and the `E3` row's own `Blocked on` cell names *"then `U-CENSUS` **and `U-GSESSION`** (the session it composes)"* — i.e. **the table's own dependency edge contradicts its row order**. **Ruling note 8 — THE SESSION'S OWN STATE IS ONE GESTURE DEEP AND IS DISCARDED AT EVERY TERMINAL.** So that *"no store, no persistence"* is a **testable** claim rather than a slogan: the instance keeps (a) the installed-control ledger, (b) **at most one** record for the active gesture — its element, its monotonic id, and its current value — and (c) two monotonic counters (`gestureSeq`, `commitCount`). **Every terminal discards (b) entirely** (`active` becomes `false`, `element`/`value` become `undefined`, `outcome` keeps only the terminal's own word), and **the counters never reset** (they are the *"one commit per gesture"* evidence, `§2.1` `stats()`). **No value, key, element or policy crosses a gesture boundary.** Landing: `§2.3` item 8, `I-12`, `I-12b`, `M-13`, `§2.2` P-8.

**Ruling note 9 — THE EVENT SOURCE IS `{on, off, isConnected?}`, AND AN UNUSABLE SOURCE IS THE VALID-STATE DEGRADATION, NEVER A THROW.** This repo's doctrine is that **environment readings are INJECTED** (`U-LISTHOST`'s `itemFactory`, `U-SLOTHOST`'s element factory per `SLOTHOST-CONTAINER-SOURCE-IS-INJECTED`, `A-d6`'s `{prefersDark}` env), and the `A-d3` ruling's own words are **an injected event source**. **RULED:** the source is an object with the callables `on`, `off` and an **optional** `isConnected`; **if the source (or any of `on`/`off`) is not usable — absent, non-object, non-callable, or THROWING when called — the session degrades to its VALID state:** `install` returns `false`, `begin` reports the declared code, `stats()` reports zeros, and **nothing throws at the consumer boundary** (`createGestureSession` itself never throws, whatever it is handed). **`isConnected` MAY be absent** (a headless/test source need not model connectivity); **it is consulted only when callable, and its `false` is the ONLY failing answer** — a non-boolean return, a throw, or its absence means **"no contrary evidence"** and the check passes. Landing: `§2.1` (`EventSource`), `§2.4` items 5/6, `F-5`..`F-8`, `I-10`/`I-11`, `§5.5.1 P-GS-TP-1`.

**Ruling note 10 — THE EVENT TYPES ARE THE SESSION'S CONTRACT, AND THE CONSUMER NEVER SUPPLIES ONE.** The rejected `selectors` vocabulary is a **selector string**; the event-type names are **not** consumer vocabulary — they are the **mechanism's own contract with its injected source**, and `A-d3`'s own quoted sentence names `pointerdown` itself. **RULED:** the session pins the four `TYPE` constants **privately** (`'pointerdown'`, `'pointermove'`, `'pointerup'`, `'pointercancel'`) and **exposes no parameter, option, union member or default by which a consumer could substitute one** — so **no `selectors` string and no `threshold` number exists anywhere in the surface** (`P-1`, `R-1`). **A consumer that needs different event types does not exist under the `A-d7` static-UI reading, and inventing one would be a new contract with its own gate.** Landing: `§2.1` (the private constants note), `§2.4` item 1, `R-1`, `§4.4 S-1`.

## 1. Scope

**One deliverable: one `src/shared` module — a node-local interaction session with an INJECTED event source, one active gesture at a time, exactly one commit per gesture, and a `dispose()` that restores its own listener baseline.**

1. **What the unit is, in one sentence.** A **synchronous, policy-free gesture lifecycle**: the consumer hands it an **event source** and, per control element, a small **config**; the session attaches **one** gesture-start listener to **that element**, opens the gesture-scoped tracking listeners **only between start and terminal**, carries the gesture's **current value** (whatever the consumer's own `onMove` computed), and **commits exactly once** at a terminal — `end` (one commit), `reset` (exactly one commit of the **supplied** value), `cancel` (**zero** commits).
2. **What it is NOT — no policy.** **Bounds, defaults, resizability, axes, thresholds, drop resolution, candidates and reveal sets are ALL the consumer's**: the session **computes no value**, holds **no default**, compares **no** pointer position, evaluates **no** policy predicate, and **reads NO field of any event object**. This is what makes `U-GUTTER`'s and `U-RELOCATE`'s arithmetic/policy rows **their own** and this unit's rows **counts and lifecycle** (§2.6).
3. **What it is NOT — no DOM access.** The session **never** touches a DOM global: it calls **only** the injected source's `on`/`off`/`isConnected` (and only for elements and handlers it was handed), and it **never** looks an element up by selector, id, class, attribute or name (`R-2`).
4. **What it is NOT — no UI.** It authors **no text, no control, no affordance, no class, no attribute and no styling**; it is a **mechanism**, and outside the `UI-RENDERED-WITH-PROVIDENT` constraint **because it is not a UI element** (`SHELL-CHROME-CARVE-OUT-FUNCTIONAL`, `§0` ruling 6).
5. **What it is NOT — no store, no persistence, no journal, no MCP surface.** No file, no `localStorage`, no store object, no cache, no module-level mutable state, no new tool/resource/group/`VALID_GROUPS` member/`RpcMethod` member/`MUTATING_METHODS` entry/IPC method. **A session is NOT journaled**, so **no `undo()`/`replay()` inverse exists** and **no unit may claim magnitude-equivalence with `provident.op`'s `state-slice`** (`§0` ruling 7).
6. **What it is NOT — no cross-unit composition, no duplication.** It **imports nothing** (not `U-ZONES`, not `U-CENSUS`, not `U-PROJ`, not `U-LISTHOST`/`U-SLOTHOST`, not the shim, not the engine) and **duplicates no sibling responsibility**. **`U-GUTTER` and `U-RELOCATE` compose THIS unit; this unit composes nothing** (`§0` ruling 13).
7. **Two dependencies EXPLICITLY ABSENT, recorded so a later pass does not assume them.** **(a)** The engine pin (`A-d2`) is **SPENT**: this module imports nothing and exercises no engine surface. **(b)** Neither `DONE` sibling (`U-ZONES` row `E1`, `U-CENSUS` row `E2`) is a dependency: **no edge exists in either direction** — a later pass asserting one would be a **fabricated edge** (`H-r6`'s dissolved-edge class).
8. **What is EXPLICITLY OUT of scope (do not do in this unit).** No `createResizeController`/`clampToBounds`/`boundsFor`/`defaultSizeFor`/`isResizable`/`axisFor` (that is `U-GUTTER`, `E3`). No `createRelocateSession`/`candidatesFor`/`resolveTarget`/`onReveal`/drop model/`threshold` (that is `U-RELOCATE`, `E4`). No `tokensFor`/`orientationFor`/`contain` declaration (`U-CONTAINER`, `E5`). No theme/`resolveTheme` (`U-THEME`, `E8`). No menu catalog (`U-MENULIB`, `E7`). No overlay state machine (`U-OVERLAY`, `E9`). No mount cardinality (`U-MOUNTGUARD`, `DONE`). No census/track vocabulary (`U-ZONES`/`U-CENSUS`, both `DONE`). No projection/applier/write sink (`U-PROJ`, `DONE`). No list host or slot host (`U-LISTHOST`/`U-SLOTHOST`, both `DONE`). No new MCP surface. No shim change. No `docs/skills/designing-pages.md` update — **no such file exists** (globbed `docs/skills/*` this pass: `process-guardrails.md` alone), so there is **no test-use-case coverage matrix and no demo-page index to update**, and **this unit renders no page**.
9. **What the unit may land.** The module (NEW) + its red/green rows + the register rows + this spec. **No host change**: this unit adds one new `src/shared/` module and touches **no existing file** except this spec and the trackers (`§5.1`).

### 2.1 What this unit ADDS — every exported name, signature, return shape, and error pattern

**New module: `src/shared/gesture-session.ts`** (`§0A` note 1). **It imports NOTHING — not even a type** (`R-4`).

```ts
/** WHAT `isConnected` MAY DO — total, and the ONLY connectivity reading the
 *  session is allowed to consult. It is consulted ONCE per `begin` attempt.
 *  ABSENT / non-callable ⇒ "no contrary evidence".  A THROW ⇒ "no contrary
 *  evidence" (the failure is swallowed, never propagated).  Returning exactly
 *  `false` is the ONLY answer that makes connectivity fail; any other return
 *  (including `undefined`, `null`, `0`, `''`) means "not known to be
 *  disconnected" and the check PASSES (§2.4 item 5). */
export type GestureElement = unknown

/** THE INJECTED EVENT SOURCE — the A-d3 seam. The session NEVER calls
 *  `addEventListener`/`removeEventListener`, `setPointerCapture`,
 *  `releasePointerCapture`, `closest`, `querySelector*` or `getElementById`
 *  on anything, ever (§2.2 P-2/P-3; R-1/R-2/R-7).  Every listener the session
 *  attaches goes through `on` and every detach through `off`, with the EXACT
 *  three values it was given (`R-7`). */
export interface EventSource {
  /** Attach `handler` to `element` for the event TYPE named (one of the
   *  session's four private constants).  Called EXACTLY once per attached
   *  listener; never called for a handler already attached.  A source whose
   *  `on` is not callable, or throws, makes the session degrade to its VALID
   *  state (§2.4 item 6) — the throw never reaches the consumer. */
  on(element: GestureElement, type: string, handler: () => void): void
  /** Detach `handler` from `element` for that TYPE.  Called EXACTLY once per
   *  prior `on` call, with the same three values (referential identity for
   *  `handler`).  A throwing `off` is caught PER CALL: the remaining detaches
   *  still run, and the report's `complete` becomes `false` (`§0A` note 3). */
  off(element: GestureElement, type: string, handler: () => void): void
  /** OPTIONAL. The ONE connectivity reading allowed (`§2.4` item 5). */
  isConnected?(element: GestureElement): boolean
}

/** WHAT THE CONSUMER PASSES AS THE PER-CONTROL OPTIONS.  Both fields are
 *  OPTIONAL; an absent `capture` is `false` (the A-d3 pin, §0 ruling 2), and
 *  an absent field is THE ABSENCE OF OPT-IN, never a mechanism default.
 *  `capture` is read for TRUTHINESS (`Boolean(capture) === true`), so any
 *  truthy value opts in and every falsy value does not (P-GS-IM-5). */
export interface GestureOptionsInput {
  /** PER-CONTROL OPT-IN for pointer capture AFTER establishment.  `false`
   *  (or absent, or falsy of any kind) ⇒ ZERO capture calls, ever.  `true`
   *  (or any truthy value) ⇒ exactly ONE `setPointerCapture`-call by the
   *  injected source, inside `begin`, AFTER the gesture is established. */
  readonly capture?: unknown
  /** Called synchronously at the END of a successful `begin`, AFTER the
   *  tracking listeners are attached and AFTER the capture call (if opted in).
   *  It receives the element and the gesture handle.  A throw propagates to the
   *  caller of `begin` and leaves NO listener behind (`§2.3` item 3). */
  readonly onStart?: unknown
  /** Called synchronously for EVERY `pointermove` of the active gesture, with
   *  the gesture handle.  The consumer COMPUTES its own next value here
   *  (bounds, axes, thresholds, resolution — all policy, §1 item 2) and hands
   *  it back with `gesture.set(value)`.  The event object is NOT passed: the
   *  session does not own the event data and does not read any field of it. */
  readonly onMove?: unknown
  /** Called synchronously at an `end` or `reset` terminal, AFTER the tracking
   *  listeners are detached and BEFORE `commit` is invoked (§0A note 11).
   *  `value` is the gesture's current value (`undefined` if the consumer never
   *  set one — the commit still happens exactly once, `§2.3` item 5). */
  readonly onEnd?: unknown
  /** Called synchronously at a `cancel` terminal (including a
   *  `pointercancel`, a cancelled `dispose()`, and a source-disconnect
   *  observation), AFTER detach, BEFORE nothing — `commit` is NEVER invoked
   *  from here. */
  readonly onCancel?: unknown
}

/** THE SESSION'S OWN VIEW OF ONE CONTROL — `capture` already resolved to a
 *  boolean, hooks present only where the consumer supplied a callable. */
export interface GestureOptions {
  readonly capture: boolean
  readonly onStart?: (element: GestureElement) => void
  readonly onMove?: (gesture: GestureHandle) => void
  readonly onEnd?: (element: GestureElement, value: unknown) => void
  readonly onCancel?: (element: GestureElement) => void
}

/** THE HANDLE FOR THE ONE ACTIVE GESTURE.  Handed to `onStart`/`onMove`, and
 *  accepted (and RE-CHECKED by identity) by every terminal call. */
export interface GestureHandle {
  /** MONOTONIC, instance-local, starts at `1`, increments on every successful
   *  `begin`, NEVER reused and NEVER reset (not even by `dispose()`). */
  readonly id: number
  /** The EXACT element reference passed to `install` (`§0A` note 2). */
  readonly element: GestureElement
  /** `true` while the gesture is in flight (between a successful `begin` and
   *  its terminal); `false` once a terminal has run. */
  readonly active: boolean
  /** `null` while active; then `'end'` · `'reset'` · `'cancel'` — the closed
   *  three-member union, and the ONLY outcome vocabulary the session has.
   *  `'reset'` is how a consumer's `commit` callback distinguishes a reset
   *  from a user-chosen end (§0A note 6). */
  readonly outcome: 'end' | 'reset' | 'cancel' | null
  /** The gesture's CURRENT value — the last value handed to `set`, else
   *  `undefined`.  It is the value `commit` will receive at an `end`/`reset`
   *  terminal, and it is DISCARDED at every terminal (§0A note 8). */
  readonly value: unknown
  /** Set (or replace) the gesture's current value. TOTAL: ANY value is
   *  accepted — `undefined`, `null`, a number, a string, an object, a
   *  function, a `Symbol` — and NOTHING is validated, coerced or defaulted
   *  (§1 item 2).  Returns the handle.  A call on a non-active handle is a
   *  no-op that returns the same handle. */
  set(value: unknown): GestureHandle
}

/** WHAT THE CONSUMER PASSES TO `createGestureSession`.  `commit` is the ONE
 *  injected commit callback (§0A note 5). */
export interface SessionOptions {
  /** THE injected event source (`§2.4` item 6).  Absent / non-object / a
   *  source whose `on` or `off` is not callable ⇒ the valid-state
   *  degradation; `createGestureSession` still returns a usable instance. */
  readonly source?: EventSource
  /** INVOKED BY THE SESSION, EXACTLY ONCE PER GESTURE, and only at an
   *  `end` or `reset` terminal — `cancel` invokes it ZERO times.  It receives
   *  the terminal handle (whose `outcome` distinguishes `'end'` from
   *  `'reset'`) and the gesture's final value.  It is invoked AFTER the
   *  tracking listeners are detached (§0A note 11).  A throw PROPAGATES to
   *  the caller of the terminal; the commit still counts as the gesture's ONE
   *  commit, and nothing is retried (`I-3c`). */
  readonly commit?: (gesture: GestureHandle, value: unknown) => void
}

/** THE RESULT OF `begin`.  A discriminated union: `ok: true` guarantees a
 *  handle, `ok: false` guarantees a `code` and NO handle. */
export type BeginResult =
  | { readonly ok: true; readonly gesture: GestureHandle }
  | { readonly ok: false; readonly code: GestureCode }

/** THE RESULT OF `end` / `reset` / `cancel`.  `committed` is the SESSION'S OWN
 *  record of whether it invoked `commit` for THAT call — `true` for a
 *  successful `end` and a successful `reset`, `false` for a successful
 *  `cancel` and for every refusal. */
export type TerminalResult = {
  readonly ok: boolean
  readonly code: GestureCode
  readonly committed: boolean
}

/** THE RESULT OF `dispose()`.  `removed` counts the listeners DETACHED BY THIS
 *  CALL; `complete` is `true` iff every detach this call attempted succeeded
 *  (`§0A` note 3).  A second `dispose()` reports `removed: 0`. */
export type DisposeReport = {
  readonly removed: number
  readonly complete: boolean
}

/** THE CLOSED RESULT-CODE UNION — SEVEN members, no eighth (§2.3 item 4). */
export type GestureCode =
  | 'ok'
  | 'not-installed'
  | 'busy'
  | 'disposed'
  | 'disconnected'
  | 'stale'
  | 'no-gesture'

/** THE SESSION'S OWN COUNTERS (`§0A` note 12).  All values are monotonic
 *  except `active`/`outcome`, and nothing here is a policy fact. */
export interface SessionStats {
  /** Installed control elements, by identity. */
  readonly installed: number
  /** Total source calls the session made: `on` + `off` + `isConnected`. */
  readonly sourceCalls: number
  /** Successful `begin` calls, instance-lifetime. */
  readonly gestures: number
  /** `commit` invocations, instance-lifetime. */
  readonly commits: number
  readonly active: boolean
  /** The active gesture id, or `0` when idle. */
  readonly gestureId: number
  /** The LAST result code this session produced (`'ok'` before anything
   *  happened), so a consumer can read a refusal without a `try`/`catch`. */
  readonly lastCode: GestureCode
}

/** THE ACTIVE-GESTURE READING (`gesture()`). */
export interface GestureStats {
  readonly active: boolean
  readonly id: number
  readonly outcome: 'end' | 'reset' | 'cancel' | null
  readonly value: unknown
  /** `commit` invocations attributable to THIS gesture: `0` while it is
   *  active and after a `cancel`; `1` after an `end`/`reset`. */
  readonly commits: number
}

/** THE SESSION — the node-local lifecycle.  Every member is TOTAL (`I-10`):
 *  none throws for any argument, whatever the injected source does. */
export interface GestureSession {
  /** Attach ONE `pointerdown` listener to `element`, bound to a new gesture.
   *  Returns `true` iff a listener was attached by THIS call.  Returns
   *  `false` — attaching NOTHING — when: the session is disposed; `element`
   *  is `null`/`undefined`; `element` is ALREADY installed (repeat install is
   *  a NO-OP, never a second listener: the FIRST config wins, §2.4 item 2);
   *  the source is unusable; or the source's `on` threw.  TOTAL: never throws. */
  install(element: GestureElement, options?: GestureOptionsInput): boolean
  /** Establish a gesture on an INSTALLED element.  Called BY THE SESSION's own
   *  `pointerdown` listener; callable by the consumer directly (it is the
   *  seam `R-7`'s tests drive).  Codes: `'ok'` · `'not-installed'` (never
   *  installed, including an element installed only by ANOTHER session) ·
   *  `'busy'` (a gesture is already active on THIS session — one at a time,
   *  `§2.3` item 3) · `'disconnected'` (the source's `isConnected(element)`
   *  returned exactly `false`, `§2.4` item 5) · `'disposed'`.  On `'ok'`: the
   *  tracking listeners are attached, the capture call is made iff opted in,
   *  `onStart` runs, and the handle is returned. */
  begin(element: GestureElement): BeginResult
  /** END the gesture and COMMIT — exactly once — the gesture's current value,
   *  or `value` when a non-`undefined` `value` argument is supplied (§2.4
   *  item 4).  The handle must be THE ACTIVE gesture's handle (identity
   *  checked): a stale handle refuses `'stale'` and commits NOTHING. */
  end(element: GestureElement, gesture: GestureHandle, value?: unknown): TerminalResult
  /** RESET the gesture: detach, then COMMIT — exactly once — the SUPPLIED
   *  value, with `outcome = 'reset'` (§0A note 6).  The session supplies no
   *  default of its own; ANY value is accepted. */
  reset(element: GestureElement, gesture: GestureHandle, value: unknown): TerminalResult
  /** CANCEL the gesture: detach, run `onCancel`, and invoke `commit` ZERO
   *  times.  This is the path for a `pointercancel`, a consumer abort, and a
   *  `dispose()` during a gesture (§2.3 item 6). */
  cancel(element: GestureElement, gesture?: GestureHandle): TerminalResult
  /** THE BASELINE RESTORE (§0A note 3): cancel any active gesture WITHOUT
   *  committing, detach EVERY listener this session attached (start listeners
   *  included), empty the installed ledger, and make the instance
   *  PERMANENTLY INERT.  IDEMPOTENT: a second call is a no-op reporting
   *  `{removed: 0, complete: true}`.  Never throws. */
  dispose(): DisposeReport
  /** The active gesture's reading, or `null` when idle. */
  gesture(): GestureStats | null
  /** The session's own counters. Never throws. */
  stats(): SessionStats
  /** `true` forever once `dispose()` has run. */
  readonly disposed: boolean
}
```

**The four private type constants, pinned exactly** (the session's contract with its injected source; `R-1` scans for the ABSENCE of every other form, `R-7` for the delegation): **`start = 'pointerdown'`** · **`move = 'pointermove'`** · **`end = 'pointerup'`** · **`cancel = 'pointercancel'`**.

1. **What they may call, and nothing else:** `createGestureSession({source, commit})` **once per session**; `install(element, {capture?, onStart?, onMove?, onEnd?, onCancel?})` **once per control element**; `begin(element)` **to establish** (normally left to the session's own listener); `end(element, gesture, value?)` · `reset(element, gesture, value)` · `cancel(element, gesture?)` **as terminals**; `dispose()` **to restore the baseline**; `gesture()`/`stats()`/`disposed` **to read state**; and — on the handle the session gave them — `set(value)`.

3. **What they may NOT do, because it would create the second authority `V-13` names:** attach a listener of their own to the control's `pointerdown`/`pointermove`/`pointerup`/`pointercancel` (the session's listeners are the gesture stream); call their `commit` callback themselves (the session invokes it exactly once — `§0A` note 5); read or set a value except through `gesture.set(...)`; keep a reference to the handle past the terminal (the handle reports `active: false` and every terminal on it refuses `'stale'`); or ask the session for bounds, an axis, a threshold, a drop target or a reveal set (**no such parameter exists**).
4. **What remains THEIRS, and is not expressible through this session:** every policy decision (`clampToBounds`, `defaultSizeFor`, `isResizable`, `axisFor`, `resolveTarget`, `candidatesFor`, `threshold` arithmetic, the reveal set) and **every write to a sink** — including `U-RELOCATE`'s `onReveal`, which **must be invoked only inside its own `commit` callback** if the *"reveal written exactly once per gesture at gesture end"* row is to be derivable (`§2.6` item 7).
5. **The composition's own rows are NOT this spec's rows.** `U-GUTTER`'s call counts and `U-RELOCATE`'s reveal-once row are **their specs'**, and **this filing asserts only that each is DERIVABLE from `§2.3`/`§2.6`** — not that it holds.

### 2.3 The lifecycle rule — the session's whole contract, stated falsifiably

**Item 1 — ATTACHMENT: exactly one gesture-start listener per installed control, on ITS OWN element.**

| Order | Step | Exact behaviour |
| --- | --- | --- |
| **(a)** | `install(element, options?)` with a USABLE source and a distinct `element` | the session records the element **by identity** and calls **`source.on(element, POINTER_TYPES.start, handler)`** **exactly once**, where `handler` is bound to **that** element; returns `true` |
| **(b)** | the same `element` installed a second time | **NO source call at all**, and the return is `false`: **a repeat install is a NO-OP** ("a second `install` does not double listeners"); **the FIRST config wins and is not replaced** (`§2.4` item 2) |
| **(c)** | `install` with `null`/`undefined` element, a DISPOSED session, or an unusable source | **NO source call**, return `false`, and **no ledger entry is created** |
| **(d)** | the session's own `handler` runs (a real `pointerdown` on that control) | it calls **`begin(element)`**, and **the event object is not read and not passed anywhere** — the handler takes no parameter |

**Item 2 — THE GESTURE WINDOW: tracking listeners exist ONLY between start and end.**

| Order | Step | Exact behaviour |
| --- | --- | --- |
| **(a)** | a successful `begin` | after the establishment checks (`§2.4` item 5), the session calls **`source.on(element, POINTER_TYPES.move, hMove)`**, **`source.on(element, POINTER_TYPES.end, hEnd)`**, **`source.on(element, POINTER_TYPES.cancel, hCancel)`** — **in that order, once each, on the SAME element**, so the session's listener count on the element goes from **`1`** to **`4`** |
| **(b)** | while the gesture is active | `hMove` runs the consumer's `onMove(gesture)`; `hEnd` runs the `end` terminal; `hCancel` runs the `cancel` terminal. **No listener is ever added to any OTHER element during a gesture** (no window/document tracking — `A-d3`'s rejected shape) |
| **(c)** | a terminal (`end`, `reset`, `cancel`) | the **FIRST** step is `source.off(element, POINTER_TYPES.move, hMove)` · `off(…, end, hEnd)` · `off(…, cancel, hCancel)` — **once each, same values, detach before any consumer code** (`§0A` note 11) — so the count returns to **`1`** and **the baseline is restored before `onEnd`/`onCancel`/`commit` run** |
| **(d)** | after the terminal | the element stays **installed** (its start listener remains) until `dispose()`; a new `pointerdown` establishes a **NEW** gesture with a **NEW** id |

**Item 3 — ONE GESTURE AT A TIME (the single-authority rule).** A `begin` while a gesture is active returns **`{ok:false, code:'busy'}`** and **changes nothing**: **no second gesture, no second listener set, no re-entrancy into the active gesture's value, no second commit**. A `pointerdown` on **another** installed control during an active gesture is likewise **`'busy'`** — the session is **one gesture authority for its whole instance**, which is the remedy `V-13` names: *"a second authority over the same gesture lifecycle"* is exactly what this item forbids.

**Item 4 — THE TERMINALS, with their commit counts (THE HEART OF THIS UNIT).**

| Terminal | Precondition | Detach | Hook | `commit` invocations | `outcome` | `TerminalResult` |
| --- | --- | --- | --- | --- | --- | --- |
| **`end(element, gesture, value?)`** | `gesture` is the **active** handle (id AND element identity) | yes, all three, once each | `onEnd(element, final)` | **EXACTLY 1** | `'end'` | `{ok:true, code:'ok', committed:true}` |
| **`reset(element, gesture, value)`** | as above | yes, all three, once each | `onEnd(element, value)` | **EXACTLY 1**, of the **supplied** value | `'reset'` | `{ok:true, code:'ok', committed:true}` |
| **`cancel(element, gesture?)`** | `gesture` omitted, or the **active** handle | yes, all three, once each | `onCancel(element)` | **EXACTLY 0** | `'cancel'` | `{ok:true, code:'ok', committed:false}` |
| **any terminal on a stale/absent handle** | — | **NO detach** (nothing of this call's own), **NO hook**, **NO commit** | — | **0** | unchanged | `{ok:false, code:'stale' \| 'no-gesture', committed:false}` |
| **`dispose()` during an active gesture** | — | **ALL listeners**, start included | `onCancel(element)` | **EXACTLY 0** | `'cancel'` | `DisposeReport` |

**The final value rule, exact:** the value committed by `end` is **the `value` argument iff it is not `undefined`**, otherwise the gesture's current value (the last `gesture.set(…)` value), otherwise `undefined`. **The commit happens in EVERY successful `end`** — including an `end` whose value is `undefined` (`§0A` note 5) — so *"one commit per gesture"* is a **count**, never a *"commit only if something changed"* heuristic. **`reset` always commits its supplied value, which may be `undefined`** (the session supplies nothing).

**Item 5 — THE COMMIT IS THE SESSION'S CALL, AND IT IS COUNTED.** `commit` is invoked **by the session**, exactly once per gesture that reaches `end`/`reset`, **never** at `cancel`, **never** twice — and the session **counts its own invocations** (`stats().commits`, `gesture().commits`) so the count is assertable **without trusting the injected callback** (`§0A` note 12). **The `committed` field of `TerminalResult` is that same record for the call at hand.**

**Item 6 — CAPTURE: ZERO CALLS BEFORE ESTABLISHMENT; AFTER IT, PER-CONTROL OPT-IN, AT MOST ONCE.**

| Case | `capture` value | Source calls for capture | When |
| --- | --- | --- | --- |
| **(a)** | absent / `false` / any falsy (`0`, `''`, `null`, `NaN`, `undefined`) | **ZERO — the capture entry point is never called** | — |
| **(b)** | the consumer opts in (`true`, or any truthy value) | **exactly ONE**, on the gesture's OWN element | **inside `begin`, AFTER the tracking listeners are attached and AFTER the element is known connected** — i.e. **after establishment** |
| **(c)** | opt-in, but the gesture is later `cancel`led | the one capture call remains the gesture's **only** capture call; **no release call is invented** | — |

**The rejected shape, named:** *"no capture at `pointerdown`"* is satisfied because **the capture call cannot happen from the start listener's own turn**: the start listener only calls `begin`, and the capture call inside `begin` is **after** the tracking listeners are open — i.e. **after the interaction is established** (`§0` ruling 2, `H-r9`, `Q2` = (a)). **A reading that forbade capture outright is explicitly NOT this contract** (it would make the fork's own `lostpointercapture` criterion inert and lose the pointer when the cursor leaves the window).

**Item 7 — DISPOSE: the baseline restore, exactly.**

1. **Cancel first, without committing:** an active gesture takes the `cancel` path (**`commit` zero times**, `onCancel` runs once).
2. **Detach everything the session attached:** the three tracking listeners of an in-flight gesture (if the cancel path has not already done so) **and every start listener of every installed control**, each with **exactly one `off(element, type, handler)`** carrying the same three values.
3. **Empty the ledger** and mark the instance **`disposed = true` FOREVER**: `install` returns `false` without a source call, `begin` reports `'disposed'`, every terminal reports `'disposed'` **without detaching or committing**, `stats()` reports `{installed: 0, active: false}`, `gesture()` returns `null`, and **the counters keep their last values** (they are not reset — `§0A` note 8).
4. **A throwing `off` is caught per call:** the remaining detaches still run, `DisposeReport.removed` counts the **successful** detaches, and **`complete: false`** is reported — an honest *"the baseline could not be fully restored"*, never a false restore (`§0A` note 3).
5. **`dispose()` is IDEMPOTENT:** the second call performs **zero** source calls and reports **`{removed: 0, complete: true}`**.
6. **`dispose()` never throws**, whatever the source does; and **the listener baseline it restores is its OWN** — the session claims **nothing** about listeners another party installed (layer anchor 5).

**Item 8 — THE STATE MACHINE, in four states (this is the whole state space).**

| State | Meaning | Reachable by |
| --- | --- | --- |
| **`absent`** | no gesture and no installed control | the instance's initial state; every terminal; a cancel; any refusal |
| **`installed-idle`** | ≥1 control installed, no gesture active | a successful `install`; every terminal; a cancel; a refusal while controls exist |
| **`active`** | exactly ONE gesture in flight | a successful `begin` |
| **`disposed`** | terminal, irreversible | `dispose()` |

**Legal transitions:** `absent → installed-idle → active → installed-idle` (**all four paths: `end`, `reset`, `cancel`, a refused terminal**), and **any** state `→ disposed`. **Illegal, and therefore refused with their codes:** `active → active` (`'busy'`); `disposed → installed-idle` (`'disposed'`); `absent → active` (`'not-installed'`); `active → installed-idle` via an `end`/`reset` carrying a **stale** handle (`'stale'`, and the gesture **stays active** — a refusal never half-terminates). **The instance's counters are monotonic across every transition** (`§0A` note 8).

### 2.4 The value, validity and event rules — how the session treats what it is handed

**Item 1 — the events are OPAQUE, and the session reads NO field of any event.** The session's four handlers take **no argument they use**; `pointerId`, `button`, `buttons`, `isPrimary`, `clientX`/`clientY` and every coordinate are **never read, never compared, never stored** (`§0A` note 4, `§0` ruling 7, `R-8`). **Consequence, stated because it is the magnitude clause in mechanical form: no pointer coordinate reaches the session, so the session cannot know a distance, a delta or a magnitude — and no pass may claim it does.**

**Item 2 — the element is compared BY IDENTITY.** `install`'s ledger is keyed by the element object (identity), never by an id, class, attribute, position or name. **Two structurally identical but distinct objects are two controls; the same object is the same control.** A repeated `install` on the same element is a **no-op returning `false`**, and **the config of the FIRST install stays in force** — *"a second `install` does not double listeners"* is satisfied **structurally** (no second `on` call can happen), which is stronger than a de-dup check.

**Item 3 — one gesture per session; a second `pointerdown` does not start one.** `'busy'` is returned and **nothing changes** (`§2.3` item 3). **A `pointermove` arriving between gestures has no handler attached at all** (the listeners do not exist outside the window), so it is a no-op **by construction, not by a guard** — this is the *"gesture-scoped tracking listeners opened ONLY between start and end"* clause made mechanical.

**Item 4 — the gesture id is monotonic and NEVER reused.** `id` starts at `1`, increments on every successful `begin`, **never resets** (not even after `dispose()`), and **a handle is valid only for the ONE active gesture with that id AND that element identity**. **A stale handle's terminal is refused `'stale'` and does NOT touch the active gesture** — so *"a stale handle's `end` terminates the live gesture"* is the `F-6` fail-state, and it is refusable-by-design rather than a judgement call.

**Item 5 — connectivity: one reading, one failing answer.** At `begin`, **iff** `source.isConnected` is callable, the session calls **`isConnected(element)` exactly once**. **Returning exactly `false` ⇒ `{ok:false, code:'disconnected'}`**, and **no listener is attached, no gesture is created, no commit can occur.** **Any other outcome — `true`, `undefined`, `null`, `0`, `''`, a non-boolean, a throw, or an ABSENT `isConnected` — means "no contrary evidence"** and the gesture proceeds (`§0A` note 9). **This is the one connectivity gate the A-d3 shape allows**, and it is deliberately **narrow**: an absent seam must not make the session inert, and a throwing seam must not crash a gesture.

**Item 6 — an UNUSABLE source is the valid-state degradation, never a throw.** "Unusable" is exact: the source is **not an object** (`undefined`, `null`, a number, a string, a boolean, a function without the members), **or** its `on` is not callable, **or** its `off` is not callable. In that state: `createGestureSession` still returns an instance; `install` returns `false` with **no source call**; `begin` reports **`'not-installed'`**; `gesture()` returns `null`; `stats()` reports zeros; `dispose()` reports `{removed: 0, complete: true}`; **and nothing ever throws.** **A source whose `on` THROWS** behaves the same at that call (`install` returns `false`, **no ledger entry**, no listener) — **the throw is swallowed at the seam, not propagated into the consumer's event handler.** **A source whose `off` throws at `dispose()`** yields the per-call catch of `§2.3` item 7 (4).

**Item 7 — no value is ever validated, coerced, defaulted, rounded or clamped.** `gesture.set(v)` stores **whatever it is given, verbatim**, including `undefined`/`null`/`NaN`/a `Symbol`/a function/an object; the session performs **no comparison, no arithmetic and no `typeof` check on a value**. **This is what keeps every bound, default and axis out of this unit** (`§1` item 2, P-5): **a session that validated a value would be a session holding policy.**

**Item 8 — nothing survives a gesture.** At a terminal the active record is discarded: `active` becomes `false`, `outcome` keeps the terminal's word, `value` keeps the committed value **as a readable record of the gesture that just ended** but is **never read by a later gesture** (a new `begin` sets `value` back to `undefined`), and **no element-keyed value, cache, memo or map exists anywhere.** Only `gestureSeq` (a number) and `commitCount` (a number) persist for the instance's lifetime.

### 2.5 What `U-GUTTER` (`E3`) and `U-RELOCATE` (`E4`) may call — the ONE signature list

**This is the section `§2.1`'s delegate clause serves, and it is stated once so both specs can be written against it:**

1. **`createGestureSession({source, commit}) → GestureSession`** — once per session.
2. **`session.install(element, {capture?, onStart?, onMove?, onEnd?, onCancel?}) → boolean`** — once per control element; `true` only on first install.
3. **`session.begin(element) → BeginResult`** — normally left to the session's own listener; exposed so a test or a consumer-driven start can establish deterministically.
4. **`session.end(element, gesture, value?) → TerminalResult`** — **one commit** (`committed: true`).
5. **`session.reset(element, gesture, value) → TerminalResult`** — **one commit of the SUPPLIED value** (`committed: true`, `outcome: 'reset'`).
6. **`session.cancel(element, gesture?) → TerminalResult`** — **zero commits** (`committed: false`).
7. **`session.dispose() → {removed, complete}`** — the baseline restore; idempotent; permanently inert afterwards.
8. **`session.gesture() → GestureStats | null`** and **`session.stats() → SessionStats`** and **`session.disposed: boolean`** — read-only state, no policy.
9. **Inside the hooks, and only there:** **`gesture.set(value) → GestureHandle`** (total, validating nothing) and the read-only handle fields **`id` · `element` · `active` · `outcome` · `value`**.
10. **Inside `commit`, the two arguments:** **`(gesture: GestureHandle, value: unknown)`** — where **`gesture.outcome`** is the `'end'` vs `'reset'` discriminator and **`value`** is the gesture's final value.
11. **Module-level, if they want the seam directly:** **`installGestureListeners(source, element, onStart)`** / **`detachGestureListeners(source, element, handler)`** / **`POINTER_TYPES`**.

**Nothing else exists.** There is **no** `commit()` method on the session, **no** `setPointerCapture`/`releasePointerCapture` method, **no** `boundsFor`/`axisFor`/`isResizable`/`defaultSizeFor`/`threshold`/`candidatesFor`/`resolveTarget`/`onReveal` parameter, **no** value getter that computes, **no** promise, **no** subscription, **no** store, and **no** options object that could smuggle a census, a selector, a default or a policy predicate in.
