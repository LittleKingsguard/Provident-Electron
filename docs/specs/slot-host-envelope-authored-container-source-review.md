## 0. THE HEADLINE CORRECTION THIS RECORD EXISTS TO CARRY

**The ask's stated blocker is not the blocker.** `src/shared/slot-host.ts`'s per-key container is **not** required to be a caller-created element, and the contract does not say it is. The accepted shape is stated normatively at `docs/specs/slothost.md` **§2.1's container-source clause, item 3**: *"a value that **offers `appendChild`** (**a function-valued `appendChild` member**) … A real DOM element satisfies it; a shim `ShimElement` satisfies it; a plain object offering an `appendChild` function satisfies it; **no predicate such as `instanceof` or a tag check is asserted or admissible**."* The module's own predicates are exactly that one test — `isNodeShaped` (`src/shared/slot-host.ts:167-171`) and `isUsable` (`:199-203`), both `typeof object['appendChild'] === 'function'` — and `obtainContainer` (`:150-159`) accepts a factory return on `isUsable` alone. **A runtime-materialised, framework-authored element satisfies that predicate by construction.** The file header's phrase *"a container manager for CALLER-CREATED nodes"* (`src/shared/slot-host.ts:4`) describes **whose nodes the host places** (the caller's; the host authors no content of its own), **not** what a container may be.

**The real constraint is TEMPORAL, and the ask never states it.** `containerFactory` is invoked **only from `syncContainers()`** (`src/shared/slot-host.ts:305-322`), and only for a declared key whose record still has no container while the injected `container` is **present and usable** (`:307-308`, `:312-318`); its callers are the driven paths — `setNode` (`:504`), `setOrder` (`:582`), `render` (`:612`). **No container is created at construction**, and a key that is never driven with a present, usable mount never gets one. So the consumer's obligation is **ordering**: the value must exist (and offer `appendChild`) **at the moment the host is driven for that key**. That is a caller-side discipline, not a missing mechanism — and it is the sentence the fork needs, stated in this repo's own words in the block `docs/FORKER.md` §4 now carries.

**And the fork's §4 claim that *"a fork-side factory can only return a caller-created element"* is refuted by the fork's own next bullet** (which concedes the alternative is *"a factory that returns a node discovered in the authored tree"*) **and by the clause above.** The capability exists today; what the fork lacks is the foundation's written reading of it, which this disposition supplies.

**Consequence for the answer's shape:** clause 1 is **not** an option, **not** a variant, and **not** a refusal — it is a **recorded derivation plus a fork-facing recipe**, carrying no new vocabulary and no new seam.
