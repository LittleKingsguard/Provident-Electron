## 6. Findings — the ONE measured observation, filed and NOT converted

**`F-1` — THE TIER'S BOOT READ IS LAZY, SO THE ABSOLUTE WORDING "NO FILESYSTEM CALL" IS NOT LITERALLY SATISFIED WHEN A REFUSAL IS THE TIER'S FIRST MEMBER CALL. MEASURED, NOT CONVERTED; NO ROW'S VERDICT IS CHANGED BY IT.**

- **The clauses, quoted.** `docs/specs/tier4-arbitrary-storage.md` **`§2.1` item 5 step 1**: *"**If CLOSED:** no admission, **no filesystem call**, no record advance …"*. And **`§3.3` item 4**: *"**NO FILESYSTEM CALL ON A REFUSAL** (`A5`; `S3` `§0A` item 3): a gate refusal and an admission refusal both precede the staging write, and a refusal touches **no** file."* Against these: **`§2.2` item 4 arm 6** ("the boot never rewrites the file; the constructor writes NO file") and **`§3.1` M-2** (the boot-ingestion read is legal and passes).
- **The measurement (instrument `PROBE-1` of `I-2`, in the transcript; NOT a scenario row, NO expectation asserted).** `PROBE-1 | fsCallsAtConstruction=[] firstMemberCallIsARefusedWrite=>fsCalls=["existsSync","readFileSync"] bootIngestionHappened={"name":"ing","value":{"a":1}} secondRefusalFsCalls=[]`. **Plainly:** the store performs **no filesystem call at construction**; it does its **boot read (`existsSync` + `readFileSync`) LAZILY on the tier's FIRST member call**; and the boot ingestion does happen there (an `entries` member carried by the file is readable immediately afterwards). **So a refusal that happens to be the tier's first member call performs ONE READ of the tier's own file before consulting the gate; every later refusal performs none.**
- **Why this is NOT filed as a FAIL and NOT converted into a pass.** The clauses' *substantive* content — **no commit, no persist, no record advance, no write-class filesystem call, a refusal answered as a VALUE** — holds on **every** drive, including the first-call one (`T4B-41`/`T4B-42`/`T4B-43` are the ordering rows; `T4B-11`/`T4B-12`/`T4B-13` are the refusal rows). What does **not** hold literally is the **absolute phrase** *"no filesystem call"* / *"a refusal touches no file"* in the one first-call case, because the tier's own boot read is deferred rather than done at construction. **The contract nowhere declares WHEN the constructor's file read happens** (it declares that the constructor **writes** no file), so there is **no clause pair that cannot both hold** — which is why this pass reports **`SPEC-AMBIGUOUS = 0`** and files the wording tension here instead. **THE ROW THAT WOULD HAVE CARRIED IT (`T4B-13`) PRIMES THE TIER WITH ONE `get()` FIRST, AND SAYS SO IN ITS OWN OBSERVED TEXT** (`(primed: the tier's lazy boot read is excluded from the count; F-1)`) — the priming is disclosed, not hidden, and the un-primed measurement is printed in the same transcript as `PROBE-1`. **A reader who judges the absolute wording binding should read `T4B-13` as `SPEC-AMBIGUOUS`, not as a pass; nothing in this file prevents that reading, and the evidence for it is on the page.**
