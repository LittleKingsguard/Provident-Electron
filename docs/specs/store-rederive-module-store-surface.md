### 4.3 The event surface

**THE LISTENER BODY, EXACT.** *"`listen(address, body)` registers `body` in the store's listener list in registration order and answers `{address, attached}` … **The body is invoked with NO ARGUMENTS and collects through the store's own `read`** … **the event surface carries no payload, no cause taxonomy, no fan-out policy, no unsubscribe and no amplifier cap**"* (`docs/specs/store-rederive/seams-and-lifecycle.md` §2.11 item 2). **A non-callable `body` is refused `'malformed-listener'` at `L-REGISTRATION` and registers NOTHING** (`§6` `PAR-6`; `docs/specs/store-rederive/store-model.md` §2.14 token 17).

**THE ATTACHMENT MACHINE — `2` STATES AND NOTHING ELSE.** *"`C23`, VERBATIM: *"an event listener can be unattached (waiting for an address that is currently unreachable) or attached to its target node"*. **The two states, and nothing else: `2 = 1 (unattached) + 1 (attached)` ✓.** … **the attachment is BY ADDRESS and follows the address across every re-mint (`C4`): a write elsewhere in the store never detaches a listener; a re-mint of the target node does not detach it**"* (`docs/specs/store-rederive/seams-and-lifecycle.md` §2.11 item 3; `docs/specs/store-rederive/census.md` §4.8). **Attachment is re-evaluated at the END of every SUCCESSFUL write and at the END of a successful `load()`, for EVERY unattached listener; a listener is never attached by a REFUSED write** (`§2.11` item 4).

**WHAT FIRES — THE FAN-OUT'S POSITION CLASSES.** A **successful** write at address `A` fires, **once each, in registration order**, every ATTACHED listener whose address is **(i)** `A` itself · **(ii)** a strict DESCENDANT of `A` · **(iii)** a strict ANCESTOR of `A`. **Listeners on any OTHER address do not fire.** *"**The whole write — mint, tombstone omission, commit, removal of a committed `file` tombstone (`R12`), purge, attachment re-evaluation — is ONE firing; a write never fires a listener twice. A REFUSED write fires NOTHING.**"* **THE FAN-OUT RUNS AFTER THE PURGE AND AFTER THE INSTALL**, i.e. inside step `(8)` of the write's order (`docs/specs/store-rederive/seams-and-lifecycle.md` §2.11 item 5). **THE POSITION CLASSES ARE `3 = 1 (an ancestor) + 1 (the written address) + 1 (a descendant)` ✓** (`docs/specs/store-rederive/census.md` §4.8 — *"The fan-out's three position classes per write: `3 = 1 + 1 + 1`"*; `C4`; `C19`). **A listener whose target is re-minted observes, when it reruns, the NEW node's data — read through the store's own `read`** (`§2.11` item 7(c)).

**THE BODY'S CONTRACT.** **(a) A body MAY read and MAY write through the store's own functions (`C1`); a write issued inside a fan-out is an ORDINARY write whose own fan-out runs to completion before the body returns (depth-first), and the store imposes no depth bound, no coalescing and no deferral** (`§0A` `DD-19`). **(b) A body that THROWS is caught, does not stop the fan-out, and is reported on the write's record as one `listenerErrors` entry; NO rollback follows, because the write landed before the fan-out** (`§0A` `DD-18`). **THE BOOT'S OWN FIRING IS `load()`'s**: the `C24` fan-out fires each listener whose address resolves after the load, **ONCE, in registration order, AFTER the whole load has completed** — *"when the data is fully loaded"* (`§2.11` item 6).

**THE EVENTS THE CONTRACT DOES NOT HAVE, NAMED SO THE SILENCE IS A RESULT.** **No `GraphEvent`, no `cause` taxonomy, no `subtree` opt-in, no amplifier cap, no `events` counter, no `unsubscribe()` and no event payload are this contract's** — *"the landed eight-cause taxonomy, the `subtree` opt-in, the cap and the event count are `STALE PENDING`"* (`docs/specs/store-rederive/seams-and-lifecycle.md` §2.11 item 2, `L [H]` `G-landed-code.md` §2). **A row that drives any of them FAILS.**

## Field 5 — `error shapes` (the closed list of documented fail-states)
