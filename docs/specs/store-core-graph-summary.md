## §1 What this store is

The successor contract specifies **one renderer-realm store**, and it is the amended store architecture in one sentence: **a node-anchor-link graph that IS the source of truth**, with **one flag per node as the ONLY residency carrier**, **a tier token that is a FILTER rather than a part of any name**, **a top-level register projected from the graph with its own caps and a closed refusal set**, **a resolved walk whose every failure arm names its own step**, **two caches with a two-part invalidator set rebuilt at the invalidation site**, **a per-`(logical path, tier)` uniqueness constraint with two declared outcomes**, **a subtree-regeneration transaction that deletes the original only on a census match and declares its failure**, **an eight-arm event surface with the `severed` arm and its subscriber-release rule**, **a stable-JSON translation for the `file`-tier crossing**, and **a non-authoritative, locally-usable export** — and **nothing else** (`§1` items 1/2/3; `§2.1`'s block; `§1` item 10). What it is **not** is stated with equal force: no policy default, no store-side clamp, no consumer vocabulary, no element or geometry read, no MCP surface, no persistence of its own, no UI (`§1` items 2/3/5/6; `§2.2` `P-1`…`P-11`).

**THE FOUR TIERS.**

| Tier | Realm | What it holds (provenance: the decision row `FOUR-TIER-DATA-OWNERSHIP-MODEL` clause (1) and `docs/specs/data-ownership-model-plan.md` `§1.1`) | The rule that decides a value's tier |
| --- | --- | --- | --- |
| **`file`** | **the renderer owns the values; `main` owns the file and the channel** (plan `§2.5`'s revised realm table; the same decision row, clause (8)) | the file-stored persistent cache — config, settings, file tracking (decision row, clause (1)) | a node whose own **`flag` is `'file'`** (`§2.1`'s `GraphNodeFlag`); the write reaches the crossing seam as a stable-JSON translation (`§2.8` item 8) |

**THE ONE-LINE RULE, stated as the contract states it:** the tier a value lives in is **the flag on the node that holds it**, and the **tier token in a name is a FILTER the walk applies to the resolved node's OWN flag** — the first segment is **not a part of the name and not a key** (`§2.3` items 1/2/7; `§2.1`'s `GraphNodeFlag`). **The flag is set ONCE per node generation and is minted by `commit` alone** (`§0A` note 4; `§2.8` items 1/3). **`GraphNodeFlag` is `'temp' | 'mem' | 'file'` — three members — because a `secure`-flagged node never appears in the register or the traversal** (`§2.1`'s block; `§2.4` item 5). **The four tier tokens are `'temp' · 'mem' · 'file' · 'secure'`, EXACTLY four and CASE-SENSITIVE, and they are NOT exported names** (`§2.1` item 4).

### §2.1 The tree invariant

**THE GRAPH IS A TREE BY CONSTRUCTION: every node has EXACTLY ONE parent link (`parentLink`), and NO operation creates a second** — a re-parent is **a DELETE of the anchors plus a MINT of new ones**, which is what makes the cache's anchor-set invalidator well-defined and **makes a cycle UNCONSTRUCTIBLE** (`§2.3` item 4; `§2.2` `P-2`; `§3.3` `I-2`). **Consequence, stated by the contract and repeated here only as its consequence: no visited set and no depth bound is owed**, and **a positive control that cannot express its failing case is VACUOUS and is itself a finding** (`§2.3` item 4; `§2.11` item 3; `§3.2` `F-23`; `§3.4` `R-2`). The invariant is driven by the register row `P-GR-IM-1` (`§5.5.1`).

### §2.2 The two relations the gate-1 record decided

**The gate-1 record `docs/specs/store-node-graph-review.md` states that the amendment's relations "are decided with winners, rewriting operations and falsifiers" (`§2`), and the successor contract turns each into clause rows.** The two that decide the structures above are:

1. **RESIDENCY — the winner is the GRAPH.** The graph is the single residency authority and **the tier collections and the per-tier indexes are VIEWS and INDEXES over it**, never second holders (`§0` ruling 1; `§3.3` `I-1`; `§2.6` item 1's clause that a cache entry stored IN a register row would make the register a second authority and **FAILS `R-5`**). The **rewriting operation** for that relation is the write surface (`§2.8`) plus the register's re-projection (`§2.4` item 3); the **falsifier** is any answer whose residency is read from a view rather than from the graph (`§3.4` `R-5`; `§3.2` `F-6`).
2. **RESOLUTION — the winner is the RESOLVED NODE'S OWN FLAG, and the tier token is a FILTER.** The reason token reported is **the FIRST that applies**, and `H-FLAG` runs AFTER `G-RESOLVE-LEAF`, so a filter miss on a resolvable leaf is `'tier-filter-miss'` and never `'no-such-anchor'` (`§2.3` item 7; `§2.5` item 2; `§0` ruling 3). The **rewriting operation** is the write surface again, with `commit` the only minter of a flag; the **falsifier** is an answer whose `tier`/`flag` disagrees with the resolved node's own flag (`§3.4` `R-6`; `§3.2` `F-4`; `§8` item 1).

**The record's `§7` also fixes the module topology these relations force:** the graph's nodes are **live object references**, so **the graph, the register and the two caches are renderer-realm and `secure` stays main-side** — and **a third module home for the graph, the register or the two caches is NOT taken** (`§0A` note 2; `§1` item 1; `§2.11` item 2).
