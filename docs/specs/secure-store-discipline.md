### 2.1 The module's declared surface — `src/main/security-store.ts` (the principal and ONLY production edit target)

1. **THE EXPORT CENSUS IS UNMOVED IN SHAPE** (`CENSUS`, `L`): the module exports `createSecurityStore` (a function), and the types `SecurityStoreOptions` · `SecurityStore` · `SecurityWriteReceipt`. **`get()`, `set()`, `lastWriteReceipt()` are members of the object the factory returns**, not module exports (`L` `:117-145`). **THIS UNIT ADDS NO EXPORTED NAME** — the admission predicate is module-internal (`T`, `§2.2` item 1), **and a diff that exports a new name, or that renames or removes one of the four, is a FAILING static row** (`§5.6.1` `P-O3-TP-1`'s attempt (2)(b)), because the module's public shape is the tier's whole contract face.
2. **`createSecurityStore(opts: SecurityStoreOptions): SecurityStore` — LANDED, signature and boot posture UNCHANGED** (`L` `:51-61`, `T`, `CONTRACT`): `SecurityStoreOptions = { path: string }`. **THE BOOT READ'S FAIL-STATES ARE UNCHANGED:** a **missing** file → the first-run default `{ token: null, enabled: ['read','dispatch'], maxJournalLength: undefined }`; a **corrupt** file (unparsable bytes) → the SAME default; a path that **IS a directory** → `readFileSync` throws `EISDIR`, the catch answers the SAME default (LIVE-measured, `SC-E-05`) — **NEVER a throw, in any of the three cases.** **The constructor writes NO file** (the boot read is a read; no default is persisted until the first successful `set()`) — **stated because `O-1`'s "live equals durable" is a claim about a record whose bytes EXIST** (`§2.3` item 7(i)/(ii)).
3. **THE WRITE PATH'S ORDER, PINNED IN SIX STEPS** (`T`, `CONTRACT`; `§0A` items 2/3; reading (b)). **`set(patch)` is total over its declared domain, never throws, and performs these steps IN ORDER:**
   1. **ADMISSION** — the representability check of `§2.2` runs over the patch's declared members. **A patch containing any unrepresentable value is REFUSED HERE, whole-patch:** the live record is untouched, no filesystem call is made, the receipt is `{status:'refused', reason:'write-failed'}`, and `set()` returns the **PRE-WRITE** record.
   2. **COERCION / CANDIDATE** — the admitted patch is coerced by the landed `sanitize()` rules into a **CANDIDATE** record (`§2.2` item 3). **The candidate is a LOCAL of the call: `current` is NOT assigned here.** Its members are `token: string | null` · `enabled: string[]` (the five-`VALID_GROUPS`-filtered, deduplicated, order-preserving set) · `maxJournalLength: number | undefined`.
   3. **STAGING + PERSIST** — the candidate is handed to `persist()`, which stages it to `${path}.tmp`, `fsync`s the tmp file, and `renameSync`s it onto the real path. **`persist()` reads NO closure state: it writes the CANDIDATE it is given** (`§0A` item 3).
   4. **THE COMMIT POINT — the successful `renameSync`.** **The record advances (`current = candidate`) HERE and ONLY here** — at the first instant the file's bytes ARE the candidate. **A failure BEFORE this point is a refusal and the record does not move; there is no third possibility** (`§0A` item 2).
   5. **THE DURABILITY STRENGTHENING** — the parent directory is `fsync`'ed. **A failure here is NOT a refusal: the write stays `committed`, the record stays advanced, and live still equals durable** (`§0A` item 2; the rationale is stated there, and the `G3` `NEW-2` re-aim is the precedent).
   6. **THE ANSWER** — `set()` returns `this.get()`, i.e. the record now live: **the candidate's record on a committed write, the PRE-WRITE record on a refusal.** `lastWriteReceipt()` answers the receipt of THIS attempt (never null after an attempt).
4. **`persist()`'s declared shape after this unit** (`T`, `CONTRACT`; `L`'s landed five-step body kept): a **pure-in-its-inputs** closure that takes the candidate record, returns `SecurityWriteReceipt`, and **touches no record state**. **Its fail-states: a failed tmp write · a failed tmp `fsync` · a failed `renameSync`** each answer `{status:'refused', reason:'write-failed'}`; **a successful rename answers `{status:'committed'}` regardless of the directory `fsync`'s outcome** (`§0A` item 2). **Its tmp discipline is UNCHANGED** (`L` `:97-114`): the tmp path is **never parsed as the record**; a stale tmp is overwritten by the next write; a caught failure removes its own tmp **best-effort, with its own failure swallowed** (the `F-11` host fix, unmoved). **The one addition: an ADMISSION refusal never reaches `persist()` at all** (`§2.1` item 3's step 1).
5. **`get(): SecuritySettings` — the DEEP detached record of the live state** (`T`, `CONTRACT`; `§2.5` items 1/2): a fresh copy of `current`, **detached at every depth, cycle-safe, prototype-safe** (`Object.create(null)` + a `seen` map), whose `enabled` array is a fresh array. **The members are exactly `token` · `enabled` · `maxJournalLength`** — no member is added and none is renamed (`L` `src/shared/types.ts:316-323` is the referent type; an optional member may be PRESENT with the value `undefined`, which is the landed shape's own spelling — a consumer treats absent and `undefined` alike).
6. **`lastWriteReceipt(): SecurityWriteReceipt | null` — a FRESH copy per call** (`T`, `CONTRACT`; `§2.5` item 3): `null` **ONLY before the first `set()` attempt** through this store instance. After **every** attempt — committed, admission-refused or persist-refused — it answers a **detached copy** of that attempt's receipt: **the tier's own receipt object is never handed out, and two calls never answer the same object.** The copy is a plain object literal carrying `status` (and `reason` on a refusal) — **the same shape as `SecurityWriteReceipt`**, so a consumer typed to `{ status: 'committed' } | { status: 'refused'; reason: 'write-failed' }` reads it identically.
7. **`SecurityWriteReceipt` — the closed form, UNMOVED** (`T`/`A`, `CONTRACT`; `§0` ruling 7): `{ status: 'committed' } | { status: 'refused'; reason: 'write-failed' }`. **EXACTLY ONE of the two answers after every attempt. There is NO third status, NO third form, NO second reason token, NO `dropped` member, and NO `null` reason.** **`SecurityWriteReceipt` is NOT a member of the store's 16-member refusal union and MUST NOT BECOME one** (`A`: the `D-GATE` row's clause (2), the channel-token precedent).

### 2.2 `O-2` — THE JSON-SAFETY ADMISSION, derived exactly

1. **THE PREDICATE IS A DECLARED, CLOSED, VALUE-PRESERVING RULE — and it is NOT a serialization** (`T`, `CONTRACT`; `A` answer (2): *"a value-preservation test on the write path, never a serialization"*). **Declared name (module-internal, never exported): `representableValue(v: unknown): boolean`.** **A value `v` is REPRESENTABLE iff ALL of the following hold:** **(i)** `v` is one of the four JSON primitive kinds reachable without conversion — `null` · a `boolean` · a **finite `number`** · a `string`; **OR** **(ii)** `v` is an **array or an ordinary object** whose **own enumerable string-keyed members** are each themselves representable, **with NO path revisiting a node it already visited** (the **cycle guard**: an alias encountered twice on one walk is NOT representable), **AND** `typeof v !== 'function'`. **`Symbol`s, `BigInt`s, functions, `Map`, `Set`, `Date` and any other non-plain object are NOT representable (`(i)` fails and `(ii)` fails); `NaN`, `Infinity` and `-Infinity` are NOT representable (`(i)` fails — "finite"); a cyclic structure is NOT representable (the cycle guard); a value carrying an own enumerable `__proto__` **key** is representable (it is an own data property, not a prototype assignment).** **The predicate is TOTAL: it returns a `boolean` for EVERY input and NEVER throws** (`Symbol.iterator`-less values, hostile proxies included — a host object that throws on property access is caught and answers NOT representable).
2. **WHAT THE PREDICATE MAY BE EQUIVALENT TO, AND WHAT IT MAY NOT BE IMPLEMENTED AS** (`T`, `CONTRACT` + `NEGATIVE`): a TestWriter may assert the predicate through the **observable** it defines — **the admitted-and-persisted value equals the value the caller supplied, for the members whose declared form IS the caller's value** — and the red set MAY drive the equivalence `representableValue(v) === (v survives a JSON round trip AND preserves every member)` as a CONTROL. **A JSON round-trip MUST NOT be the implementation of the check as the write path's admission gate**: a round-trip THROWS on cycles and `BigInt`, and the write path is TOTAL (`§2.3` item 1). **A red row that observes the module throwing on a cyclic patch FAILS.**
3. **THE BOUNDARY — WHERE THE DOCUMENTED `sanitize()` COERCION ENDS AND REFUSAL BEGINS** (`T`, `CONTRACT`; THE DERIVED RULE, stated so a test can drive it). **The landed, documented coercions STAY, inside this exact boundary:** for `token` — **a non-empty `string` is the value; `''` and `null` CLEAR it** (`null`); for `maxJournalLength` — **a finite positive `number` is `Math.floor`-ed** (so `50.7` → `50`, and a positive number below `1` floors to `0`, which **is** the declared clear), **`0`, `-0`, any negative number and `null` CLEAR it** (`undefined`); for `groups`/`disable` — **an ARRAY is filtered through the five `VALID_GROUPS` (`read` · `dispatch` · `graph` · `code` · `module`), deduplicated, with current-state order preserved; non-group strings are dropped** (the landed, documented filter). **THE RULE, in one sentence: an unrepresentable value is admissible ONLY as a DECLARED CLEAR of its own member** — i.e. `null` for `token` / `maxJournalLength` and **nothing else** — **and every other unrepresentable value REFUSES THE WHOLE PATCH.** So: `undefined` as a member value is the **absent** marker (the landed semantics: the member keeps its current value — **the write is admitted**); `null` on `token`/`maxJournalLength` is a DECLARED CLEAR (**admitted**); `0`/negatives/`NaN` on `maxJournalLength` are **declared-domain values the sanitize documents as "else cleared"** (**admitted, and they clear** — note `NaN` is unrepresentable but sits in the documented clear arm, which is exactly why it needs this rule rather than the predicate alone); **`Infinity`/`-Infinity`/`BigInt`/a `function`/a `Symbol`/`Map`/`Set`/`Date`/a cyclic object — on ANY declared member, and at ANY depth inside an array — REFUSE the patch.**
4. **WHY THE PREDICATE GOVERNS A WHOLE MEMBER AND NOT MERELY AN ELEMENT** (`T`, `CONTRACT`; the derived consequence, stated because it MOVES a landed behaviour): the landed filter silently DROPS a non-group element from `groups`/`disable` **and answers `committed`** — which is `SECURITY-STORE-COMMITTED-RECEIPT-ON-A-DROPPED-VALUE`'s exact subject. **After this unit: a non-STRING element inside the array is still dropped by the documented filter (admitted); a non-REPRESENTABLE element (`BigInt(7)`, a function, a nested cycle) REFUSES THE WHOLE PATCH** — no `committed` receipt ever answers a value the write discarded. **The distinction is the two axes meeting: the COERCION axis is a declared filter over an admitted domain; the ADMISSION axis is a refusal of a value the tier cannot carry. Where the two meet, §2.2 item 3's rule decides, and this item's example is the derived consequence.**
5. **THE REFUSAL'S TERMS ARE EXACT** (`T`, `CONTRACT`): a refusal at admission is **(a)** whole-patch — **no partial write, no member applied "up to" the bad one**; **(b)** accompanied by the landed refused receipt, never a throw; **(c)** a **no-op on the filesystem** — no `${path}.tmp` is created, no existing file is touched, the real path's record is byte-identical before and after; **(d)** a **no-op on the record** — the LIVE record equals the pre-attempt record member for member; **(e)** answered by `get()` as the PRE-WRITE record.
6. **THE ADMISSION'S SCOPE IS THE DECLARED PATCH AND NOTHING ELSE** (`T`, `NEGATIVE`): the check runs over the **patch object's declared members** (`token`, `groups`, `disable`, `maxJournalLength`). **A patch member OUTSIDE the declared set is not this unit's subject** — the landed posture (an unknown key never reaches the record; the class is filed as `SECURITY-STORE-SILENT-KEY-DROP`, owned by `S2`) is **UNCHANGED, and this unit neither fixes, moves nor claims it** (this item's own scope clause; the class is `S2`'s — `§1.3` item 1). **The record itself is never admitted** — it is the module's own three-member value and is representable by construction.

### 2.3 `O-1` — THE ROLLBACK, and what a refusal leaves behind

1. **THE NEVER-THROWS RULE, RESTATED AS THIS UNIT'S FIRST PROPERTY** (`T`, `CONTRACT`): **`set()` and every other declared member are TOTAL over their declared domains: no patch shape, no filesystem state and no hostile value makes a declared member throw.** The landed exception — `set(null)` throwing a `TypeError` on the member read (`M`, `SC-E-01`'s recorded out-of-domain observation) — **is CLOSED here rather than left as a documented wart**: a non-object patch (including `null`/`undefined`/a primitive/a function) is answered as a **whole-patch refusal** (the receipt of `§2.1` item 7, the record unmoved) and **never throws**. **This is a declared behaviour change with its own red row, and it is required by `O-2`'s own answer (the value cannot be persisted as JSON) plus the totality the receipt's design rests on.**
2. **THE RECORD-ADVANCE INVARIANT** (`T`, `CONTRACT`; `§2.1` item 3's steps 1–5): **the live record advances IFF a save succeeded** — the assignment happens at the commit point and nowhere else. **An implementation that assigns first and rolls back afterwards is FAILING**, even if its observable answers match on the paths a given test drives: the invariant is about the RECORD's state at every instant, and the measured defect (`:138-139`) is exactly that shape. **The red set MAY assert this both ways (the ordered form and the observable form), and a row that only checks the observable form MUST say so.**
3. **WHAT HAPPENS TO THE PREVIOUSLY-PERSISTED FILE ON A REFUSAL** (`T`, `CONTRACT`; `L`'s landed rule kept): the real path's record is **byte-identical** to the pre-write record — for **all four** refusal classes: **(a) admission** (no filesystem call at all), **(b) a failed tmp write**, **(c) a failed tmp `fsync`**, **(d) a failed `renameSync`**. **A TORN FILE AT THE REAL PATH IS IMPOSSIBLE** — the rename is atomic on one filesystem, and the record at the real path is only ever one of the two well-formed records.
4. **THE RESIDUAL `${path}.tmp` ON A REFUSED PATH** (`T`, `CONTRACT`; `L` `:97-114` kept): **(a)** a SUCCESSFUL persist leaves **NO** `${path}.tmp` (the rename consumed it); **(b)** on a CAUGHT failure the staging tmp is removed **best-effort, with its own removal failure SWALLOWED** — a stale tmp that happens to name a DIRECTORY (or a protected path) **must not make `set()` throw** (the landing's `F-11` host fix, re-asserted as this unit's property); **(c)** a stale tmp is **never parsed as the record** and is overwritten by the next write; **(d)** an **ADMISSION** refusal leaves **no new tmp** because it wrote none. **A residual tmp is a tolerated, documented residue; a THROW from the cleanup is FAILING.**
5. **THE EXACT POST-REFUSAL `get()` ANSWER** (`T`, `CONTRACT`): **the PRE-WRITE record, member for member** — same `token` (including `null`), the same `enabled` sequence in the same order, the same `maxJournalLength` (including its absent/`undefined` spelling). **A `get()` that answers any member of the refused patch is FAILING.**
6. **THE RECEIPT'S `status`/`reason` FOR A FAILED SAVE** (`T`, `CONTRACT`; `§2.1` item 7): **`{ status: 'refused', reason: 'write-failed' }`** — the same token at all three filesystem failure points AND at the admission refusal (`§0A` item 1). **On a committed write, `{ status: 'committed' }` and NO `reason` member.** **A refusal whose `reason` differs, is absent, is `undefined` or is a second spelling FAILS.**
7. **WHETHER ANY IN-MEMORY-ONLY STATE MAY EXIST AT ALL** (`T`, `NEGATIVE`; reading (b), clause (1)): **NO.** After a successful write the live record and the file's bytes agree (the post-commit directory `fsync` is a durability strengthening, not a content divergence — `§0A` item 2); **a live record that carries a value the file does not hold IS THE DEFECT THIS UNIT REPAIRS.** **Two declared, non-divergent states are recorded so the rule is not over-read:** **(i) THE PRE-FIRST-WRITE STATE** — a cold store at a path with no file holds the first-run default while no file exists; **this is not a divergence but the absence of a durable state, and the first successful write creates the file** (the `G2` `VERSION-FROM-FIRST-WRITE` shape); **(ii) THE BOOT-FALLBACK STATE** — a corrupt/unreadable file leaves the record at the defaults while the unreadable bytes remain at the path; **the record is then the file's declared reader-answer, and the NEXT successful write replaces the bytes with the record** — the two agree from that point on. **A third state — a record advanced past a refusal — does not exist after this unit.**

### 2.5 `O-3` — THE FULL-SURFACE DEEP CLONE

1. **THE COPY'S DISCIPLINE** (`T`, `CONTRACT`; `§0` ruling 6, `§0A` item 4): **every value a declared member returns is a DETACHED COPY, at every depth** — built with **`Object.create(null)`** as the prototype and a **`seen` map** as the cycle guard; **no aliasing at any depth** (**a holder's mutation of any returned sub-value is invisible to the next read, and to the tier's own state**). **A JSON round-trip is INADMISSIBLE** as the implementation (`§2.2` item 2's reason, and it would throw where this discipline must not).
2. **`get()`'s return is an instance of that discipline** (`T`, `CONTRACT`): the record object **and** its `enabled` array are fresh; the two values are primitives. **Depth-completeness is asserted STRUCTURALLY** (the walk returns no alias of any node it copied) rather than by observing only today's three-member shape — so a later record member that is itself an object is covered by construction.
3. **THE CLOSED READ-SURFACE SET — EVERY MEMBER NAMED** (`T`, `CENSUS`; `§0A` item 5): **`Object.keys(createSecurityStore({path}))` is EXACTLY `["get","lastWriteReceipt","set"]`** — in the landed order, and the census is a TERM (**a fourth value-returning member FAILS; a member REMOVED fails too**). **The three members, and what each returns:** **`get()`** → the deep detached `SecuritySettings` record (`§2.1` item 5) · **`set(patch)`** → `this.get()`, i.e. the same deep detached record (the pre-write one on a refusal) · **`lastWriteReceipt()`** → a fresh detached `SecurityWriteReceipt` copy, or `null` before the first attempt (`§2.1` item 6). **The channel's carriers are outside this census and unedited** (`§0A` item 5).
4. **`lastWriteReceipt()`'s SHAPE AND DETACHMENT, PINNED** (`T`, `CONTRACT`): **(a) the shape** is `{ status: 'committed' }` or `{ status: 'refused', reason: 'write-failed' }` or `null` (pre-first-attempt only) — **no other member, no `undefined` `reason` on a refusal**; **(b) the detachment**: two successive calls **never answer the same object** (`a === b` is `false`), and **a holder's mutation of the returned object is INVISIBLE to the tier and to the next call** — the mutated copy must not be able to rewrite the tier's answer to its last write (the measured `SC-E-07` defect, closed). **THE TIER'S OWN RECEIPT OBJECT IS NEVER HANDED OUT.**
5. **THE CENSUS'S POSITIVE CONTROL** (`T`, `NEGATIVE`-class control, `CENSUS`): the detachment detector is **NOT vacuous** — driven against a subject that hands out ONE shared object, it **fires**; against a subject that returns a fresh copy, it **does not**. **The control is a term of the register row that carries it** (`§5.6.1` `P-O3-IM-2`'s attempt (8)), because a detector that cannot fail proves nothing.
