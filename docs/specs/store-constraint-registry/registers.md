#### 2.1.1 The constraint register and its entry

```
type ConstraintName = string                     // the CALLER-SUPPLIED unique name (registers.md §2.2)
type ConstraintTest  = 'held' | 'refused' | 'repaired' | 'unavailable'

interface ConstraintEntry {                      // ONE record per distinct name, for the instance's lifetime
  readonly name:            ConstraintName
  readonly address:         Address              // the READ ADDRESS the constraint is assigned to
  readonly position:        number               // its index within the carrier's OWN registration list
  readonly hasRepair:       boolean              // whether a repair function was registered with it
  readonly lastResult:      ConstraintTest       // the outcome of its MOST RECENT test in this store instance
  readonly repairsInvoked:  number               // ≥ 0; how many times the store invoked ITS repair across the instance's writes
}

type ConstraintRegister = ReadonlyArray<ConstraintEntry>   // ORDERED ascending by (address, position)
```

1. **THE JOIN KEY IS THE CALLER-SUPPLIED NAME, OVER THE FUNCTION IDENTITY, AND THE STORE MINTS NO ID.** `UK-1`/`UK-2`/`UK-3` rule *"the caller's unique-name spelling over the function identity; no store-minted id"* (`A docs/specs/store-constraint-registry-review.md ⟦ CLOSING RULINGS AND VERDICT 2026-10-13 ⟧ (a)`, delta table; the row's own status `defined` at `A4 docs/specs/u-store-constraint-registry-adoption-dossier.md · A-6`, carried at that document's `⟦ CLOSING DELTA ⟧`). **A store-minted id is STRUCK** (`A3 docs/specs/store-rederive/contract.md §0A` `DD-15`: the registration seam carries no withdrawal verb and declares no constraint id). **Therefore `name` IS the entry's identity, and `===` governs what a DUPLICATE does** — see `docs/specs/store-constraint-registry/registers.md §2.2`. `(A UK-1 · A UK-2 · A UK-3 · A3 docs/specs/store-rederive/contract.md §0A · CONTRACT + NEGATIVE)`
2. **THE ADDRESS IS THE READ ADDRESS THE CONSTRAINT IS ASSIGNED TO — the directive's own clause (*"assigned to a read address and a unique name"*, quoted at `A docs/specs/store-constraint-registry-review.md`, head block) read with the landed seam.** **`address` is the SAME argument the landed `constrain(address, registration)` takes, with the same domain (`A3 docs/specs/store-rederive/parameter-semantics.md §6` `PAR-1`) and the same carrier (`A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10` item 2: the LINK at the address, or — at a 1-segment address — the REGISTER ENTRY).** **This layer adds NO address form, NO key domain and NO reserved spelling**: `PAR-1`'s row is cited, never re-declared. `(A3 docs/specs/store-rederive/parameter-semantics.md §6 · A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10 · CONTRACT)`
3. **THE ENTRY'S LIFETIME IS THE STORE INSTANCE'S, EXACTLY AS A REGISTRATION'S IS.** `ConstraintRegister` is a **table of the names this instance has been asked to test**, held in the store's closure beside the existing `register` (which holds the registrations themselves); **no arm removes a row of it** — the removal rule of this unit is the **commit register's** (`docs/specs/store-constraint-registry/lifecycle.md §2.3`), and the two tables do NOT share one lifetime rule. **A row disappears only with the instance** (`A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10` item 2: a registration stands for the store instance's lifetime). `(A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10 · T · CONTRACT + NEGATIVE)`
4. **`lastResult` IS `4`-VALUED AND ITS FOUR VALUES ARE THE FOUR THINGS A TEST CAN DO — terms `4 = 1 (held) + 1 (refused) + 1 (repaired) + 1 (unavailable)` ✓.** **`held`** = the constraint answered `{ok:true}`; **`refused`** = it answered `{ok:false, message}`; **`repaired`** = it answered `{repair:true}` and the store invoked its repair; **`unavailable`** = it answered `{repair:true}` and the store could not invoke a repair — **because none is registered, or because this registration's repair has already run in that write** (`A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10` items 5/9(a): the two arms of reason token `13`'s availability reading). **A fifth value, an ordinal, a timestamp or a store-authored verdict is OUTSIDE this type and FAILS.** `(A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10 · T · CONTRACT + NEGATIVE + CENSUS)`
5. **`repairsInvoked` EXISTS BECAUSE THE DIRECTIVE'S OWN FAILURE ARM NAMES REPETITION (*"if a constraint function fails more than once (ex. its repair was overwritten by another repair)"*, quoted at `A docs/specs/store-constraint-registry-review.md`, head block), and the store's own loop-breaker is token 20 (`A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10` item 11 · `A3 docs/specs/store-rederive/store-model.md §2.14` item 5).** **The count is RECORDED, NEVER CONSULTED: nothing in this layer reads `repairsInvoked` to decide anything.** **The store's repetition bound is the ARCHITECT's and it is PER REGISTRATION PER WRITE** (*"a registration's `repair` runs AT MOST ONCE per write"*, `A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10` item 9) — **this layer declares no round limit, no repetition policy and no second bound** (`A R4`: the store owns no policy over module code). **A row in which `repairsInvoked` gates a decision FAILS.** `(A R4 · A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10 · CONTRACT + NEGATIVE)`

#### 2.1.2 The commit register and its pending entry

```
interface PendingResult {                        // ONE row per TEST DRIVEN for this commit, in test order
  readonly name:     ConstraintName
  readonly position: number                      // 0-based index of the driven registration within the write's set S
  readonly pass:     number                      // the 1-based constraint-phase pass that produced it
  readonly result:   ConstraintTest
  readonly messages: StoreMessage[]              // ≥ 0 entries; the error messages recorded FOR this commit (verbatim where a module authored them)
}

interface PendingEntry {                         // ONE row per commit that has not yet passed all its constraints
  readonly recordedOpId:  string                 // §2.4 — the ADOPTED identifier, RECORDED and NEVER used to reverse
  readonly address:       Address                // the write's address
  readonly tier:          Tier                   // the tier the write targeted ('file' for every secure write)
  readonly results:       ReadonlyArray<PendingResult>   // ORDERED by (pass, position), ascending
  readonly repaired:      boolean                // whether ANY repair was invoked for this commit
  readonly messages:      StoreMessage[]         // the SAME entries the write's own record carries, in the same order — one channel, one log
}

type CommitRegister = ReadonlyArray<PendingEntry>          // ORDERED ascending by recordedOpId's emission ordinal (registers.md §2.1.2)
```

6. **THE PENDING SET IS KEYED BY THE RECORDED `op.opId`, AND THE KEY IS A RECORD — NEVER AN UNDO HANDLE.** `D-1` verbatim: *"The state machine governs — the op id is a record, not an undo handle"* (`A docs/specs/store-constraint-registry-review.md ⟦ CLOSING RULINGS AND VERDICT 2026-10-13 ⟧ (a)`). **Consequently: this layer performs NO undo-by-id, holds NO pending-commit window, and declares NO arm in which a recorded id is handed to a reversal verb.** **The `journalLength` window and the two unavailable-undo statuses are `not-adopted-in-this-layer`** (`A4 docs/specs/u-store-constraint-registry-adoption-dossier.md · A-3` · `· A-4`, carried at that document's `⟦ CLOSING DELTA ⟧`; `D-3`: this fraction holds **no** pending-commit window to bound). **A row in which a recorded id is passed to a reversal, or in which a window is bounded, FAILS.** `(A D-1 · A4 docs/specs/u-store-constraint-registry-adoption-dossier.md · A-3 · A-4 · CONTRACT + NEGATIVE)`
7. **`results` AND `messages` CARRY THE TWO THINGS THE DIRECTIVE NAMES — *"the ops and error messages associated with them"* (quoted at `A docs/specs/store-constraint-registry-review.md`, head block).** **THE ERROR-MESSAGE CHANNEL IS NOT A SECOND CHANNEL:** `messages` on the pending entry **is the write's own returned message list, by identity of content and order** — `A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10` item 10's ONE channel with three authorships (`'constraint'` · `'repair'` · `'store'`), whose entries the store stamps. **This layer authors no entry, mints no `source` value and adds no member to `StoreMessage`** (whose members are `6 = 2 + 4`, `A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10` item 10). `(A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10 · CONTRACT + NEGATIVE)`
8. **THE ORDER OF `results` IS THE ORDER OF THE TESTS, AND IT IS EXACTLY `(pass, position)` ASCENDING** — the same lemma the message list carries (`A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10` item 10: *"the list is ordered by `pass` ASCENDING and, WITHIN one pass, by `position` ASCENDING"*). **A `results` row that is not in that order FAILS**; **two rows with the same `(pass, position)` are ONE row, updated in place** (a registration is tested once per pass). `(A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10 · T · CONTRACT + NEGATIVE)`
9. **`pass` IS READ FROM THE PHASE, NOT MINTED HERE**, and **`position` is the written set `S`'s index — NOT `ConstraintRecord.position`**, whose referent is the addressed list's own index (`A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10` item 10: *"`position` here is NOT `ConstraintRecord.position` … the two are distinct referents"*; `ConstraintEntry.position` at `docs/specs/store-constraint-registry/registers.md §2.1.1` is of the SECOND kind). **Three `position` referents stand in this contract, and this clause is where all three are named: the written set's index (this row), the registration list's index (`ConstraintEntry.position`), and the returned `ConstraintRecord.position` (the landed one, unchanged).** `(A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10 · A3 docs/specs/store-rederive/store-model.md §2.1 · T · CONTRACT)`
10. **`CommitRegister` IS THE PENDING SET AND NOTHING ELSE: an entry leaves it when the commit passes all its constraints (`docs/specs/store-constraint-registry/lifecycle.md §2.3` item 2), and the constraint register's rows are NOT its rows.** **The two tables are read together only by the returned report (`docs/specs/store-constraint-registry/registers.md §2.5`), never merged.** `(A docs/specs/store-constraint-registry-review.md §3 · T · CONTRACT + NEGATIVE)`

#### 2.1.3 The two-register split — one register per graph (`UK-5`)

14. **THE `secure` ENFORCEMENT SITE IS NOT THIS UNIT'S.** The landed residual `R-5` names it as `F3`'s (`A3 docs/specs/store-constraint-registry-uk9-f3-elaboration.md §1`: *"the `secure` enforcement site (`F3`'s own residual `R-5`)"*). **This unit declares the SPLIT only; it declares no gate, no reader, no realm and no enforcement arm.** `(A3 docs/specs/store-constraint-registry-uk9-f3-elaboration.md §1 · T · CONTRACT + NEGATIVE)`

### 2.5 The returned report — the ONE observation channel (`UK-9` = (a); the funnel is `F3`'s)

```
interface RegisterReport {                       // the two registers AS THEY STAND at the reporting call's return
  readonly constraint:  ConstraintRegister       // the constraint register — registers.md §2.1.1
  readonly pending:     CommitRegister           // the commit register    — registers.md §2.1.2
  readonly evicted:     ReadonlyArray<string>    // ≥ 0 entries; the recordedOpIds removed by the EVICTION arm in THIS call
  readonly pendingBound: number                  // the declared resident bound — lifecycle.md §2.3 item 4; constant for the instance
}
```

1. **THIS REPORT IS THE WHOLE OBSERVATION SURFACE, AND THE CHOICE IS FORCED — stated so no reader invents a fifth shape.** **The store's state is closure-private and no function returns a node, an anchor, a link, a register entry or any live internal record** (`A3 docs/specs/store-rederive/store-model.md §2.1` item 1: *"the surface is a member table of functions, the store's state is closure-private"*; `A3 docs/specs/store-rederive/store-model.md §2.3` item 4, `C1`/`C2`). **AND THIS LAYER MAY NOT MINT A NEW STORE-LEVEL VERB OR A NEW SURFACE FUNCTION** (`A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10` item 2's `DD-15`; `A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.13` item 4's `R7`; `A4 docs/specs/u-store-constraint-registry-adoption-dossier.md · A-2`, closed `not-adopted-in-this-layer` by `D-1`; `A docs/specs/store-constraint-registry-review.md §3`'s `NOT IN IT` cell as re-grained by `§2(d)`). **THE REPORT IS THEREFORE CARRIED ON THE RETURN VALUE OF THE CALL THAT PRODUCED THE STATE — no new verb, no new member on the store's declared surface, and no `__peek`-class debug door** (the landed debug door is not a contract surface: `A3 docs/specs/store-rederive/store-model.md §2.1`'s surface table carries the ten functions and no door). `(A3 docs/specs/store-rederive/store-model.md §2.1 · A4 docs/specs/u-store-constraint-registry-adoption-dossier.md · A-2 · A D-1 · CONTRACT + NEGATIVE)`
2. **THE SHAPE THE REPORT IS CARRIED ON, DECLARED EXACTLY.** **The unit's declared edit is the `runWrite` edge** (`A3 docs/specs/store-constraint-registry-uk9-f3-elaboration.md §5`; `A docs/specs/store-constraint-registry-review.md ⟦ CLOSING RULINGS AND VERDICT 2026-10-13 ⟧ (a)` `UK-9`), **where the landed funnel returns `WriteRecord` — a `'committed'` arm carrying `status` plus SEVEN payload members, or the closed five-member `Refusal`** (`A3 docs/specs/store-rederive/store-model.md §2.1`; measured in the landed module at `S src/renderer/store.ts:166-178` and `:146-153`). **THE DECLARED CARRIAGE IS A RECORD PAIR ON THE SAME EDGE:**

3. **THE REPORT'S FOUR MEMBERS, AND WHAT EACH OBSERVES:**
   - **`constraint`** — **the constraint register, ordered ascending by `(address, position)`.** It carries **one row per distinct name asked for**, so its length is **the number of distinct names this instance has tested**, `≥ 0`.
   - **`pending`** — **the commit register, ordered ascending by `recordedOpId`'s emission ordinal.** Its length is **`≥ 0` and `≤ pendingBound`**, and it carries **exactly the commits that have not yet passed all their constraints** (`docs/specs/store-constraint-registry/lifecycle.md §2.3` item 2).
   - **`evicted`** — **`≥ 0` recorded ids, in eviction order, for the entries the BOUND removed in this call only** (`docs/specs/store-constraint-registry/lifecycle.md §2.3` item 4). **It is the silence-breaker: an eviction is never unobservable. It is empty on every call that evicted nothing — which is every call in which the pending set did not exceed the bound.**
   - **`pendingBound`** — **the declared constant `64`, reported so no reader infers it** (`docs/specs/store-constraint-registry/lifecycle.md §2.3` item 4). **A row that asserts a bound other than the reported one FAILS; a row that recomputes the bound instead of reading it is not a row of this contract's observable set.**

4. **WHEN THE REPORT IS TAKEN: at the reporting call's OWN RETURN, AFTER the landing work and AFTER the refusal's own register writes — so it shows the state the call left, never the state it began in.** **Consequences, each checkable: a refusing call's report shows its OWN entry resident; a passing call's report does not; a call that evicted shows the removals on `evicted` and not in `pending`.** `(T · CONTRACT)`
