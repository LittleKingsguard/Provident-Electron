### 2.2 The constraint register's join key and its duplicate arm (`UK-1` · `UK-2`+`UK-3` · `D-2`)

1. **THE CALLER SUPPLIES THE NAME, AND `UK-1` RULED THE DUPLICATE ARM HERSELF: *"the caller supplies it; duplicates replace in place; no new token"*** (`A docs/specs/store-constraint-registry-review.md ⟦ ARCHITECT ANSWERS 2026-10-13 ⟧ (a)`; `⟦ CLOSING RULINGS AND VERDICT 2026-10-13 ⟧ (a)`; row `A-6` `defined` at `A4 docs/specs/u-store-constraint-registry-adoption-dossier.md · A-6`). **Consequences, each a rule:**
   - **(a) A DUPLICATE REPLACES THAT ENTRY IN PLACE. It is NOT appended, NOT refused, and it mints NO token and NO second entry.** `ConstraintRegister` therefore carries **at most ONE row per distinct `name`** — and a row that carries two rows of the same `name` FAILS.
   - **(b) THERE IS NO REFUSAL ARM FOR A DUPLICATE NAME.** The closed `22`-member reason union keeps its membership and its ordinals (`A3 docs/specs/store-rederive/store-model.md §2.14` item 1: `22 = 6 + 2 + 2 + 6 + 2 + 2 + 1 + 1`, *"a row that mints a token outside these twenty-two FAILS"*), **and the message list's `4 = 2 + 2` appender doors are untouched** (`A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10` item 10). **A row that refuses a duplicate, or that mints a reason token or an appender door for it, FAILS.**
   - **(c) THE REPLACEMENT IS TOTAL OR IT DOES NOT HAPPEN: a `constrain` call that replaces an entry leaves exactly ONE row for that name, carrying the NEW call's arguments.** `(A UK-1 · CONTRACT + NEGATIVE)`
2. **`===` GOVERNS THE REPLACEMENT, ON THE FUNCTION IDENTITY, AND THIS IS THE LANDED READING RE-CITED — NOT A SECOND MECHANISM.** `A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10` item 2: *"A re-registration carrying the SAME `constraint` function identity (`===`) at the SAME address REPLACES that entry in place (idempotent wiring); otherwise it APPENDS."* **`UK-2`+`UK-3` rule *"the caller's unique-name spelling over the function identity"* (`A docs/specs/store-constraint-registry-review.md ⟦ CLOSING RULINGS AND VERDICT 2026-10-13 ⟧ (a)`), and the derived red set row that shows what the landed reading looks like is `C-3` (`S tests/store-rederive.test.ts` `:1847`, measured: *"a re-registration with the SAME function identity REPLACES that entry in place"*).** **THE ORDER OF THE TWO TESTS IS THEREFORE FIXED, AND THE TWO ARMS ARE DISTINCT:**
   - **(a) SAME `name` ⇒ REPLACE THAT ENTRY IN PLACE** — **whatever function identity it carries, at whatever address** (`UK-1`). The name is the register's join key, so a name match alone decides.
   - **(b) DIFFERENT `name`, SAME function identity (`===`) at the SAME address ⇒ REPLACE that entry in place** — the landed idempotent-wiring arm, unchanged.
   - **(c) DIFFERENT `name`, DIFFERENT function identity ⇒ APPEND**, in registration order (the landed seam's own rule).
   **A row in which two names hold one function and the second call APPENDS instead of replacing FAILS; a row in which a repeated name leaves the OLD row standing FAILS.** `(A UK-2 · A UK-3 · A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10 · S tests/store-rederive.test.ts · CONTRACT + NEGATIVE)`
3. **THE CALLER'S ARGUMENT RECORD ADDS ONE OPTIONAL MEMBER AND CHANGES NO OTHER — and the omission is the landed form.** `A3 docs/specs/store-rederive/store-model.md §2.1` declares `type ConstraintRegistration = { constraint: ConstraintFn; repair?: RepairFn }`; **this layer's declared request record is**
   ```
   interface ConstrainRequest {                 // the registration seam's argument, plus this layer's name
     readonly constraint: ConstraintFn          // REQUIRED — the landed member, unchanged
     readonly repair?:    RepairFn              // OPTIONAL — the landed member, unchanged
     readonly name?:      ConstraintName        // OPTIONAL — THIS LAYER's declared addition
   }
   ```
   **The landed two members keep their declared domains and their cited parameter rows (`A3 docs/specs/store-rederive/parameter-semantics.md §6` `PAR-7` (the registration record) and `PAR-8` (the two callables)); this contract adds the parameter row `PAR-15` for `name` at `docs/specs/store-constraint-registry/parameter-semantics.md §6`.**
   **AND WHEN `name` IS ABSENT, THE CONTRACT DECLARES A NAMED DEFAULT RATHER THAN A SECOND PATH — `DECLARED`: `name` absent ⇒ this layer takes the name from the store's own registration order, spelled `constraint-<position>`, where `<position>` is the entry's own `ConstraintEntry.position` in the carrier's list (a caller can therefore always predict and always observe it: the returned record carries it).** **The default is a DEFAULT and not a second identity: it is still a caller-facing `name` in the register, it is still replaced in place under item 1(a) by a later call spelling the same name, and the store still mints no id.** `(A UK-1 · A3 docs/specs/store-rederive/store-model.md §2.1 · A3 docs/specs/store-rederive/parameter-semantics.md §6 · T · DECLARED-DEFAULT)`
4. **THE PRICED ALTERNATIVE, NOT TAKEN: `name` REQUIRED, an absent name refused.** **Refused because it would open a refusal arm with no token to carry it** — `'malformed-constraint'` (`A3 docs/specs/store-rederive/store-model.md §2.14` item 18) is scoped to *"`registration.constraint` — or a present `registration.repair` — is not a function"*, and widening it is a re-grain of `PAR-8`'s own row, which `UK-1`'s *"no new token"* does not license. **Reversible at this spec gate; reversal moves `PAR-15`'s OUTSIDE cell and this item, and nothing else.** `(A UK-1 · A3 docs/specs/store-rederive/parameter-semantics.md §6 · T · DECLARED-DEFAULT)`
5. **WHAT THE NAME IS NOT: NO MECHANISM, NO STORE VOCABULARY, NO CONSTRAINT DATA.** `docs/decisions.md:34` (`CONSTRAINTS-ARE-PASSED-FUNCTIONS`) rules *"CONSTRAINTS ARE CODE FEATURES, NOT DATA: no install path, no runtime table mutation"* (`A2 docs/decisions.md · CONSTRAINTS-ARE-PASSED-FUNCTIONS`, cited at `A4 docs/specs/u-store-constraint-registry-adoption-dossier.md §2` `X-4`, which states this layer's residual as a duty: *"the unit must declare that the registry mints no store-owned vocabulary and adds no install path"* — **this item discharges it**). **THEREFORE, stated at its widest: this layer declares NO install path, NO constraint-kind table, NO store-owned constraint vocabulary (no built-in constraint, no kind name, no reserved constraint spelling), NO store-owned round limit, and NO constraint data of any kind.** **`name` is a DECLARATION KEY over a caller-supplied function, exactly as the frozen artifact's own `constraintId` reading puts it** — *"`constraintId` is an id into the CALLER-SUPPLIED CONSTRAINT SET — a declaration key never a mechanism word"* (`S docs/specs/store-core-module-store-core-graph-surface.md:355`, measured, quoted at `A4 docs/specs/u-store-constraint-registry-adoption-dossier.md §2` `X-4`). **A row in which the constraint register carries a constraint's DATA, KIND, MATCHED SET, EVALUATION POINT or REPAIR ACTION FAILS.** `(A2 docs/decisions.md · CONSTRAINTS-ARE-PASSED-FUNCTIONS · A4 docs/specs/u-store-constraint-registry-adoption-dossier.md · X-4 · S docs/specs/store-core-module-store-core-graph-surface.md · CONTRACT + NEGATIVE)`
6. **THE NAME DOMAIN, AND ITS ONE OUTSIDE ARM.** **IN: any `string`, including the empty string — the store declares no alphabet, no escaping, no reserved spelling and no uniqueness check beyond the table itself** (the same permissiveness the address segments get at `A3 docs/specs/store-rederive/parameter-semantics.md §6` `PAR-1`: *"any string is a legal segment (no alphabet, no escaping, no reserved spelling)"*). **`name` present but not a string ⇒ a data condition, and this unit's rule is the repo's: a RETURNED record, never a throw** (`A3 docs/specs/store-rederive/store-model.md §2.1` item 4: *"EVERY FUNCTION IS TOTAL: it answers one of its declared records and NEVER THROWS for a data condition"*). **The declared answer is the landed `'malformed-constraint'` refusal at step `L-REGISTRATION`** (`A3 docs/specs/store-rederive/store-model.md §2.14` item 18 — the arm already governs a malformed registration record, and `name` is a member of that record) — **this contract mints NO token for it and widens no union.** **`name` of any string value is IN, and the string `''` is a legal name that joins and replaces like any other.** `(A3 docs/specs/store-rederive/store-model.md §2.1 · A3 docs/specs/store-rederive/parameter-semantics.md §6 · A UK-1 · CONTRACT + NEGATIVE)`
7. **THE NAME DOES NOT REACH THE EVALUATION RECORD, THE PHASE OR THE EVENT SURFACE.** **`ConstraintEvaluation`'s members are the landed `4` plus `notes`, and this layer adds none** (`A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10` items 4/10; `A3 docs/specs/store-rederive/contract.md §0A` `DD-1`); **the phase's order is `S`'s order, not the name's** (`A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10` item 3); **and the constraint register is not delivered to a listener body** (`A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.11` item 2: the body is invoked with no arguments and collects through the store's own `read`). `(A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10 · A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.11 · CONTRACT + NEGATIVE)`

### 2.3 The register's lifetime, its state machine and its declared bounds (`UK-6`+`UK-7` · `UK-8` · `D-1`)

1. **THE ENTRY'S CREATION POINT IS THE LANDED EVALUATION POINT, AND THERE IS NO OTHER — `UK-2`(change) ruled *"each write/commit — the landed evaluation point"*** (`A docs/specs/store-constraint-registry-review.md ⟦ ARCHITECT ANSWERS 2026-10-13 ⟧ (a)`). **READ AT ITS SOURCE: the phase runs inside the write's OWN step `(5)`, before step `(6)`'s install and before step `(7)`'s commit** (`A3 docs/specs/store-rederive/write-and-read.md §2.5` item 1's nine steps, measured: `(5)` *"evaluate the constraints in order (`H-CONSTRAINT`)"*, `(6)` *"mint the prospective state in memory"*, `(7)` *"WRITE THE FILE (`I-SAVE`)"*, `(8)` *"INSTALL the new state, run the purge (`C19`), fire the listeners"*). **THEREFORE, EACH A RULE:**
   - **(a) THE REGISTER IS FED INSIDE ONE WRITE, AND THE PASS BOUND IS THE LANDED ONE.** The phase terminates at `≤ |S| + 1` passes where `S` is the write's evaluated set, because a registration's repair runs at most once per write (`A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10` items 8–9; `A3 docs/specs/store-rederive/contract.md §0A` `DD-22`). **This layer declares NO second bound and NO round limit** (`A R4`).
   - **(b) THERE IS NO POST-HOC WINDOW AND NO DETACHED RE-CHECK.** No arm re-tests a commit after the write returns; no timer, sweep, TTL, clock, idle pass or GC hook exists (`A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.13` item 4: *"NO store-level verb drops it, and NO timer, idle sweep, TTL, clock or GC hook exists"*). **A row in which a pending entry's constraints are re-tested outside a write call FAILS.**
   - **(c) THE PURGE AND THE FAN-OUT ARE NOT A DRIVER.** Step `(8)` runs AFTER the phase has terminated, so **a purge does not add a `PendingResult` row and a listener's own write is an ORDINARY WRITE with its own entry** (`A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.11` item 7(a): a write inside a fan-out is an ordinary write whose own fan-out runs to completion, depth-first). **Terms: `1` driver (the write's step `(5)`) — steps `(6)`, `(7)`, `(8)` and the fan-out add none ✓.** `(A UK-2(change) · A3 docs/specs/store-rederive/write-and-read.md §2.5 · A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10 · CONTRACT + NEGATIVE + CENSUS)`
2. **A COMMIT THAT PASSES ALL ITS CONSTRAINTS LEAVES THE REGISTER IN ITS OWN CALL — the directive's own clause, *"if a commit passes all constraints, then the commit is removed from the registry"* (quoted at `A docs/specs/store-constraint-registry-review.md`, head block), READ WITH `UK-8`'s ruling.** **The exit is a rule over the SAME call: the entry is added when the first test of that write begins, its `results` grow as the phase walks `S`, and the write that reaches the end of its phase with EVERY driven result `held` OR `repaired` and NO refusal carries NO pending entry on its returned report.** **`repairsInvoked` and `repaired` do not exempt a commit from this rule** — a repaired write is a successful write (`A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10` item 6(a): it lands, it is committed if its tier is `file`, ONE commit, and the purge runs after it). **A row in which a write whose every constraint held leaves a pending entry FAILS.** `(A UK-8 · A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10 · CONTRACT + NEGATIVE)`
3. **REMOVAL ON REVERSAL — `UK-8` ruled *"removal on reversal, plus a declared resident bound"*** (`A docs/specs/store-constraint-registry-review.md ⟦ ARCHITECT ANSWERS 2026-10-13 ⟧ (a)`; `⟦ CLOSING RULINGS AND VERDICT 2026-10-13 ⟧ (b)`: *"`A-3` (`journalLength`) and `A-4` … pin an undo WINDOW … `D-1` rules no undo-by-id is ever performed — a violation lands nothing, the pre-call snapshot stands — so no window and no unavailable-undo state exists in this layer to bound or to answer"*; row `A-5` `defined` at `A4 docs/specs/u-store-constraint-registry-adoption-dossier.md · A-5`). **WHAT A REVERSAL IS, HERE, IS THE STATE CONSEQUENCE OF `UK-6`+`UK-7` — *"a state consequence — the pre-call snapshot restore, refusal before anything lands"*** (`A docs/specs/store-constraint-registry-review.md ⟦ ARCHITECT ANSWERS 2026-10-13 ⟧ (a)`), **read with `D-1`'s own words: *"The state machine governs — the op id is a record, not an undo handle"*.**
   **THE REMOVAL ARMS, ENUMERATED EXACTLY — `2` arms, terms `2 = 1 (a later landing write at the entry's address and tier) + 1 (the session's end)` ✓, AND NOTHING ELSE:**
   - **(i) A LATER WRITE THAT LANDS AT THE PENDING ENTRY'S OWN `address` AND `tier`.** The landed store **discards and re-mints the addressed instance** (`A3 docs/specs/store-rederive/write-and-read.md §2.5` items 3–4: `C19`'s total overwrite *"an existing instance at `(address, tier)` is discarded and re-minted"* and `C4`'s *"every node on the walk … is re-minted too"*) — **so the commit the entry recorded has been reversed and replaced as a STATE CONSEQUENCE, the pre-call state it left is gone, and the entry is removed.** **The removal is observed on the LATER write's returned report: the reversed entry is absent, and (if the later commit itself drove constraints) the later commit's own entry is present.** **A `mem`/`temp`-tier entry follows the SAME rule at its own tier: the two arms that drop a `temp` instance are a later write at the same address at a tier of equal or lower persistence and the session's end** (`A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.13` item 4; `A3 docs/specs/store-rederive/write-and-read.md §2.5` item 4) — **and a purge of a lower tier by a higher-tier write is that same landing write** (`A3 docs/specs/store-rederive/write-and-read.md §2.5` item 4's purge sets, terms `0 + 1 + 2 = 3` ✓).
   - **(ii) THE SESSION'S END.** The session IS the lifetime of the store instance, so an app closure AND a realm/window reload lose the whole register with the closure (`A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.13` items 1–2; `A3 docs/specs/store-rederive/contract.md §0A` `DD-7`).
   **NO OTHER ARM REMOVES AN ENTRY: no withdrawal verb, no `clear`/`sweep`/`sever`-class verb, no explicit undo, no explicit "forget" call, no timer, no sweep and no TTL** (`A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.10` item 2's `DD-15` ban; `A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.13` item 4's `R7` ban; the withdrawal verb is STRUCK at `A4 docs/specs/u-store-constraint-registry-adoption-dossier.md §4` `UK-8`'s candidate (b): *"a withdrawal verb (struck by `DD-15`)"*). **A row in which an entry is removed by a verb, a policy, a clock or a count alone FAILS.** `(A UK-6 · A UK-7 · A UK-8 · A D-1 · A3 docs/specs/store-rederive/write-and-read.md §2.5 · A3 docs/specs/store-rederive/seams-and-lifecycle.md §2.13 · CONTRACT + NEGATIVE + CENSUS)`
4. **THE DECLARED RESIDENT BOUND — *"DECLARE that bound (a stated `≤ n` with its terms)"*, and here it is.** **`pendingBound` is a DECLARED CONSTANT of this layer, `DECLARED: pendingBound = 64`; the pending register holds `≤ pendingBound` entries at every return point of every call, and the value is reported on every returned report so no reader infers it (`docs/specs/store-constraint-registry/registers.md §2.5` item 3).** **TERMS, PRINTED: `1` bound, `1` table it bounds (the commit register), `64` its value, `0` timers, `0` TTLs, `0` clocks ✓.**
   **WHAT THE BOUND IS AND IS NOT.** It is a **COUNT over one store-instance's own pending table**, and it is **this layer's own residency cap on a table this layer holds** — **NOT a policy over module code** (`A R4`), **NOT an undo window** (that is `A-3`'s reading, closed `not-adopted-in-this-layer`), **NOT `journalLength` under another name** (`docs/specs/store-constraint-registry/registers.md §2.4` item 4), and **NOT a bound on how long a commit stays pending** — nothing here is measured in time.
   **THE EVICTION ARM, STATED SO IT IS TOTAL AND OBSERVABLE: when a write that drives a constraint would leave MORE than `pendingBound` pending entries, the OLDEST entry — by its `recordedOpId`'s emission ordinal (`docs/specs/store-constraint-registry/registers.md §2.1.2`) — is REMOVED, and it is removed FOR THE SAME REASON arm (i) carries: it has been reversed.** **The arm is observable in one call: with a bound of `2`, a sequence of three failing writes leaves exactly `2` entries, and the third write's returned report NAMES the removed entry's `recordedOpId` on its `evicted` list (`docs/specs/store-constraint-registry/registers.md §2.5` item 3) — so the removal is never silent.** **A row in which eviction is silent, or in which the pending set exceeds the bound, FAILS.**
   **PRICED ALTERNATIVE, NOT TAKEN: a construction input `pendingBound?: number` read ONCE at construction.** **Refused here, and the ground is the `PAR-14` seam precedent's own condition** (`A3 docs/specs/store-rederive/parameter-semantics.md §6` `PAR-14`): **a construction seam is owed where the declared domain has an OUTSIDE arm that must answer a record — and here the OUTSIDE value's declared answer would be a REFUSAL at construction, i.e. a store that cannot be built, which is a wiring failure this layer must not invent, since the landed posture is that *"the package's two fields are carried on a RETURNED record — no throw enters this layer's channel and `P-4` is untouched, not relaxed"*** (`A4 docs/specs/u-store-constraint-registry-adoption-dossier.md §2` `X-1`'s disposition, cited). **Reversible at this spec gate; reversal adds one row to `docs/specs/store-constraint-registry/parameter-semantics.md §6` and moves this item's value cell, and it moves no property-register row's term.** `(A UK-8 · A R4 · A3 docs/specs/store-rederive/parameter-semantics.md §6 · A2 docs/decisions.md · REGISTER-ATTEMPT-TOTALS-PRINT-THEIR-TERMS · T · DECLARED-DEFAULT + CENSUS)`
