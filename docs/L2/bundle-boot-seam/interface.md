|---|---|---|
| `ASM-L2-1` | the arrangement is decided on the **artifact and what a boot publishes** — the two readiness lines and the instance's own profile file — and not on a transport handshake or a rendered surface, neither of which this seat drives; the window and the renderer themselves do run (P-10, P-11's renderer-ready line) | asserting a booting app from a control that never reached `whenReady` (P-9's wrong inference), and the unbounded-wait reading `F-2` punished (`strata/.strata/returns/security-store-storeroom-l2-examination.json`) |
| `ASM-L2-2` | main is emitted **ESM** and named by the `main` field (§1) | each of §3's arms, rejected on its own measurement rather than on taste |
| `ASM-L2-3` | the artifact's **name** carries its module system (P-7), so a misnamed artifact is a loud load failure | a `.cjs` name for ESM bytes, which the loader rejects at parse |
| `ASM-L2-4` | E-5 is a **cross-module exception of three sites** — the two harness script constants (`scripts/electron-spawn.mjs:75`, `scripts/electron-ui.mjs:131`) and the ui leg's matcher (`tests/ui-leg-contract.test.ts`), **one name each**, written by `harness` — and A-5 verifies it rather than trusting it | leaving the legs naming the retired path, which reddens both Electron legs for a filename |
| `ASM-L2-5` | the preload stays **CJS** (§1) | an ESM preload, which needs `sandbox: false` in the `webPreferences` block of `new BrowserWindow(...)` in `src/main/main.ts` — a renderer-security change no boot seam may buy |
| `ASM-L2-6` | the two sibling bundles and the renderer bundle are **untouched**, and measured so **in §1's table** — neither sibling emission carries an addon-path reference, a reading cited from there rather than re-taken here | rebuilding them “for consistency”, which buys nothing and puts two other modules' boot rows at risk (L1 §6 B-7) |
| `ASM-L2-7` | **the package is external**, so the app resolves it from `node_modules` at run time (P-11..P-13; landed at both manifest sites) | inlining it (§3, first and second arms), which relocates its derivation or binds the artifact to the building host |
| `ASM-L2-8` | a **packaged** app must ship `node_modules/provident-storeroom` and its platform optional dependency, with the native addon loadable from disk (P-13, P-15) | assuming the artifact is self-contained, which it was never measured to be — and this baseline ships **no packaging config at all** (no builder/forge key or dependency in the tree), so the packaging leg is the forker's and is stated, not tested, here |
