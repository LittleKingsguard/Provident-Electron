## 0. Scope

This module is the app's **authored data**: one provident envelope tree, the node ids other modules resolve through the graph, and one example of the caller seams the gutter affordance takes. ## 3. The tabs row's three declarations — hook, prototype, `keyField` (D-182)

| Declaration | Where it stands | What it settles, and what it costs to omit |
|---|---|---|
| **the hook** | **on the tabs-row node**: `hooks: ['tab-rows']` with `hooksKind: {'tab-rows': 'placement'}` — the name is `TABS_ROWS_ID`, so the node and its hook share one string | a placement mint on an UNDECLARED hook is **REFUSED** (`hook-kind-mismatch`): `D-179`'s measured contract, and the envelope's first `hooks` block in this tree (`D-178` §1's `(i)`, established at `D-179`) |
| **the prototype** | an authored **def-root `component`** node named by `TABS_ROW_PROTOTYPE_ID`, resolvable BY NAME | without it the mint answers **`rows-prototype-unresolved`** (`D-179`, `D-182` measurement 1): a row has no shape |
| **`keyField`** | **the mint op's operand** (`S-4`'s), naming the member each row datum carries its tab id under — **the tab record's own row key** (`D-158`, `store-tabs-record`'s shape), not a name invented here. **THE DATUM'S SOURCE IS `['tabs'].rows`, NOT `order`**: `order` is the record's `readonly string[]` and supplies the row SET and its sequence, while the member `keyField` names and the label the row paint reads live on the record's rows (`preload.ts`'s `tabs.read`) | `D-182` measurement 4/5: an UNKEYED re-mint **replaces and churns** the row ids (`node-6/7 → node-8/9`), so every paint on a row must be redone per delivery; a KEYED one mints nothing and keeps both ids **stable**. **So it is REQUIRED, not an optimisation** (`D-179`, `D-182`) |

**A mint is `D-182`'s five measurements, and this module's obligation is the shape they rest on**: the op is `{kind:'rows-mint', target: TABS_ROWS_ID, hookName: TABS_ROWS_ID, mintKind: 'placement', prototypeName: TABS_ROW_PROTOTYPE_ID, placementName, keyField, rows}`, **one row per `['tabs'].order` entry in `order`'s sequence, each row's DATUM the record's own row for that id**; a re-mint **replaces, never duplicates**; the row node carries the tab id under `keyField`'s member so the attach turn reads it off the row itself. **The refusals are the ENGINE's and `producing-runtime`'s** — `hook-kind-mismatch`, `rows-prototype-unresolved`, `rows-placement-name-missing`, `rows-shape-invalid` — and the turn that sends the op is `renderer-wiring`'s, not this module's (L1 §5).

## 4. The `css` this design authors, and the two it must not

| Block | Authored here | Why, and what reads it |
|---|---|---|
| **the drag region** (`C-10`, `D-183`) | the top-bar `-webkit-app-region: drag`; the tabs row `no-drag`; **the strip the native controls occupy NOTHING** | with `titleBarStyle:'hidden'` the OS title bar is gone, so **without the first item the window cannot be moved at all**; `no-drag` is what keeps the minted rows clickable, and it only means anything on a node INSIDE the dragging bar (§2); the third is a deliberate ABSENCE — the platform owns its own region (`D-179`) |
| **the arrangement** (`D-176`'s charter) | on the ROOT and the container: **the top-bar, then the `top` zone spanning the full width, then the row of `left` + stage + `right`, then the `bottom` zone spanning the full width** — the charter's own nesting, with the sidebars stretching BETWEEN the two full-width zones | it is `css` on containers and NOTHING stores it; **the record's `display` is the ZONE's participation and is the paint's**, so `display` is never authored on a zone beside it (`D-185`, `D-129`) |
| **the zones' own scrolling** (`D-187`) | each zone's `overflow` on its ARRANGEMENT axis — `overflow-x` on `top`/`bottom`, `overflow-y` on `left`/`right` | a zone with several panes exceeds its own extent along that axis, so **the ZONE scrolls the arrangement while each PANE scrolls its content — the same `overflow` at two depths**, which is how *"all scroll internally"* and this rule stop contradicting each other (`D-187`) |
| **the pane's fill/adjust/scroll pairs** (`D-186`, `D-187`) | a pane in `top`/`bottom` **FILLS the zone's height, ADJUSTS width, `overflow-x`**; a pane in `left`/`right` **FILLS the width, ADJUSTS height, `overflow-y`**; `pane-a` (no `zone`, the stage) keeps today's behaviour | the invariant is ONE sentence — a pane fills the axis its zone fixes, adjusts the other and scrolls the one it adjusts — and the menus pane's horizontally-scrollable strip **falls out of it rather than needing a special case** (`D-187`) |
| **the stage** | `overflow` and the flex remainder only — **NO dimension** | the stage is derived, so a figure here would be the second authority `D-185` refuses |
| **NOT authored: the top zone's height (or a sidebar's width), and no zone's `display`** | nothing | they come from **`['zones'].size`/`display` through the paint** (`D-185`; `D-184`'s pane-owned height is superseded BY POINTER, and an authored figure beside the record is `D-129`'s defect). **AND THIS ROW IS ALSO THE WHOLE ANSWER TO *"WHAT RENDERS BEFORE A WRITER SPEAKS"*** (`view-record` rev 16's `OWED-4`, `D-174`): a zone stating no `size` gets **no dimension written**, so the authored `css` (placement and `overflow`, never a figure) is all that stands and the stage takes the remainder — **an authored fallback here would be a figure right on one boot and false on the next**, which is the class `D-174` deleted from the gutter's read-out |
| **NOT authored: any figure with a record behind it** | nothing | **`['panes']`'s `width` and `height` are the record's for BOTH panes** (`D-189`: `pane-a`'s `height` the migrated `100`, its `width` a repair's `DEFAULT_PANE_SIZE`; `pane-menus`'s `width` its adjustable member and its `height` the memory), and `DEFAULT_PANE_SIZE`/`DEFAULT_PANE_BOUNDS` are `src/shared/view-shape.ts`'s (rev 3 §4, `D-87`/`D-151`) |

**AND NONE OF THESE IS MEASURABLE, COUNTED AS A PAIR** (`D-178` §4, `D-183` §6): `overflow` and `-webkit-app-region` are layout and compositor behaviour, invisible to a rendered-HTML read, so no gating row asserts them and the app's movability and its internal scrolling are **recorded gaps, not implied guarantees**. What IS measurable stays: a `css.style` write appears in the markup, which is how the zone and pane dimensions are read at all (`D-185`, `D-187`, `renderer-wiring` `OWED-3`).

## 5. What this page may NOT claim

- **The node list is STATIC.** The tree's node type carries `type`, `content`, a LITERAL `children[]`, `props`, `handlers`, `css`, `derived` and `hooks` — and **no `each`, no `repeat`, no per-node binding to a store family and no conditional** (`D-177`). So one row per `['tabs'].order` entry is a MINT (§3) and the eighteen items are a static enumeration, which is legal as nodes.
- **`derived` carries `props` and `css` ONLY — never `content`** (`D-177`). **No label, no name and no figure is COMPUTED in this envelope**: each is authored (the static strings §2a lists) or painted by a turn, or reads EMPTY until one does (`D-129`, `D-164`).
- **Placement routing does not work post-bootstrap** (`D-182`, upstream-owned under `D-5`/`D-52`): a mint dirties only its target, the container is never recompiled, and path-compiling double-emits. **So NO node may be declared as "placed into a zone at runtime"** — every pane and every row is authored where it belongs, a minted row renders wherever its TARGET lives, and the `zone` member is DECLARATIVE (`C-8`, `D-182`).

## 6. What the module does not do

- **No store, no tier, no address, no constraint, no repair** — the crossings are the other modules' (D-65, D-87).
- **No write**: every `handlers` entry is a body STRING the graph dispatches; a body can `apply` node props and **can reach no record and no main-process command**, which is why the mint, the attach, the paint and the menus turns are the wiring's (`D-177`, `D-181`).
- **No graph, runtime or element access** — it imports no `src/renderer/`, so no member resolves a node or reads the DOM at construction (D-3, D-117).
- **No authored fallback anywhere**: the receipt carrier authors nothing, so what stands between a boot and the first answer is EMPTY and never a figure (`D-127`, `D-129`).
