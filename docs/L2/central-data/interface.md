## 2a. The per-node readout — the shape, `kind`, the one shadowed name, and the arms that gain nothing

- **THE READOUT'S SHAPE IS A TOTAL FUNCTION OF NODE KIND, AND `_tier` IS THAT NODE'S OWN TIER** (§2's `DataReadNode`; D-134, `the declaration`'s `TieredNode`): an OBJECT node is `{_tier, …members}` with its members INLINE and no `value` wrapper, an ARRAY node is `{_tier, value:[…]}` dense and in index order, a LEAF is `{_tier, value:<the literal>}` — so EVERY node of the answer is an OBJECT, never a primitive and never a bare array, and `_tier` is ONE of `file`/`mem`/`temp` and never a set, because `TierSet` is the ARGUMENT's type and the answer never carries one. An object's or an array's is its own ANCHOR tier and a leaf's is the tier of the version the read selected, so ONE call can return nodes standing at DIFFERENT tiers — which is why `D-133`'s per-call echo is superseded BY POINTER before it was built, and why the register node's own token is measured and never pinned here (D-133, D-46, D-101).
- **`kind` IS DERIVED FROM THAT NODE, AND THE ANSWER'S MEMBER SET IS UNMOVED** (D-134, D-53): `'row'` exactly when the answer's node is a LEAF — its key set `{_tier, value}` with `value` a primitive, the address `readLiteral` used to have to be asked for — and `'branch'` otherwise, covering an object node, an array node and the empty register node `{_tier}`; so the two words describe ONE node and no arm carries a tier beside it, a fourth arm member naming one being the superseded echo wearing a name.
- **THE ONE SHADOWED NAME, AS A RULE AND NOT AS A DISCOVERY** (`the declaration`, `readTiered`'s docblock; D-134): a member a caller STORED at the name `_tier` is NOT DELIVERED by this verb — the minted field wins on the node that carries it — while the store's own `read` at the same address still answers the stored value, so nothing is destroyed and the truth stays reachable; nothing under `src/` writes a `_tier` today, and an answer handed back to `data.write` is stored as ORDINARY DATA, `_tier` members and `value` wrappers included, because the readout is the read's compilation and does not round-trip.
- **WHICH ARMS GAIN NOTHING, AND WHY** (L1 `ASM-3`; D-133, D-107, D-134): `absent` and every `DataLedger` arm — an absence states a fact about the caller's own argument, and a refusal that never reached a store has no node to name, the same reading that keeps `log` off those arms; the other four verbs, a receipt naming no node; `list`, which is §1's prefix reading of PATHS and declares no `tier`, so its walk stays on `read`/`readLiteral` and a per-path tier is nobody's answer here; and **the cold register arm** — `read {path:[]}` where the profile's name does not stand — which answers `{status:'absent', path:[]}`, because no store answered it and this module spells no tier of its own to mint a node with (D-80, D-101).

## 3. The receipt vocabulary — closed, and a value

Every answer is one of the statuses `committed`, `read`, `absent`, `refused`; no fifth, and no answer is a throw (D-11).
