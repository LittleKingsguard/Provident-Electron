## 0. Scope

This document fixes the view record's I/O surface: its addresses and their tiers, the `view` bridge member and its routes, `read()`'s answer, the declared roots the `data.*` surface's guard consumes, this module's refusal vocabulary, and the hunks L4 must land. ## 1. The families the record holds now — four roots, and the one that left

| Address | Tier | Holds |
|---|---|---|
| `['panes']` | `file` | one member per pane id, each `{ size: number; bounds: { min: number; max: number } }` (D-87) |
| `['zones']` | `mem` | one member per **DECLARED** zone id — the closed set is `DECLARED_ZONE_IDS`, **one** id at this head — each carrying any of an opaque `slot`, a `distance`, a `size`, a `display`, and each created as an EMPTY record by the creation repair (D-91, D-151) |
| `['theme']` | `file` | **one whole record** `{ token?, attribute?, declaration: { name?, value, removal } }` — the setting, the caller-held attribute name, and the declaration the mechanism computed for that pair (D-97, D-98) |
| `['drag']` | `temp` | **the gesture's in-process reading**: one member per pane id, each `{ size }` — the placement alone — present while a drag is in process and ABSENT once it ends (D-132) |

**THE ZONE FAMILY'S ID DOMAIN IS CLOSED, AND IT CLOSES BECAUSE A LEAF WRITE NEEDS IT TO** (D-151, D-139). The store creates no parent — measured at this node, where a leaf write over a family holding no such key answers `AddressNotFound` and even an EMPTY family is not enough — so `['zones', id]` must be GUARANTEED to stand for every id the route is handed, and an open id set cannot guarantee anything; that premise is exactly what `D-139`'s judgement of `composeZones` assumed and what `D-151` makes true. So the set is one constant, `DECLARED_ZONE_IDS` in `src/shared/view-shape.ts`, derived from `DEFAULT_ZONE_ID`'s single spelling of the one id the app addresses — `DEFAULT_PANE_ID`'s pattern, so that the fallback and the declared set cannot drift — and **a caller naming an id outside it is REFUSED** (§5's `undeclared-zone`) **rather than silently creating a zone**; the family's own judge refuses a VALUE that names one, so the closure holds at the address as well as at the route.

**THE DRAG FAMILY IS DECLARED AND UNPAIRED, AND THAT IS LAWFUL RATHER THAN AN OMISSION** — the one place this module's usual "address + tier + declaration + root entry" shape is narrower. It carries an address, a tier constant and a `viewDeclaredRoots()` entry, and **no `viewConstraintDeclarations` row**: no invariant holds the family, and a repair whose subject is "no drag has started" would mint a placeholder for data whose ABSENCE is the product (D-132, D-101). **What the entry buys is the family's ONE judgement, and it is the tier's**: a `file` or `mem` write at this root is refused `declared-tier`, naming the root and the tier it is declared at, ahead of any store verb (D-101).

**IT IS ALSO THE ONLY FAMILY WITH NEITHER A COMPOSER NOR A BOOT DATUM.** A nested write creates no parent (measured), but `['drag']` IS a root holding one member and no sibling, so the first move writes the root itself and nothing is left to preserve — the member merge `composePanes` exists for has no subject here (D-135, `D-138`). Its durable half is `['panes']`' own value, written by the release's unchanged `commitPane` (D-132).

**THE `['focus']` ROOT LEFT WHOLE AT rev 6 AND STAYS GONE** (D-142): its address constant and `FOCUS_TIER`, the `focus-must-stand` declaration and its body, its `viewDeclaredRoots()` entry, `commitFocus`/`composeMirror`/`mirrorFrom`, the surface's route, its channel constant and `ipcMain.handle` site, both lockstep halves, the client's route and the renderer's carrier left in one edit. **What it held was a SECOND SPELLING of a fact `['tabs']` already owns** (`D-140`, `D-141`, `D-76`), and it was `mem`, the one tier that persists nothing (D-141); what replaced it is no route of this module's (D-142).

**FOUR ROOTS AND NOT ONE VALUE, MEASURED** (D-87's ground, re-driven at each later root): a nested write does not create its parent (`AddressNotFound` over a fresh store), so one root would need a declaration minting a parent branch; and a root written at `file` answers its descendants at `file` and `TierNotFound` at `mem` or `temp`, so one value could not carry a `mem` family and a `temp` one at their own tiers. The tab record's one-root pattern is applied **once per tier**, not once per family (D-63, D-87).

## 2. The bridge member and its seven routes

`window.provident` carries **one** top-level member, `view`, declared in `src/main/preload.ts` and re-declared in `src/renderer/secure-panels.ts`'s `declare global` as the **same text** — the lockstep pair a battery compares member for member (D-87, D-112). A route here is never a path: a caller names a pane id, a zone id, an appearance act or a placement, and never an address or a tier (D-87, D-91, D-132). Every channel constant is single-sourced in `src/shared/view-channels.ts`, because a name spelled in the handler and again in the preload is a rename that half-lands (D-87).

**WHAT THE TWO DRAG ROUTES WRITE, AND BOTH SIDES IN ONE EDIT** (D-14, D-112, D-132): `commitDrag(pane, { size })` → `store.write(['drag'], 'temp', { [pane]: { size } })`, ONE whole value the caller formatted and no composer touches (`D-136`, `D-135`); `clearDrag()` → `store.delete(['drag'], 'temp')`, a DELETE at the family's own tier and never a placeholder, so the address answers `absent` once the gesture is over. Each lands on both sides in the SAME edit — the channel constant, the surface's route, the `ipcMain.handle` site, the preload's member with `secure-panels`' lockstep half, and the client's method — because a client method whose channel has no handler is a method that writes nowhere, the class `D-132` refused to half-land.

**AND THE ZONE ROUTE'S MEMBERS ARE LEAVES — THE ORDER AND THE PARTIAL ARM ARE THIS SECTION'S, NOT THE IMPLEMENTATION'S** (D-151): every supplied member is written at its OWN leaf in the shape's own order, so a leaf write cannot drop a sibling member and no copy of the family is taken at all; **a refusal after the first leaf LEAVES THE FIRST STANDING, and that is ADMISSIBLE** — every supplied member is judged before the first store verb, a landed leaf is a state the pair admits (a zone carrying any subset of the four members is the family's measured shape), and the answer names the leaf that refused; **and a zone supplying NO member writes nothing and answers `committed`**, the declared empty record being the state the act names. Atomicity would need one write at `['zones', id]`, which **REPLACES** the zone whole (measured) and would therefore have to merge over a copy of what stands — the composer `D-151` removes.

**AND `view.commitFocus` STAYS ABSENT FROM BOTH SIDES** (D-14, D-142): the constant `IPC_VIEW_FOCUS_COMMIT`, the `ipcMain.handle` site, the record's and the surface's `commitFocus`, both lockstep halves and the client's `routeOf(member, 'commitFocus')` turn left together and nothing replaces them.

## 3. `view.read()` — three families, and the drag reading is not one of them

`read()` answers `{ status: 'committed'; panes; zones; theme; source: { panes; zones; theme } }`: the three families' admitted values and one `source` word per family, `'record'` or `'default'` (D-142, D-84, D-87). **NO `focus` MEMBER AND NO `drag` MEMBER STANDS ON EITHER SIDE OF THE WIRE**: the mirror left with its family (D-142), and the temp reading is read WHERE THE TIERS ARE READ — `provident.data.read({path: ['drag']})`, whose node carries its own `_tier` (D-133, D-144) — so a consumer asks the readout, and `dragOf` is the member `D-133` refused to mint. **`source` NAMES A REAL DIFFERENCE** — the record answered, or the declared default did — which keeps a placeholder from being substituted at a read and called a record (D-84). **`read()` IS TOTAL AND CARRIES NO REFUSED ARM**, a measurement and not an omission: a read that misses answers the family's declared arm and a refused read is caught at the same place (D-84). It carries **no `repaired` member** either, because no route of this module can produce the difference such a member would report (D-70, D-105).

`paneGeometryIn(panes, id)` and `zoneIn(zones, id)` are the **pure** derivations over one reading, so a client needs no second store verb and no route stands without an answer site (D-87, D-91). Their missing arms differ, and the difference is the measurement: a pane the family does not name answers the measured default geometry, a zone answers `null` (D-91). **AND AFTER THE CLOSED DOMAIN `null` NAMES A DIFFERENT FACT** (D-151): a DECLARED zone always stands, so a zone nothing has written yet answers a MEMBERLESS record while `null` answers for an id the record does not declare — the two states are told apart by the derivation itself, with no new member on the reading.

## 4. The declared roots — four, and the same-edit rule stated as a rule

`viewDeclaredRoots()` publishes each root **paired with the tier its own declaration writes at** — `['panes']` `file`, `['zones']` `mem`, `['theme']` `file`, `['drag']` `temp` — built from the same address and tier constants the batch uses, so a family that moved tier would move here without a word (D-101, D-97, D-98, D-132). Its caller is the `data.*` surface's declared-tier guard (`src/main/data/surface.ts`'s `declaredTierLedger`, fed by `src/main/main.ts`'s `declaredRoots: [...tabsDeclaredRoots(), ...viewDeclaredRoots()]`), which admits a write or a delete at a declared root only at that family's tier and refuses `declared-tier` otherwise, ahead of any store verb (D-101). **AND THE SUBSCRIPTION IS NOT THIS SECTION'S SUBJECT — §7's IS**: what stands here is each ROOT and the tier its entry is declared at; the array that hears them, one listener per root and **TIER-BLIND** because the store's own `listen` binds an address and never a tier, is §7's bullet *The subscription and the push*, stated there — cited here, never re-derived (D-137; `src/main/view-record/index.ts`'s `subscribe`; `docs/L1/pane-drag-temp.md` §3).

**THE ENTRY AND ITS FAMILY ARE ONE HUNK — a RULE, not tidying** (D-101, D-132, D-142): an entry outliving its family hands the guard a tier for a root that is gone, and an address with no entry leaves the family shadowable at another tier. The rule binds the drag pair exactly as it bound the deleted focus pair, and it is why the entry joins the address and tier constants in the SAME edit rather than after them. **AND AN ENTRY WITHOUT A PAIR IS LAWFUL, BECAUSE THE GUARD DOES NOT READ THE BATCH**: `declaredTierLedger` keys on the roots it is HANDED, so the `temp` root is guarded while nothing is declared at it — the whole of what a `temp` family needs (D-101, D-132). **WHAT THE GUARD DOES AT AN UNDECLARED ROOT: IT ADMITS THE WRITE**, because a path no crossing declares reaches the store verb and is judged by the store's own constraints and nothing else (D-101, D-105).

## 5. The refusal vocabulary — two tokens per paired family, the third the closed zone domain mints, and none of its own for the drag

| Token | Family | Names |
|---|---|---|
| `malformed-pane` | panes · drag | no pane id, or no plain geometry record (D-87) |
| `malformed-geometry` | panes · drag | a **supplied** `size` that is not a finite non-negative number, or a `bounds` pair that is not two finite numbers with `min ≤ max` (D-87) |
| `malformed-zone` | zones | no zone id, or no plain zone record (D-91) |
| `malformed-zone-member` | zones | a supplied `size` that is not finite and non-negative, a `distance` that is not finite, a `display` that is not a string, or a `slot` the crossing's boundary would refuse (D-91, D-105) |
| `undeclared-zone` | zones | a **well-formed** zone id that this record does not declare — the closed set is `DECLARED_ZONE_IDS` (D-151); the id's DOMAIN is judged before the payload, so an undeclared id answers this and never `malformed-zone` |
| `malformed-theme` | theme | no setting token that can be an appearance setting (a string; the EMPTY one is the absence the mechanism declares), or no attribute name a caller could compose a write from (D-97) |
| `stale-theme` | theme | the carried declaration is not the one the mechanism would produce for the setting and attribute it carries — **the CONSTRAINT's arm, never a route's** (D-97) |

## 6. Boot data: the file, or a repair — and for the drag root, nothing

**Clause 1 and clause 3 of the convention, per address** (D-82 via D-87). `panes-must-stand` at `['panes']` refuses a value that is not a plain record and repairs it to the measured default family as ONE whole legal value; on a fresh profile the file carries it when the constructor returns (D-86) and the next boot is handed it (D-87). `zones-must-stand` is that shape at `mem` with one fact of its own: **its placeholder is EVERY DECLARED ZONE ID WITH AN EMPTY RECORD — `{'zone-1': {}}` — and not the family carrying no member at all**, which SUPERSEDES `D-91`'s sentence *"the family that names no zone"* **BY POINTER AND NOT BY REWORDING** (`D-151` (a), `D-46`); `{}` is admissible as a zone (`zoneOf(id, {})` answers `{id}`, so `zoneNodeAdmits` admits it), and that is what makes the creation write lawful and the declared node — the one a leaf write needs beneath it — STAND. **AND THE PAIR'S EXISTENCE ARM IS THE FAMILY ROOT'S**: absence is answered at `['zones']` alone, while a write at or below a zone id is judged at its own node and never repaired, because the context's value is the act's landed value and an ancestor's pair is asked (`guide §7.6`, `D-56`) — so a leaf write hands the body a scalar, and a body that read that as absence would write the placeholder over the family inside a commit that answers `committed` (D-105, D-151). **A `mem` value can never come from a file** (D-84), so the zone family is re-minted at **every** boot and not one byte of it reaches the profile (D-91). `theme-must-stand` carries the two arms of the appearance record: no plain record repaired to the placeholder, and **STALENESS** — a record that stands whose carried declaration is not the mechanism's answer for the pair it carries — repaired from the record's OWN two members (D-97, D-98), its comparison STRUCTURAL because the crossing normalises key order. Its tier is `file` on the durability ruling (D-98).

**THE DRAG ROOT HAS NO BOOT DATUM AND NO REPAIR**: it is `temp`, the tier that persists nowhere, so a fresh profile carries no `drag` key, a restart cannot resurrect a gesture, and a read over an absent drag root is the absence a gesture that has not started IS (D-132, D-84). **NOTHING IS DERIVED AT A READ, AND A BOOT APPLIES NOTHING**: the one stated `fill()` adopts and only a delivery applies, so a `file` record standing at boot is DATA (D-98).

## 9. The write's receipt — `writeOutcome()`, and the finding it stands unread under

`writeOutcome(): ViewWriteOutcome | null` answers **THE LAST WRITE'S DECLARED ANSWER, OR `null` BEFORE THE FIRST** — this module's second hold beside `reading()`, read at `src/renderer/view-client.ts`'s `ViewClient.writeOutcome` and the factory's `lastWrite`. It exists because **A SENT WRITE ANSWERS NOTHING IN ITS CALLER'S TURN**: `ViewWriteStatement` is `{ status: 'sent' }` or `{ status: 'absent' }` — which route was handed the write, or that no route was — and **never the commit's outcome**, so the receipt is the ONLY place a REFUSED `commitPane`, `commitZones`, `commitTheme` or `commitDrag` becomes a reading instead of a silent no-op (§2, §5). A write that answers `absent` records NOTHING, because it was never sent: the receipt is the sent write's, and an absent write leaves the standing one exactly as it stood.

| Member | Carries | Cite |
|---|---|---|
| `route` | **the FAMILY the receipt belongs to** — `'pane'`, `'zone'` or `'theme'` for the three commits, `'drag'` for the gesture's pair | `D-132` |
| `answer` | the crossing's answer AS IT ARRIVED, `unknown` because a bridge is a TRUST BOUNDARY and a shape is checked before it is read | §2 |
| `status` | `'committed'`, `'refused'` or `'unread'` — the three arms `outcomeOf()` mints, and no fourth | §2, §5 |
| `reason`, `message` | the refusal's own two, VERBATIM, and `null` on every arm that has neither | §5 |

**`'drag'` IS THE FOURTH WORD BECAUSE THE `temp` FAMILY HAS NO MEMBER ON A READING**: `read()` answers the three families (§3) and the gesture's reading is read where the tiers are read, so nothing in the shape says which family a receipt belongs to — the route word is the only way a caller tells a drag's receipt from the three commits' (`D-132`, `D-133`).

**`outcomeOf()` NEVER THROWS AND MINTS THREE ARMS FROM THREE QUESTIONS** (`src/renderer/view-client.ts`'s `outcomeOf`): a `committed` answer is `committed`; a `refused` answer is `refused`, carrying `reason` and `message` where each is a string and `null` where it is not; and **ANYTHING ELSE — a status no route of this module answers, or an answer that is not an object at all — is `unread` with `reason: 'answer-not-declared'`**. The `unread` arm it does not mint is the transport's: a route that threw or rejected is recorded at the call, by `send`, as `unread` with `reason: 'route-threw'` and the rejection's sentence as its `message` — the difference between a store that refused and a bridge that never spoke. **NOTHING COMPOSES A DECISION FROM IT** (`src/renderer/renderer.ts`'s release note): the gesture's `release` returns `void`, and its next read is the shape a delivery refilled.
