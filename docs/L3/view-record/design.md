## 2. The four addresses — and the one that is DECLARED AND UNPAIRED

Each family is ONE whole value at its own root — a WRITE may land at a leaf inside that value, which is a fact about the address and not about the family's identity (D-151) — and `ViewTier` is the **four** tier constants' union, so no read, write or repair spells a tier literal (D-87, D-91, D-97, D-98, D-105, D-132).

| Address | Tier constant | Declaration id | Holds |
|---|---|---|---|
| `['panes']` | `PANES_TIER` = `file` | `VIEW_PANES_MUST_STAND_ID` | **at this head** one member per pane id, each `{ size, bounds }`, the pane the app has standing with its measured default geometry from the creation repair; **at rev 13** one member per **DECLARED** pane id — `DECLARED_PANE_IDS`, **one** declared id (D-87, D-138) |

**THE ZONE ADDRESS'S ID DOMAIN IS CLOSED, AND THE SET LIVES IN THE SHAPE** (D-151, D-139). `src/shared/view-shape.ts` gains `DEFAULT_ZONE_ID = 'zone-1'` — `DEFAULT_PANE_ID`'s pattern, ONE spelling of the id the app's two zone turns name — and `DECLARED_ZONE_IDS: readonly string[] = [DEFAULT_ZONE_ID]`, so the fallback and the declared set cannot drift; `DEFAULT_ZONE_ID` is the name a caller with no element gets and `DECLARED_ZONE_IDS` is the set the family declares, which is why the second is derived from the first rather than spelled beside it. **THE SET IS ONE ID AND THAT IS A MEASUREMENT, NOT A NARROWING CHOSEN HERE**: `renderZone` and `zoneIdOf` address that one id — they named it `'zone-1'` literally when this was measured and read `DEFAULT_ZONE_ID` at this head, `renderer-wiring`'s landed half of `D-152`'s routing — no authored element under `src/` carries a `zoneId`, and no file of `src/` spells another id FOR THIS FAMILY — the `zone-<k>` strings at `src/shared/path-fork-cycle.ts` are the stress envelope's PLACEMENT names and name no stored zone (D-41) — so one declared zone is what the app addresses, and declaring more would mint records nothing reads (`ASM-10`). **IT CLOSES BECAUSE A LEAF WRITE NEEDS IT TO**: the store creates no parent (measured at this node, `D-151`), so `['zones', id]` must be guaranteed to stand for every id the route is handed and an OPEN set can guarantee nothing — so a caller naming an id outside the set is REFUSED (`undeclared-zone`, §5) rather than silently creating a zone, and the family's own judge refuses a VALUE naming one, which is the closure's second seat (`ASM-9`).
