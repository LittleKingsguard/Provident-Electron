## 2. The four addresses — and the one that is DECLARED AND UNPAIRED

Each family is ONE whole value at its own root — a WRITE may land at a leaf inside that value, which is a fact about the address and not about the family's identity (D-151) — and `ViewTier` is the **four** tier constants' union, so no read, write or repair spells a tier literal (D-87, D-91, D-97, D-98, D-105, D-132).

| Address | Tier constant | Declaration id | Holds |
|---|---|---|---|
| `['panes']` | `PANES_TIER` = `file` | `VIEW_PANES_MUST_STAND_ID` | one member per pane id, each `{ size, bounds }` (D-87) |
| `['zones']` | `ZONES_TIER` = `mem` | `VIEW_ZONES_MUST_STAND_ID` | one member per **DECLARED** zone id — `DECLARED_ZONE_IDS`, **one** at this head — each carrying any subset of four independently optional members, and each created as an EMPTY record by the repair (D-91, D-151) |
| `['theme']` | `THEME_TIER` = `file` | `VIEW_THEME_MUST_STAND_ID` | one whole record `{ token?, attribute?, declaration }` (D-97, D-98) |
| `['drag']` | `DRAG_TIER` = `temp` | **NONE — there is no pair at this root** | the gesture's in-process reading: one member per pane id, each `{ size }`, present while a drag is in process and **ABSENT once it ends** (D-132) |

**THE ZONE ADDRESS'S ID DOMAIN IS CLOSED, AND THE SET LIVES IN THE SHAPE** (D-151, D-139). `src/shared/view-shape.ts` gains `DEFAULT_ZONE_ID = 'zone-1'` — `DEFAULT_PANE_ID`'s pattern, ONE spelling of the id the app's two zone turns name — and `DECLARED_ZONE_IDS: readonly string[] = [DEFAULT_ZONE_ID]`, so the fallback and the declared set cannot drift; `DEFAULT_ZONE_ID` is the name a caller with no element gets and `DECLARED_ZONE_IDS` is the set the family declares, which is why the second is derived from the first rather than spelled beside it. **THE SET IS ONE ID AND THAT IS A MEASUREMENT, NOT A NARROWING CHOSEN HERE**: `renderZone` and `zoneIdOf` address that one id — they named it `'zone-1'` literally when this was measured and read `DEFAULT_ZONE_ID` at this head, `renderer-wiring`'s landed half of `D-152`'s routing — no authored element under `src/` carries a `zoneId`, and no file of `src/` spells another id FOR THIS FAMILY — the `zone-<k>` strings at `src/shared/path-fork-cycle.ts` are the stress envelope's PLACEMENT names and name no stored zone (D-41) — so one declared zone is what the app addresses, and declaring more would mint records nothing reads (`ASM-10`). **IT CLOSES BECAUSE A LEAF WRITE NEEDS IT TO**: the store creates no parent (measured at this node, `D-151`), so `['zones', id]` must be guaranteed to stand for every id the route is handed and an OPEN set can guarantee nothing — so a caller naming an id outside the set is REFUSED (`undeclared-zone`, §5) rather than silently creating a zone, and the family's own judge refuses a VALUE naming one, which is the closure's second seat (`ASM-9`).

**AND THE FOURTH ENTRY IS DECLARED AND UNPAIRED, AND THE STRUCTURAL REASON IS TWO CLAUSES.** No invariant holds the family — a `temp` reading is a gesture's transient fact, and nothing needs it to exist — **and a repair's subject would be "no drag has started"**, so a pair here could only mint a placeholder for data whose ABSENCE is the product (D-132, D-101). So the root carries an address, a tier constant and a `viewDeclaredRoots()` entry, and **`viewConstraintDeclarations` gains no row**: the guard itself is untroubled, because `declaredTierLedger` keys on the roots it is HANDED rather than on the batch, so a `file` or `mem` write at `['drag']` is refused `declared-tier` ahead of any store verb. **What the entry buys is therefore the family's ONE judgement, and it is the tier's** — and it is the whole of what a `temp` family needs. The family is also the only one with **no composer and no boot datum**: `['drag']` is a root holding one member and no sibling, so nothing is left to preserve and the first move writes the root itself (D-135, D-136, D-138).

**AND THE ENTRY LANDED WITH THE SET ROW'S OWN RE-GRAIN, BECAUSE THAT ROW IS THE ROOTS' OWNER (D-43, D-101, D-40, D-145).** `tests/integration/central-data/declared-root.test.ts`'s `D-1` asserts the published roots **equal** the declared batch's roots **plus the one root declared without a pair**, that the publication is one pair per root, and each root's tier — all gating and unmarked — so the drag entry and that row's re-grain were one pass, and a root that is declared and carries no pair is the LAWFUL asymmetry it names. **This page restates neither the published set nor how many roots stand ACROSS the two crossings** — that count is that row's to state, and it is stated nowhere else.

## 3. The same-edit rules, stated as arms of one rule

- **The entry and its family are ONE HUNK** — and for the drag root the hunk landed as **the address, the tier constant and the entry together, with no declaration** (D-101, D-132, D-145): an entry outliving its family hands the guard a tier for a root that is gone, and an address with no entry leaves the family shadowable at another tier. **AND THAT HUNK CARRIED ITS CENSUS'S COMPANION EDIT**: `central-data`'s `D-1` is the set's owner (D-43), so the drag entry and that row's re-grain were one pass — an entry landed alone reds a gating floor (§2, `E-6`).
- **`subscribe`'s array gained `VIEW_DRAG_ADDRESS` WITH the constants** (D-137, `R-2`): `createViewRecord`'s `subscribe` ranges over all four roots — `[VIEW_PANES_ADDRESS, VIEW_ZONES_ADDRESS, VIEW_THEME_ADDRESS, VIEW_DRAG_ADDRESS]` — because a `temp` root the array omits is a write the renderer never hears, the one place this can fail silently. **THE LISTENER IS TIER-BLIND**: `standing.listen(handle, [address])` binds an ADDRESS and no tier — the store's own `listen` takes addresses and never a tier — so an outside `provident.data.write({path:['drag'], tier:'temp'})` fires the same delivery the drag's own commit does, and the consumer's only correct answer is a re-read (`P-3`, `D-137`).
- **The seven sites were ONE EDIT** (D-14, D-112, D-145): the channel constants, the record's two routes, the surface's two arms, the two `ipcMain.handle` sites, **both lockstep halves** and the client's two methods. A client method whose channel has no handler writes nowhere, and a bridge member landed at one half only answers a route the other cannot reach — **the half-landing this edit closed**: `src/renderer/secure-panels.ts`'s `view?` block and `preload.ts`'s `view` now carry the same seven members, and the crossing's comparison row is their only witness (D-112, §9).
- **The drag root's hunk is smaller than a family's usual pieces and is still one hunk**: address + tier + entry (no id, no body, no repair, no batch row), the two routes, the array entry.
