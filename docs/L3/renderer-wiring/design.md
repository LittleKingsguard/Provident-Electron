## 2. The module's two writes — the `focus` act's ONE body, and the drag's two turns at the affordance's ONE preview seam

`startGutterAffordance` holds the seat and the key; `createPaneDrag` holds the two turns. The affordance calls the seat with the `PreviewState` its own turn built (`src/shared/gutter-affordance.ts`: `onMoveTurn` writes `valid: true`; `revertStateFor` builds `valid: false`).

```
const GESTURE_KEY = GUTTER_AFFORDANCE_ID    // ONE constant at BOTH seats (the `commit` seam, the preview seam's two arms); the handle's `id` is a NUMBER, so `gestureIdOf` retires
const applyPreview = (state: unknown): void => {              // the affordance's ONE preview call — L1 §3's seat
P1  holder, style, set = target's own members ; if any is unusable → return          // the landed gates, unmoved
P2  value = state.value ; if typeof value !== 'number' || !Number.isFinite(value) → return    // the landed gate, unmoved
P3  set.call(style, 'width', `${value}px`)                // THE INLINE PREVIEW, on EVERY arm: the routes are ADDED, never substituted
P4  if (state.valid === true)  → drag.move(GESTURE_KEY, state)    // THE PLACEMENT CHANGE → commitDrag; the state's clamped `value` is the size
P5  if (state.valid === false) → drag.cancel(GESTURE_KEY)         // THE REVERT → clearDrag; `valid` is boolean, so there is no third arm

move(key, preview):                                           // createPaneDrag's per-move turn
M1  size = preview?.value ; if typeof size !== 'number' || !Number.isFinite(size) || size < 0 → return   // the composition's OWN gate (`§3.2 F-8`)
M2  gestures.set(key, { erased: false })                      // THE FLAG IS CLEARED: a first move RE-OPENS it, for every gesture
M3  if (view !== null) view.commitDrag(DEFAULT_PANE_ID, { size })    // ONE write per placement change; no tier, no path, no composer

endReading(key):                                              // the ERASE, reached from `cancel` and the release — `rightClick` was THE SAME CALL and is DELETED (§5)
E1  if (gestures.get(key)?.erased === true) → return          // the ONE route this skips, and NOTHING else
E2  gestures.set(key, { erased: true })                       // set by whichever ending turn ends the reading FIRST
E3  if (view !== null) view.clearDrag()                       // the family ENDS: no placement, no geometry, no value judged
cancel(key) = endReading(key)                                  // ONE abandon terminal: no `contextmenu` reaches the affordance anywhere in this tree (§5)
```

- **`P4`/`P5` are the WHOLE discriminator, and the flag is the affordance's own** (L2 §2.1, ASM-RW-2): `valid === true` is the placement change of an observed move, `valid === false` the revert `revertStateFor` builds for all three abandon arms (`resetArm`, `dropArm`, `onCancelHook`) — no counter, no session read, no `isDragValid` reuse, and **NO SECOND LISTENER on the gesture's events** (the `D-126` two-authorities class untouched, D-30). **A non-resizable gesture's VALID moves reach no seat** (the affordance returns before its one `writePreview`), while its reset/drop/cancel REVERT does — a `valid: false` state, so the seat's `P5` arm fires and ends an already-absent family (`F-4`'s class). **AND THE FLAG'S PROVENANCE AND CLEARING, ONCE**: it is `gestures` in this closure, keyed by the key each turn is handed (total over any string); the WIRING hands ONE constant at BOTH seats — the `commit` seam's release and the preview seam's two arms — so the app's one gesture sees exactly one ending. `M2` CLEARS it on every move, `E2` sets it before its route is sent, no other line writes it — and an ending turn whose flag is set skips `E3` alone, never the sink and never the commit.
- **`E1`'s other arm is lawful and required** (`M-6`, `F-4`): a gesture that never moved has no entry, so an erase sends exactly one `clearDrag` — the store answers `committed` whether or not the family stood, and the composition decides nothing about that answer.
- **`M1` is the turn's own totality, not a second judgement**: the affordance writes no non-finite preview, and a directly-driven surface's hostile preview sends nothing and leaves whatever last stood standing (`M-10`). **AND THE SEAT INHERITS ITS PRESENTATION GATE**: `P1`/`P2` are the LANDED statements and they precede `P4`/`P5`, so a target with no usable `style` sends no route either — one call, one order, stated rather than hidden. **AND THE `commit` SEAM STAYS AN INLINE PROPERTY of the options literal** — `commit: (gesture, value): void => { drag.release(GESTURE_KEY, value) }`, the sink's third argument DELETED (§5) — because `D-117/LIVE-READ` probes that exact form in this file and its `[^}]*drag\.release\(` regex survives the shortened call; hoisting it to a `const` reds a gating source row (`tests/pane-drag-compliance.test.ts`).
- **THE PAGE'S OTHER WRITE IS THE `focus` ACT, AND IT IS ONE BODY** (`D-141`, `D-142`, `D-158`; the source's `focusActRoute`, whose docblocks cite THIS section and §3): S1 the argument space GUARDED rather than trusted (`'target' in <non-object>` never attempted, `newTab === true` with no coercion), S2 ONE committed reading of `['tabs']` through `getTabsClient()`, S4/S5/S7 the three arms that WRITE NOTHING (no `target` answers the reading as it stands; a non-string target is the route's own `malformed-arguments`; no standing row and no open is `target-absent`), S6 the seat in the RECORD's own terms (`seatOf`: the first row of `order` whose `target` matches **and the ROW it resolved**, else one OPENED as `tab-<n>` by the existing `mintTabId`), S8 **ONE ROW** handed VERBATIM to `dataRoute('write', {path: ['tabs', row.id], tier: 'file', value: row})` — ONE store verb, one commit, one delivery, no retry and no member re-spelled (§3) — S9 the record RE-READ after the write, **which is still owed and now more**: `D-70`'s rule is that the answer is the record that STANDS, and `D-158`/`D-159` leave the act unable to predict EITHER the `'seat'` repair's append position (a reading and not a law) OR the survivor `exactly-one-active` keeps — so the re-read is the ANSWER's and NOT a delivery (it does not feed `holdTabsReading`) — and S10/S11 that write's judgement carried BESIDE the re-read as `refused`, member for member (`refusalOf`/`withRefusal`) — **`parent-absent` being the ONE refusal this address can meet**, since `tabsMustStand` answers at a deeper address instead of minting (`D-157`) — while every arm answers a value and none throws (`D-127`, `D-136`). **AND WHAT FOLLOWS THE WRITE IS THE RECORD'S OWN PUSH, NOT THIS ACT'S RE-READ**: one subscription body re-reads the record and drives the two authored terminals (L2 §5, `D-137`).
- **WHO OWNS THE NORMALISATION IS THE RECORD'S, AND THE ROW THIS MODULE WRITES MAY SEAT TWO ACTIVES ON PURPOSE** (`D-129`, `D-142`; `focus-retirement`'s `ASM-3`; `src/main/tabs-record/index.ts`'s `TABS_CONSTRAINT_ID`, its body and `healedFamily`): `rowForSeat` stamps `active: true` on the ONE row it answers and never touches another — **THE CALLER NEVER CLEARS THE OLDER FLAG, and after this pass it CANNOT: the write names one address** — because `exactly-one-active` normalises the pair INSIDE THE CALLER'S OWN COMMIT: its repair JOINS that attempt through `writeJoined` (naming the commit it was handed at `write`'s required fourth position, never opening a second), keeps ONE by the written referent's precedence and deactivates the rest IN THE SAME OBJECT, so the re-read answers one corrected record — and a local `active: false` here would be the second authority that repair exists to be.
