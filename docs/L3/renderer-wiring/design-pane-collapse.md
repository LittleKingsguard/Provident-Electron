## 1. The act is a RECORD WRITE, and the three shapes it could have been

- **A VIEW-ONLY TRANSIENT IS REFUSED, ON THREE MEASURED GROUNDS.** (i) **There is no tier for it**: the record's four families are `['panes']` and `['theme']` at `file`, `['zones']` at `mem` and `['drag']` at `temp`, the last DECLARED AND UNPAIRED because no invariant holds a gesture's transient (`D-145`) — a fifth root for a collapse would be a fifth family, a creation repair and a placeholder for a state the pane already has an address for. (ii) **A collapse outlives a gesture**: `['drag']` is re-minted at every boot and its bytes never reach the profile, which is right for a pointer and wrong for a person's decision about a pane. (iii) **A realm-local flag would be a second authority beside the record** (`D-129`): the bar is painted from the record on every delivery, so a state the delivery cannot read is a state the next delivery overrules.
- **SO `collapsed` JOINS THE PANE'S OWN RECORD**, and **its ABSENCE MEANS EXPANDED** — the `D-243` no-default rule applied to a state: a `false` written by the creation repair would be a fact nobody stated, and the family's two record forms (`C-9`) are already told apart by absence.
- **THE ACT, ONE LEAF WRITE** (`D-248` §3's `dataRoute('write')`, `AL-10`'s leaf precedent):

## 3. What collapsing does to the BOX — one composition, four zones, and the figure is not overwritten

- **THE ADJUSTABLE AXIS BECOMES `auto`, THE SCROLL BECOMES `hidden`, AND THE FILL IS UNTOUCHED.** `panePaintOf` (`:4359`) already composes the three parts from the zone alone; it gains ONE branch on `record.collapsed === true`:

```
panePaintOf(zone, record, collapsed):                        // REV 3: the THIRD operand is the EFFECTIVE collapse — the
                                                             // delivery composes `record.collapsed === true || zoneCollapsedOf(…)`
                                                             // and the preview its post-commit answer (design-zone-collapse.md
                                                             // §2, §5); its TWO CALLERS are still the delivery and the preview
S1  placement = paneFillAxisOf(zone); if placement !== null → style[placement.fill] = PANE_FILL     // UNCHANGED: a `top` pane still fills its height
S2  for member of paneAxisMembers(zone):
      collapsed → style[member] = 'auto'                     // THE ROW'S OWN BOX, and NO FIGURE IS INVENTED (`D-174`)
      else      → style[member] = `${record[member]}px` where the record STATES a finite non-negative figure   // UNCHANGED
S3  if placement !== null → style[placement.scroll] = collapsed ? 'hidden' : 'auto'                  // the axis it adjusts, clipped not scrolled
```

- **WHY `auto` AND NOT A DECLARED COLLAPSE FIGURE**: a `14px` constant would be right on one axis and false on the other — the collapsed member is a WIDTH in `top`/`bottom` and a HEIGHT in `left`/`right` — and a figure the sheet declares cannot beat the paint's inline value anyway. **`auto` is the one declaration that means "the row's own box" in both arms**, so a collapsed `top` pane is as wide as its glyph, name and status, and a collapsed sidebar pane is as tall as its row.
- **THE THIRD ARM IS THE STAGE, AND IT IS `C-12`'S OWN RULE READ TO ITS END** (rev 2): `paneAxisMembers(undefined)` answers **BOTH** members (read off that relation), because a stage pane's two figures are its own and `paneFillAxisOf` answers `null` for it — so a collapsed stage pane writes `width: auto; height: auto` and **writes no scroll at all, because there is none to write**. That is *"a stage pane behaves as a sidebar pane"* (`C-12`) plus the second member its own record owns, and **it collides with nothing**: `AL-10`'s stage clause asserts a stage pane *fills nothing and scrolls nothing*, which is exactly what this composition writes.
- **AND THE ROW MUST BE THE WHOLE BOX, WHICH IS ONE SHEET RULE** (§6): `:has(> .pane-head)[collapsed="true"] > :not(.pane-head) { display: none }` — **the `:has()` scope is rev 3's and it is what lets a ZONE carry the same word without hiding the panes it must SHOW** (`design-zone-collapse.md` §6; `index.html`'s own `:has(> .pane-head)` key, one clause longer). **It reaches a pane's BODY only because no pane keeps a body in its own `content`** — a node's text renders in the node's own flow AHEAD of its children, so the rule is blind to it, and `A-14` (`app-envelope` rev 2 §2) moves the one authored body into a child for exactly this reason (`D-259`'s measurement, one state over). **The record's figure is NOT overwritten** — it stays stored as the memory `C-11` calls it, so expanding restores it with **zero writes**, which is the property that makes this a view-state and not an edit.
- **THE ZONE'S SPACE IS THE ARRANGEMENT'S, AND TWO THINGS MUST NOT BE CLAIMED ABOUT IT** (rev 2). **`D-258`'s PROVISIONAL NOTE IS NARROWED HERE** (`D-259` narrowed it once already): panes in one zone lay out along the pane-adjustable axis **each at its own figure** — **from this rev, each at its own figure EXCEPT where the record says the pane is collapsed, where its basis is the row's own box.** **AND THE FREED SPACE IS NOT REDISTRIBUTED**: every zone child is `flex: 0 0 auto` (the sheet's four zone rules), which forbids grow as well as shrink, so a collapsed pane shortens the zone's own scroll extent (a `top`/`bottom` row) or leaves the column's free space unfilled (a sidebar) — **the stage's remainder is the ARRANGEMENT's and is not changed by a pane's figure** (`D-185`). **The SIZES' interaction remains owed to L1/L2**, and a collapsed pane is one more case of it, stated rather than discovered.
- **IT SURVIVES A RELOCATION — CONDITIONALLY, AND THE CONDITION IS A HUNK OF THIS PAGE** (rev 2). `collapsed` is per-pane record data, so the `move` re-parents the node and re-authors nothing (`D-252`) and every delivery re-reads it; the preview draws it correctly for free, because `panePaintOf` is the preview's composition too (`D-263`) and the collapsed axis is derived from the DESTINATION zone handed in. **BUT THE ONE COMPOSITION THAT WRITES A PANE WHOLE TODAY IS `paneFamilyValueOf` (the one whole-family composition, called from `paneMoveAct`), AND IT COMPOSES `{width, height, zone?, bounds?, index?}` FROM ITS OPERANDS** — so at this head **a relocation drops `collapsed`, `status` and `updatedAt` for every pane in the family**. **§8's first guardrail is therefore the hunk that makes this sentence true, and not a warning beside it**: the value must be **the standing record SPREAD**, with `zone`/`index` replaced and `bounds` REMOVED — `D-249` §4's one drop, kept.

## 4. The indicator: three words from the record, a fourth DERIVED, and one precedence rule

- **`updated` IS NOT A FOURTH `status` VALUE, AND THE CORPUS SHOULD SAY WHY IN ONE SENTENCE**: `busy`, `waiting` and `done` describe **the pane's own work** — a fact about the content, held in one place; `updated` describes **a relation between the content's update and the user's last look** — two facts, one of which is not in the record at all. **So the record's closed three never carry it, and the paint derives it** (`§5`).
- **THE FOUR PAINTED WORDS ARE EXACTLY `busy`, `waiting`, `done`, `updated`** — lowercase, no space (`waiting` is the *"waiting on/requesting user action"* of the user's sentence, shortened because the bar is 14px). The bar prints the attribute verbatim, so the vocabulary is legible in markup and in a row.
- **ONE COMPOSITION, TWO CALLERS** (`panePaintOf`'s own precedent, `D-263`):

```
paneStatusOf(record, viewedAt: number | null): string | null      // null = a REMOVAL, the `D-253` spelling for an absent member
T1  if typeof record.status === 'string' return record.status      // the record's word WINS — it is the more specific fact
T2  if record.collapsed !== true return null                        // the `updated` word is for COLLAPSED panes ONLY (the user's own parenthetical)
T3  content = instantOf(record.updatedAt); if content === null return null       // no stamp → never `updated`
T4  if viewedAt !== null && viewedAt >= content return null         // a look at or after the change clears it
T5  return 'updated'
```

- **THE HEAD ARM IS ONE `state-slice`, `mode: 'replace'`, WITH A REMOVAL WHERE THE ANSWER IS `null`** — the shape `D-253` measured for the pane's attribute, on the head node (`app-envelope` rev 1 §2), written **once per pane per delivery** and re-derived from the record on every one (`D-129`: no remembered state).

## 5. The two stamps, where each lives, and the honest gap

- **THE CONTENT STAMP IS RECORD DATA, AND THE PRECEDENT IS `tabs`' `lastActiveAt` WITH ONE DIFFERENCE THAT DECIDES THE REPAIR.** `lastActiveAt` is an ISO member stamped by its writer (`renderer.ts:1540`) and repaired to NOW when blank (`tab-has-lastActiveAt`, `tabs-record/index.ts:1165`) **because "a tab that was never active is active now" is TRUE at creation**. **A pane's "content changed at" has no such true default**: a repair stamping every pane at boot would make the whole app read `updated` — a lie, and the `D-243` no-default class. **So `updatedAt` is written by whoever changes the pane's content, repaired by nobody, and the demo stamps nothing** — the state is EXPRESSIBLE and measurably INERT until a producer exists, which is the honest price and is why `AL-14` (§7) drives it through `data.write`.
- **THE VIEW STAMP IS THE REALM'S, AND IT IS A CLOSURE** — `lastViewedPanes: Map<string, number>`, beside `handedNewTabTarget` (`:2411`) and `startThemeApplication`'s `lastSetting`: realm state that covers a gap the record cannot, **never written to a store, never read by a row, reset by nothing but a reload** (a durable "last look" would be a `file` write per glance, which is not a fact about the content and has no invariant to hold it — `D-145`'s test).
- **WHEN IT CLEARS, EXACTLY**: on the **expand** act (§1 `X4`: the stamp is taken before the write's own push lands, so the delivery the write produces composes `T4` against the advanced stamp and the word is gone **in the same turn** — no second write, no poll, `D-82` clause 4). **A COLLAPSED PANE CANNOT CLEAR IT, BY CONSTRUCTION**: nobody is looking at a closed pane, and the look IS the expansion — which is the whole reason the user asked for this indicator *"for collapsed panes"*.
- **AND THE HONEST ANSWER, SAID IN ONE PLACE**: **this indicator needs a member the corpus does not have (`updatedAt`) and a definition of "view" nobody has written.** The smallest thing that works is the three lines above: one optional record member with no producer required, one realm closure stamped at the one act that IS a look, and a comparison that needs nothing else. **The comparison is by PARSED INSTANTS AND NEVER BY STRING ORDER** (`D-242`'s order-sensitive diff, one comparison over): a stamp that does not parse on either side answers ABSENT, not "newer".

## 6. The sheet block, and the four declarations it owes

- **THE ROW**: `.pane-head` takes `display: flex; align-items: center; gap: .25rem; width: auto; padding: 0 .25rem; position: sticky; top: 0; left: 0; z-index: 1;` and `:focus-within { z-index: 4 }` — **`D-257`'s measured row, `D-246`'s pin and `D-261`'s two ranks, MOVED from `.pane-grab`** (`app-envelope` rev 2 §3), because the row is now the box that makes the stacking context the four drops are confined to. **BOTH STICKY INSETS ARE DECLARED AND THAT IS `D-243`'S AXIS PAIR READ ONE NODE OVER**: a sidebar pane scrolls `overflow-y` and a `top`/`bottom` pane scrolls `overflow-x`, so `top: 0` holds the row in three of the four zones and `left: 0` holds it in the fourth — **one rule, no zone-keyed spelling, and `D-246`'s measured defect cannot return on either axis.**
- **THE NAME STAYS ON THE GRIP**: `.pane-head > .pane-grab::after { content: attr(name) }` — **and it now paints in EVERY zone**, which is the user's *"title/control bar"*: `D-257`'s `top`/`bottom` form deliberately painted no name because there was no row.
- **THE COLLAPSE GLYPH IS A PSEUDO KEYED ON THE PANE'S PAINTED MEMBER** — `[collapsed="true"] > .pane-head > .pane-collapse::before { content: '▸' }` and `▾` otherwise — **no state on the node, no class the paint touches, and the record's member written in exactly one place** (`app-envelope` rev 1 §4). **AND THE SELECTOR IS SCOPED BY `>` FROM REV 3, FOR THE SAME REASON THE BODY RULE IS**: a ZONE now carries the same word about ITSELF (`design-zone-collapse.md` §6), and an unscoped descendant selector would let the zone's attribute paint a pane's control — one fact, one writer, one reader, per node (`D-129`).
