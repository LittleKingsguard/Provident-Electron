## 3. The executor's five doors (`L2` §11), the fifth the invocation door

- `createModuleExecutor(host)` builds ONE object whose state is `records: Map<string, ActiveRecord>` and `order: readonly string[]`; `install` is §4–§5 in one act, `deactivate` is §4, and `activations()` answers `order.map(name => recordOf(records.get(name)))` — the order is the resolver's ANSWER and no caller sorts (`L2` §7, `D-304`). **And the surface's fifth member is `invoke(toolName, args)` — THE INVOCATION DOOR** (`L2` §11, `ASM-MS-4`): the ONE route from `mcp-surface`'s transport to a `module:<name>.<tool>` handler, answering that handler's own value VERBATIM or a `Refusal` naming the name it could not run. **Each shape it rejects is NAMED rather than passed over** (`D-1` §8): **(i) a handler TABLE carried on `activations()`'s answer** hands every LISTING consumer a TOOL HANDLER that OUTLIVES its activation — the answer is the resolver's order report and a consumer's business there is the published names, so a name `deactivate` has already deleted would still run, its record gone and its listener pair withdrawn; **(ii) a FIFTH `ModuleHost` member** moves the interface this seat is bound by and makes the HOST — the embedding — answer for the executor's OWN state, where `invoke` is what the executor ANSWERS and the host is only what it is GIVEN. **So the table is the RECORD's, filled at activation and read AT THE TURN**: `activate` already collects `handlers` keyed by the FULL published name (`Registrations` declares it beside `tools` and `mains`, `src/main/modules/admission.ts`), the record it answers therefore CARRIES that map, and the door looks the name up in the STANDING records — while `activations()` keeps answering the published names and the declarations only, never a tool handler (§2, §4). **THE HANDLER RUNS WITH THE CLOSURE ITS OWN ACTIVATION CREATED** (`D-307`'s grain read at a tool): no re-compile, no second run of `entry`, no state rebuilt, `args` travelling BY IDENTITY with no schema, no coercion and no wrapper beside it, and the key the FULL `module:<name>.<tool>` — injective by §1's namespace rule — so the door parses nothing and no caller re-qualifies a name. **And the two-gate is `mcp-surface`'s, checked BEFORE the door**: this module reads no security group and holds no gate, so a call that reaches `invoke` is one the transport has already admitted (`L2` §0, `L1` §3 `S-5`, `D-305`).

## 4. Pseudocode — `install`, its activation loop, `deactivate`, and the invocation door

```
install(delivery):
  loaded = loadDelivery(delivery); refused = Map(); out = Map()      # verdict order IS delivery order
  for src in loaded: for check in [s => admitSource(s), s => admitDeclaration(s, FOUNDATION)]   # host-api-token, then foundation-tool
    a = check(src); if !a.ok && !refused.has(src.name): refused.set(src.name, a)
  plan = resolve(standing ++ loaded.filter(s => !refused.has(s.name)), host.appVersion())  # §5, C-11
  if !plan.ok: return loaded.map(src => rejected(src, refused.get(src.name) ?? plan))
  for src in plan.order where src is IN THIS DELIVERY:   # activation follows the RESOLVER, not the delivery
    if refused.has(src.name): continue
    standing = records.get(src.name)
    if standing && standing.version === src.manifest.version: sendFrame(standing); out.set(src, 'no-op'); continue
    if standing: withdraw(standing, host.store)    # the entry's own inverses, contained
    made = activate(src)
    if made.ok: records.set(src.name, made.record)
    out.set(src, made.ok ? (standing ? 'updated' : 'installed') : rejected(src, made))
  order = plan.order.filter(name => records.has(name))
  return loaded.map(src => out.get(src) ?? rejected(src, refused.get(src.name)))
rejected(src, r) = {status: 'rejected', name: src.manifest.name, version: src.manifest.version, reason: `${r.reason}: ${r.subject}`}   # the NAME *and* the thing it refused (ASM-MS-3)
activate(src):                                       # its failure answers are an `ActivationOutcome`'s `{ok: false, reason, subject}` — neither a `Refusal` nor the door's `refuse(…)` (signatures.md §2)
  cap = src.manifest.capabilities; mains = Map(); reg = {tools: Set(), mains, handlers: Map(), refusal: null}   # mains: addressKey -> compiled main | null
  ctx = {store: refusingStore(),                     # the FOUR members, EXACTLY (L2 §3, §10)
         declare: d => { mains.set(addressKey(d.address), d.main ? compileMain(d.main) : null); return moduleHandle(src.name, addressKey(d.address)) },
         tool: (t, h) => { n = toolName(src.name, t); reg.tools.add(n); reg.handlers.set(n, h)   # the map the DOOR reads (§3)
                           if isFoundationTool(n): reg.refusal ??= {reason: 'foundation-tool', subject: n}; return n },
         log: (line, detail) => host.log(`module:${src.name}: ${line}`, detail)}
  try { compileMain(src.manifest.entry)(ctx) } catch e { return failed({reason: 'entry-threw', subject: msg(e)}) }
  c = compare(cap, reg)      # BOTH directions; a declaration with NO `main` is the passthrough arm and lawful (C-12)
  if c || reg.refusal: return failed(c ?? reg.refusal)     # nothing reaches the store before this comparison
  bindings = []
  for d in cap.listeners ?? []:                       # ONE store entry per DECLARATION (D-307, L2 §4)
    k = addressKey(d.address); h = moduleHandle(src.name, k)
    if d.main && !mains.get(k): return failed({reason: 'declaration-overstated', subject: k})   # C-12, dir. 1
    bindings.push({address: d.address, handle: h, main: mains.get(k) ?? undefined})
    host.store.listen(h, d.address)                   # the watching, under the declaration's ONE handle
    host.store.register(h, contained(mains.get(k) ?? passthrough(d.address)))   # the body; the wrapper is U3's
  if src.manifest.client: sendFrame(src)              # {module, client}, ONCE, by value (L2 §9)
  return {ok: true, record: {name: src.manifest.name, version: src.manifest.version, manifest: src.manifest,
                             tools: [...reg.tools], listeners: bindings, handlers: reg.handlers}}   # `Activation` never hands it out
deactivate(name):
  rec = records.get(name)
  if !rec: return {status: 'no-op', name}             # nothing stands: NO store call, no throw to contain
  failures = []
  for b in [...rec.listeners].reverse():              # reverse of the registration order (L2 §6)
    for verb in ['removeListener', 'unlisten']:       # ONE entry's two store-side halves, withdrawn as a UNIT:
      try host.store[verb](b.handle)                  #   a failed body-withdrawal ABORTS the pair, so the watch the
      catch e: failures.push({handle: b.handle, message: msg(e)}); break   # retry needs is never consumed (N2)
  if failures.length:                                 # the record STANDS, so the inverse stays retryable
    return {status: 'rejected', name, reason: `${failures[0].handle}: ${failures[0].message}`}
  records.delete(name); order = order.filter(n => n !== name)   # the handler map goes WITH the record (§3)
  return {status: 'deactivated', name}
invoke(toolName, args):                               # THE DOOR (L2 §11, ASM-MS-4): ONE route, re-read AT THE TURN
  for name in order:                                  # the STANDING records, never a table a listing handed out
    h = records.get(name)?.handlers.get(toolName)
    if !h: continue
    try return h(args)                                # the handler's OWN value, VERBATIM; `args` travels BY IDENTITY
    catch e: return refuse('handler-threw', toolName, msg(e))     # a throwing body is a VALUE, never a throw
  return refuse('tool-unknown', toolName, `no activated handler publishes ${toolName}`)
refuse(reason, subject, message) = {status: 'refused', reason, subject, message}   # D-105: four members, a VALUE
```

## 5. Pseudocode — the resolver's ordering (`L2` §7), and the one number it judges

```
resolve(candidates, appVersion):                   # its refusals are `{ok: false, reason, subject}` — a RESOLUTION answer and never a `Refusal` (no `status`, no `message`: signatures.md §2's `Resolution`)
  for c in candidates:
    if c.requires?.app && !satisfies(appVersion, c.requires.app):
      return gap('application-version-unsatisfied', `requires app ${c.requires.app}; ${appVersion} stands`)
    for dep in c.requires?.modules ?? []:
      held = byName(dep.name)
      if !held || !satisfies(held.version, dep.versionRange): return gap('dependency-unsatisfied', `requires ${dep.name} ${dep.versionRange}; ${held ? held.version : 'not admitted'}`)
  indegree = Map(c => 0); dependents = Map()                  # edges: dependency -> dependent, built per candidate
  for c, for dep in c.requires?.modules ?? []: dependents.get(dep.name).push(c); indegree(c) += 1
  ready = candidates.filter(indegree 0); order = []           # arrival order, so ties keep it — never a sort
  while ready.length: n = ready.shift(); order.push(n)
    for d in dependents.get(n) ?? []: if --indegree(d) === 0: ready.push(d)
  if order.length < candidates.length: return gap('dependency-cycle', `cycle among ${candidates.filter(c => !order.includes(c)).map(name)}`)
  return {ok: true, order}   # the FOUNDATION's own nodes precede every module's by construction, and
                             # `activations()` carries modules only, so no prefix is added here (C-6)
satisfies(version, range): ...   # `>`, `>=`, `<`, `<=`, `=` and a bare exact version, on dotted numerics; an UNPARSABLE range is UNSATISFIED — `L2` §7's refusal-by-name read at a range: one the authority cannot satisfy is named and refused, never silently satisfied
```

## 7. Guardrail notes — what a later implementer must never do

1. **No `window`, no IPC, no `ipcRenderer`, no `webContents`, no `window.provident.*` and no bridge route** in the contract or either ctx: the passthrough is the only way out, and the door is `admitSource` (`C-1`, `D-304` (i), findings 19).
2. **No dispatch-time resolver and no source text in graph data**: `action` installs a LIVE closure keyed by name (`C-10`, `D-313`).
3. **No second store**: the executor hands `host.store` into the ctx and constructs nothing — no `storeCreate`, no filesystem, no `provident-storeroom` import except `import type` (`C-16`, `D-312`).
4. **One handle per DECLARATION, from `moduleHandle` and nowhere else, and never a tool's**: no counter, no random id, no store-minted handle, no collision with a constraint id (`C-3`, `D-310`).
5. **The main half's `store` refuses EVERY verb `reentrant-call`, as a value**, and the two ctx halves stay DISJOINT: each a literal of exactly its keys, `store` and `log` the only members both carry, `declare`/`tool` never client-side, `onDelivery`/`action`/`graph` never main-side. The guard stands in this module's ctx and at no seam, so no store verb and no `STOREROOM_DECLARED_SURFACE` member moves (`L2` §10, `D-311`, §0, ASM-MS-1).
6. **Every refusal is a VALUE carrying its SUBJECT**: no throw crosses `install`, `deactivate`, `activate` or a ctx door, every store call sits inside its own `catch`, and the composed `reason` names the thing refused — `<name>: <subject>` for a verdict, `<handle>: <message>` for a deactivation — while the CTX's own refusal keeps `L2` §10's `reason: 'reentrant-call'` and puts its sentence in `message` beside a `subject` (`D-105`, `L2` §5, §10, ASM-MS-3).
7. **`host.appVersion()` is read ONCE per install and is the ONE number**: no second literal, no `'0.1.0'` beside `createServer`, a range the authority cannot satisfy refused by name (`C-11`, findings 12) — and **no new dependency**, no `semver`; ranges are judged by the contract's own comparators (`platform.md` §4).
8. **The client source crosses as a STRING in `{module, client}` and in no other form** — never a function, never an `RpcMethod`, never a route on the `module` bridge member (`C-15`, `D-308`).
