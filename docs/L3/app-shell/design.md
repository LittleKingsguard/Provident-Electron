## 1. The window: the platform draws the controls, and the page owns the window (`S-3`, `D-179`, `C-1`)

- **ONE option pair, on the ONE `new BrowserWindow`, and nothing else in the constructor moves**: `titleBarStyle: 'hidden'` and `titleBarOverlay: true`, inserted after `height: 720,` and before `webPreferences`. The bare boolean is deliberate: it leaves **colour, symbol colour and height to the platform's own defaults**, exactly as `D-121` measured it at this construction — content `980×720` at `y+0` with **the OS painting its own controls over the page** — so no authored figure stands beside the platform's chrome (ASM-L3-3, OWED-5).
- **What it buys is MEASURED, not assumed, AND NO FIGURE OF THE PROBE TRANSFERS** (`D-179`, on the same `44.4.5` binary; `docs/L2/app-shell/interface.md` §3's own constraint): with the pair `navigator.windowControlsOverlay.visible` is `true`, `getTitlebarAreaRect()` returns `[0,0,607,36]` and **the page owns the whole window** — but that rect is a **`720`-wide, `220`-high probe's**, where the platform's controls took `113 px`; **this app's window is `980×720`**, so its free strip is the window's width less the platform's controls **and its height is the platform's**, and `AL-9` is the reading that settles it (§7).
- **AND NO PAINT TURN IS OWED FOR THE CONTROL STRIP** (`D-193`): `env(titlebar-area-width)` computes to `607px` and `env(titlebar-area-x)` to `0px` **on that same probe** — the resolution is measured, the value is the platform's and adapts — so the tabs row bounds itself in **authored CSS** (`env(titlebar-area-width, 100%)` — `app-envelope`'s) and this module ships **no geometry, no resize listener, no IPC and no figure** for it.
- **IT IS PROVEN BY CONTRACT AND NEVER BY A PICTURE** (`D-179`): `capturePage()` returns web contents only and `desktopCapturer` hung on this Wayland session, so **no screenshot confirms the buttons' appearance** and this page claims none. `AL-9` is the reading that matters (§7).
- **What MUST NOT change in the constructor or around it** — each a byte this pass leaves alone: **`show`** (absent, and `show: false` must not appear — `tests/ui-leg-contract.test.ts`'s DIS-3 guard reads that absence); **`webPreferences`** verbatim (`preload: join(here, 'preload.cjs')`, `contextIsolation: true`, `nodeIntegration: false`); `width: 980`, `height: 720`; `backend.attachWindow(win)` and `await win.loadFile(rendererHtml)`; the boot order `D-19`'s clause fixes (the settings close **before** the window exists — `tests/tier4-arbitrary-storage.test.ts` reads that relation); and **`win.on('closed', …)` + `app.on('window-all-closed', …)` verbatim** — after §2 the app's own quit paths are the **platform's overlay close button** (the WINDOW's, not authored — `D-179`, L2 §4), this `closed` handler that closes the MCP port and calls `app.quit()`, and `window-all-closed`; **`Ctrl+Q` is gone**.
- **No authored control, no `frame: false`, no window IPC** (`D-178` §2, `C-1`): `D-121`'s authored-controls arm was **never landed** and `D-178` refuses it; authoring the buttons would put a dispatchable close in the app graph, outside `app-surface`, where the default grant reaches it.

## 2. The native menu leaves, and this is what a user loses (`S-10`, `D-181`, `C-6`)

- **`Menu.setApplicationMenu(null)` in `main()`, immediately BEFORE `const win = new BrowserWindow({`**, in the SAME edit as §3's route (`S-10`): a pane that contains the menus implies the native bar is not also drawn, and a pane beside a live native menu would draw the menu twice (`D-180` §iii). `src/shared/menu-template.ts` builds a template for the menu this act REMOVES, so `chrome` gains no consumer — **AND ONE OF `chrome`'S OWN PINS REFUSES THIS VERY ACT**: `tests/menu-template.test.ts`'s `X-5` sweeps `src/**` for `\bMenu\b` and `setApplicationMenu` and excludes exactly ONE path (that module), so `M-1`/`M-4` red it. It is a **MARKED file on notice**, so the four-leg floor holds and `npm test` prints it — but two units' contracts now contradict each other in the tree, and the ruling is OWED-6.
- **RE-BOUND BY THIS UNIT: *none*** (`D-181`, `D-188`, `C-6`). **GONE, and not replaced**: `Ctrl+Q` (quit) · `Ctrl+W` (close) · `Ctrl+R` (reload) · `Shift+Ctrl+R` (force reload) · `Ctrl+Shift+I` (devtools) · `Ctrl+M` (minimize) · `Ctrl+0` · `Ctrl+=` · `Ctrl+−` · `F11`.
- **THE USER-VISIBLE COST, SAID PLAINLY RATHER THAN BURIED**: after this unit **`Ctrl+Q` does nothing**, `Ctrl+W` does not close, `Ctrl+R` cannot rescue a stuck renderer, `Ctrl+Shift+I` cannot open devtools, and `F11` cannot fullscreen. **The pane's eighteen items do not restore any of them** — a pane item needs a click, and the seven shortcuts behind destructive roles are the ones refused (§3). What survives is the **edit keys** (`Ctrl+Z`/redo/`X`/`C`/`V`/`A`), which were never the menu's: the renderer handles them over a focused element, menu or no menu (`D-181`). **A keyboard surface is a later unit's and NOT this one's** (`C-6`): no accelerator, no `globalShortcut` and no key listener is added here.
- **AND THE SILENCE IS UNMEASURED BY THE FOUR LEGS**: no row reads `Menu.getApplicationMenu()` and no leg sends a keystroke, so this is a **recorded gap** beside the drag region and the internal scrolling (L1 §6(iv)), never an implied guarantee.

## 3. The role route — one channel, one member, one handler, and the seat where the grant stops (`S-10`, `D-181`)

- **The member**: `window.provident.menu(role: string)`, answering `{status:'admitted', role}` or `{status:'refused', role, reason, message}` — `renderer-wiring`'s `startMenusItems` calls exactly this and writes the answer into `MENUS_RECEIPT_ID` (§9 `OWED-4`). Exact text, the channel constant and the two role sets: `signatures.md` §2–§3.
- **THE GUARD IS `main`'S ADMITTED SET, AND NOWHERE ELSE** (`D-181`, L1 §2): the pane renders **eighteen** and the route admits **eleven**; the seven refused items render `disabled` with **no handler** (`app-envelope` `S-9`), which is a **courtesy**, because a renderer-side guard is a guard an agent's `provident.dispatch` bypasses — an admitted set in `main` cannot be bypassed.

| | the roles | why | enforced at |
|---|---|---|---|
| **ADMITTED (11)** | `undo` `redo` `cut` `copy` `paste` `delete` `selectall` · `resetzoom` `zoomin` `zoomout` · `togglefullscreen` | content operations on the focused element, whose keys are Chromium content behaviour and survive the menu's removal; then magnification and window presentation, **which end nothing** | `MENU_ADMITTED_ROLES` in `main.ts` |
| **REFUSED (7)** | `quit` · `close` · `reload` · `forcereload` · `toggledevtools` · `minimize` · `zoom` | **`quit`/`close` kill the app and the MCP port the agent is speaking on**; **`reload`/`forcereload` wipe every renderer transient** (the drag, the ghost, the overlay's in-flight state); `toggledevtools` is an agent-visible devtools toggle; **`minimize`/`zoom` are window-state the corpus already refused for authored controls** (`D-177`) | `MENU_REFUSED_ROLES` in `main.ts`, tested **before** any other arm |

- **A REFUSED ROLE ANSWERS, IT DOES NOT VANISH**: `{status:'refused', role, reason:'role-not-admitted', message}` — **the role named**, so `AL-7` can read seven refusals by name and the app is still answering on its transport afterwards. **The refusal is a VALUE, never a throw** (`D-101`'s shape read on a channel that owns no store).
- **THE ARM NOTHING PUBLISHED DROVE UNTIL NOW IS THE THIRD**: a role that is **neither** the eleven nor the seven answers `role-unknown`, and a **non-string** answers `role-malformed`; neither throws and neither is silent (`AL-11`, L2 §7 `OWED-4`). The total function's order is **R1** type test → **R2** refused set → **R3** admitted set → **R4** unknown, and the two sets are **literal, disjoint and total over `D-181`'s eighteen** — **no prefix test**: `zoom` is refused while `zoomin`/`zoomout` are admitted, and `selectall` is one word.
- **What the admitted answer does NOT claim**: an admitted role is **ADMITTED, not executed** — no arm of this unit applies a role, because the native menu that defined them is the thing being removed (OWED-1, OWED-2). **A click on `Copy` in the pane therefore admits the role and changes nothing on screen**, and that is stated here so nobody discovers it as a defect.
- **This route is NOT stricter than its siblings** (`D-121`, L2 §8 `ASM-L2-8`): it inspects **no `_event`**, adds **no `permitted(`**, reads **no `senderFrame`** and spells no bare `event` token — the three scans `BR-10` already holds over `main.ts` — because the admitted set is what bounds it.
- **The channel constant lives in `src/main/store-channels.ts`** and enters **`src/shared/types.ts` nowhere** (`D-123`, `ISO-5`/`ISO-6`): that file is imported by the MCP-reachable stack, so an address spelled there is an address an MCP-reachable file could name. **The file's own census moves `2 → 3`** and `ipc-contract` gains no member.
