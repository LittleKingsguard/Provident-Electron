## 4. The constraints this design fixes

- **`C-1` — the passthrough is the only way out, and admission is where that is enforced.** A module's code names no `ipcRenderer`, no `webContents`, no `window`, no `window.provivent.*` and no IPC channel; the foundation's ctx is its whole outside (D-304 (i), research B1). **The rule is prompt-level for a HOSTILE module** — modules are trusted-equivalent to `code` and the ctx is *"an ERGONOMICS layer, NOT a security boundary"* (`src/renderer/extensions.ts`'s header; findings 19) — **so the gate the design can build is the one at the door it owns: `S-3`'s install-time refusal, by name**, and nothing here claims isolation it cannot build (D-44). **A route that exists and is forbidden is still forbidden**: `ProvidentBridge`'s `data` member carries five store routes and the renderer reaches them as `window.provident.data.*` (`src/main/preload.ts`), so a module's realm half has a store route in reach and may not name it — the named action is its route, not the bridge.
- **`C-2` — one message per write turn per realm, AND IT CARRIES PER-LISTENER DATA — WHICH IS `D-92` READ AT ITS OWN BOUNDARY AND NOT A REPEAL OF IT** (`D-307`): *"all listeners fired by a storeroom write should be sent in one block in the channel, not piecemeal"* (D-304 (ii)). **AND THE WRITER IS THE CHANNEL — `D-311`'s CLARIFICATION, AND THE GROUND OF EVERY ARM BELOW** (`D-311`, verbatim: *"the channel object is the writer for e2e requests, meaning it will receive the listener data from the store"*): a client half's `store` act is an **e2e REQUEST THE CHANNEL EXECUTES** — client half → channel → store — so **the receipt is the CHANNEL'S own** and the batch below is composed from that receipt's `returnedValues`/`bodyFailures`, the settled values with rank-23 `bodyFailures` read as the DATUM, **and NO capture of the binding's own stands beside it**: the channel writes, so the channel reads the answer, and the binding's handler records only that it FIRED. **`threw` therefore STANDS** — a synchronous throw pre-empts the answer and crosses as itself, containment being the binding's — and **`refused` stays narrowed to genuinely non-transport-safe values**, never a `Promise` (research A6, D2).
