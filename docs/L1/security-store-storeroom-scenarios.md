## 4. REQUIRED, NOT YET AUTHORED

Each is stated goal → expected so a test writer can author it without this audit. All are rows of this unit's own batteries (`docs/L1/security-store-storeroom.md` §2, §8; D-10).

1. **`SC-E5-03` — a corrupt record at boot.** Goal: the operator's settings survive a damaged file without losing the defaults. Expected: seed `<userDataDir>/provident-operator-settings.json` with unparsable bytes, a torn prefix, a zero-length file and a wrongly-shaped object (`{token:42, enabled:'read'}`); each boot serves `token:null`, `enabled:['read','dispatch']`, no cap, the safe pair, and throws nothing. Cite `persistence.md` §2/§3, P-1's limit as the row's own stated bound.
2. **`SC-E5-08` — a commit that cannot land.** Goal: an operator's write that cannot be made durable is refused as a value, never half-landed. Expected: with `<userDataDir>` unwritable (a `0500` parent, and a directory standing at the file's own name where the store can be made to attempt), `write({token:'x'})` answers `status:'refused'` with **the store's own reason word** and its generated message; the previous bytes are byte-identical; the record is unmoved; the call returns (never throws). Phrase the reason as *the store's own status* — pinning `'FileCommitFailed'` may assert an arm the package does not mint, and an unsatisfiable row is a test finding (`examiner.md` §3).
3. **`SC-E5-09` — the closed write-outcome vocabulary.** Goal: one refusal has one spelling. Expected: over a commit, a value refusal, a construction refusal and a malformed patch, every `write()` answer's `status` is one of exactly `committed` / `refused`; a `committed` answer carries `cursor` and `opId` and no `reason`; a `refused` answer carries `reason` and `message`; and **no** write outcome is `'write-failed'` or `'tier4-closed'` (the latter is a read token only, `surface.test.ts:133`). D-16, ASM-3, `interface.md` §3.
4. **`SC-E5-12` — the returned receipt is not the instance's object.** Goal: a caller cannot rewrite the record's own answer. Expected: two `write()` calls on one instance answer two objects (`a !== b`), deep-equal when nothing was written between; mutating the first (deleting `reason`, setting `status`) leaves the next answer's `status`/`reason` intact; the same across `committed` and `refused` receipts. `interface.md` §2, `design.md` §3 (`receiptOf`).
5. **`SC-E5-15` — the operator clears the token.** Goal: a cleared credential stays cleared across a restart. Expected: `write({token:'t'})` then `write({token:null})` → the second commits, `read().token` is `null`, and the file's bytes carry **no** `token` member (a cleared member is stored as its absence, `interface.md` §2, `persistence.md` §4); a fresh construction over that directory still serves `null`; `write({})` leaves `token`, `enabled` and the cap as they stood. Include the landed `token:''`-clears arm if the implemented domain admits it, and say so if it does not.
6. **`SC-E5-17` — the late-read patch.** Goal: a caller's object cannot present one value to the admission and another to the write. Expected: a patch whose `token` is an accessor answering `'NEW'` on its first read and a `BigInt` on a later read, and one whose `maxJournalLength` answers `42` then `Infinity`, each answer either a `committed` receipt whose record the file also carries, or a `refused` receipt that moved nothing and touched no byte — never a `committed` receipt over a value the bytes do not hold; and the member is read exactly once. `design.md` §6, ADV-1's scenario.
7. **`SC-E5-18` — a read during a write.** Goal: no reader ever observes a half-applied record. Expected: with a subscription registered, a `read()` issued from inside the listener (the one delivery the design gives) returns the **committed** post-state and never the pre-write or the candidate; and a `read()` before the write's return returns the pre-write record. If the layer judges the window unobservable because the package owns it, the row's own message must say so rather than pass silently (`examiner.md` §2; `interface.md` §1).
